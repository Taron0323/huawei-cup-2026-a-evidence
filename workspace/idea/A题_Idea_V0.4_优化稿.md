# A 题 Idea V0.4：张量驻留域感知的多核划分与调度

题目：2026 年华为杯 A 题《通用神经网络处理器下的多核调度问题》  
日期：2026-09-23  
用途：后续算法实现、实验安排和论文建模的完整设计。

## 1. 这条思路怎样解决问题

多核调度的难点，是让并行计算节省的时间超过数据搬运、等待和片上空间不足带来的代价。我们围绕一份张量追踪三个问题：哪些任务或核心需要它，它在片上保留多久，下一次读取能否利用共享 Cache。

算法先沿合法拓扑序切块，用轻量计算分核，再对完整方案建立四条流水线的参考图。问题一同时考虑整图单块、接近核数的少量块和更细的块；问题二通过收拢消费者和提前末次消费，减少跨核搬运与片上占位；问题三根据真实查询和插入事件，调整能够影响读取先后的子图顺序。

代理是用于快速比较方案的估计分数，负责筛选候选；官方 Makespan 决定最终选解。有限的追加评估由全局机会队列分配，让少切分方案、容量调序和 Cache 调序都能在预算内参与竞争。

“张量驻留域”指一份数据可以直接保留、供后续计算复用的范围。问题一的域是一次独立下发的任务（Task），问题二、三的域是核心。三个问题共享图结构、方案表示、流水线模型和接受规则，分别改变跨域搬运与读取机制。Makespan 是全部操作的最晚结束时刻。

## 2. 题意、执行过程与瓶颈

### 2.1 输入和可提交决策

原图是操作和张量交替连接的有向无环图。操作给出计算周期和所属流水线，张量给出存储类别及字节数，依赖边本身不携带独立通信量。当前附件含 100 个用例。本轮只读检查确认，这些图没有直接操作到操作的边，每个计算结果张量至多有一个计算生产者，非 COPY 操作均属于 M 或 V 流水线。后文的计数式以这些条件为基础。

算法提交两个字段：

- node_to_subgraph：恰好覆盖全部非 COPY_IN/COPY_OUT 操作，指定其子图。
- core_schedules：外层恰有指定的 $K$ 个核心列表，列出各核的子图顺序，每个子图出现一次，允许空列表。

子图划分、分核和同核子图顺序是决策。操作发射时刻、换出对象、重新搬入（Reload）和 Cache 内容由官方程序生成。算法内部的拓扑序、参考时刻和驻留区间用于构造或评分；额外等待、预取及直接指定 COPY 发射时刻不在提交接口中。

### 2.2 三问的执行语义

| 机制 | 问题一 A | 问题二 B | 问题三 C |
|---|---|---|---|
| Task 组织 | 一个子图一个 Task | 同核全部子图合成一个 Task | 沿用 B |
| 同核跨子图数据 | 经 DDR 中转 | 可在 L1/UB 驻留 | 沿用 B |
| 同核 Task 切换 | 前 Task 完成后等待 100 cycles | 无逐子图等待项 | 沿用 B |
| 跨核就绪条件 | 前驱 Task 完成后等待 1000 cycles | 对应源 COPY_OUT 完成后等待 500 cycles | 命中 Cache 仍保留 500 cycles 条件 |
| 私有容量 | 每核 L1 为 524288 bytes，UB 为 131072 bytes | 相同，驻留跨越子图 | 相同 |
| 共享带宽 | DDR 读写共用 60 bytes/cycle | 相同 | DDR 与 Cache 两池独立；Cache 为 250 bytes/cycle |
| 共享 Cache | 无 | 无 | 1048576 bytes，按先进先出（FIFO）淘汰 |

配置来自官方 data/config.txt。时间单位为 cycles，数据单位为 bytes；宿主运行成本用秒或小时。KiB 和 MiB 分别表示 $2^{10}$ 和 $2^{20}$ bytes。

官方处理顺序为：校验方案 → 重建 Task 和边界 COPY → Step1 生成确定性顺序 → B/C 按子图列表稳定分桶并检查拓扑 → Step2 插入换出换入 → Step3 建立逐 Pipe 顺序和内存复用依赖 → 全局合法性检查 → 共享带宽事件模拟。四条 Pipe 分别是 M、V、MTE2 和 MTE3，后两条负责搬入和搬出。

B/C 的稳定分桶按核列表排列各子图，保留桶内原操作顺序。它改变各 Pipe 的操作先后，允许不同子图在不同 Pipe 上重叠执行。Step3 将容量复用转成执行依赖，多核模拟遵守这些依赖；标准结果中的片上峰值来自核内 Step3 参考执行。

### 2.3 为什么单看计算负载不够

把消费者分散到多个域会增加读取次数；把它们集中到同核又可能延长张量驻留，触发换出。M 与 V 可以重叠，真实依赖和 COPY 队首仍可能拖长尾部。Cache 的收益还取决于第二次查询是否发生在填充之后、淘汰之前。因此，计算负载适合快速试放，完整候选还需要通信、依赖和容量评分，最后由真实执行比较。

## 4. 主方法的组成

整个方法由一条流程贯穿：

**共享图结构 → 少量拓扑分块起点 → 轻量试放分核 → 完整参考图 → 容量保留筛选 → 选择性官方比较 → 冻结 B 后进行 C 对照与调序。**

其中，张量域计数决定搬运量；四流水线参考图描述依赖和队首等待；驻留扫描找出大张量占位区间；全局机会队列安排昂贵的真实比较。容量候选在生成时有保留位置，完整评分时有专用名额，具备实际 Spill 依据时还能挑战代理持平方案。初始竞争者和局部修改共享真实评估机会。

同一提交计划只保留一套参考状态和一份对应场景的真实结果。这样，所有改进都能落到两个提交字段上，已有计算也能按计划内容复用。

## 5. 共享数学模型

### 5.1 图、张量与方案

令 $V$ 为非 COPY 操作集合，$n=|V|$；$T$ 为与计算操作相连的逻辑张量集合。对 $t\in T$，$b_t$ 为大小，$m_t\in\{\mathrm{L1}, \mathrm{UB}\}$ 为片上类别，$C(t)$ 为去重后的计算消费者集合，$u(t)$ 为计算生产者。

没有计算生产者而有计算消费者的本地逻辑张量属于 $T_{\rm in}$；有计算生产者的张量属于 $T_{\rm prod}$。原始 DDR 端点保留作来源与搬运核对，不再作为另一份计算输入重复计入。若重建时遇到需进入片上的原 DDR 张量，按官方规则使用 UB。不同原片上张量标识即使来自同一 DDR 节点，也分别保留逻辑身份。

令 $o_t=1$ 表示 $t$ 有原始 COPY_OUT 消费者，或没有计算消费者，需要最终写出；否则 $o_t=0$。计算操作周期为 $c_v=\max(1, \mathrm{cycles}_v)$，计算 Pipe 为 $q_v\in\{M, V\}$。方案为

$$
X=(g, a, \sigma), \qquad
g:V\to\{0, \ldots, S-1\}, \qquad
a:\{0, \ldots, S-1\}\to\{0, \ldots, K-1\}.
\tag{1}
$$

$g$ 给出子图，$a$ 给出核心，$\sigma_k$ 给出核心 $k$ 的子图列表。驻留域为 $d_A(v)=g(v)$、$d_B(v)=d_C(v)=a(g(v))$。

同一逻辑张量在不同域中有不同物理副本。换出后再次读入形成新的物理版本，记为 $\tilde t$；官方 Reload 保留 logical_tid，新增物理 id 和 version。DDR backing 指已经存在、可供后续恢复的有效 DDR 副本。

### 5.2 目标、约束和接受规则

固定原图、配置和评估器，记场景 $r$ 的官方 Makespan 为 $F_r(X)$，新增搬运为 $Q_r^{\rm add}(X)$。真实目标是

$$
\min_{X\in\mathcal F_r(G, K)}F_r(X), \qquad r\in\{A, B, C\}.
\tag{2}
$$

$\mathcal F_r$ 包含覆盖、依赖、Task/Pipe 顺序和片上容量要求。候选成功完成官方评估后，按 $(F_r, Q_r^{\rm add})$ 字典序更新最好方案：Makespan 优先，周期相同才比较新增字节，两项相同保留原方案。始终保存成功评估中的最好计划及其匹配结果；C 的配对发布按第 7.3 节执行。

本方法沿一个操作拓扑序连续切块，再将合法全局块序投影到各核。若 $\eta(s)$ 为块位置，则所有跨块依赖满足

$$
u\to v, \quad g(u)\ne g(v)
\quad\Longrightarrow\quad
\eta(g(u))<\eta(g(v)).
\tag{3}
$$

把每个子图缩成一个点得到商图。连续分块使跨块依赖向后；同核列表也向后，因此商图与同核 Task 顺序边的并图无环。合并全局相邻块、拆开连续区间、保持块序的迁核保留这一性质；插入式调序重新检查式（3）。这是本方法采用的搜索范围。

原图无环由 validate_graph 检查，商图及基本核序由 derive_multicore_plan 检查，A 的任务并图由 validate_task_order 检查，B/C 的扩展操作图由 validate_execution 检查。扩展图包含实际数据、逐 Pipe FIFO、跨核 COPY 和内存复用依赖。核心间双向传输是否可行，取决于这些操作是否形成等待环。

每核每条 Pipe 同时最多运行一个操作。计算负载及计算下界为

$$
W_{k, q}=\sum_{v:a(g(v))=k, \ q_v=q}c_v, \qquad
F_r(X)\ge
\max\left\{L_G, \frac{\sum_{q_v=M}c_v}{K},
\frac{\sum_{q_v=V}c_v}{K}\right\},
\tag{4}
$$

其中 $L_G$ 是计算依赖图的最长加权路径。统一单核基准由官方启发式产生，可能高于这个下界，因此加速比大于核数仍需结合执行结构解释。

### 5.3 片上容量与搬运口径

物理副本在生产或搬入操作申请输出空间时分配，在全部读者完成后释放；无读者输出在生产者完成后释放。令分配、释放时刻为 $A_{\tilde t}, D_{\tilde t}$，容量要求为

$$
\sum_{\tilde t:A_{\tilde t}\le\tau<D_{\tilde t}}
b_{\tilde t}\,
\mathbf1\{\operatorname{core}(\tilde t)=k, \operatorname{mem}(\tilde t)=m\}
\le C_m.
\tag{5}
$$

Step2 沿固定序列恢复当前输入、申请输入输出，再处理超容，最后释放末次使用数据。换出对象须有未来使用，并排除当前操作的输入输出；选择下一次使用最远者。有有效 backing 时复用它，缺少 backing 时写回，后续使用通过 Reload 恢复。

Step3 按扩展序列申请输出容量，以可拆分的字节额度生成复用依赖：旧副本有读者时，等全部读取完成才允许新写入（WAR）；无读者时，等旧生产者写完再覆盖（WAW）。源 COPY_OUT 也属于读者。全局模拟沿导出的依赖执行，存储按字节额度分配和合并。

令 $Q^{\rm orig}$ 为原始 COPY 字节，$Q_r^0$ 为重建边界后的 COPY 字节，$\mathcal S_r$ 为容量不足时的实际换出换入（Spill）记录，$z_e$ 表示该次换出是否真的新写 DDR，则

$$
\begin{aligned}
Q_r^{\rm spill}&=\sum_{e\in\mathcal S_r}b_e(1+z_e), \\
Q_r^{\rm partition\_add}&=Q_r^0-Q^{\rm orig}, \\
Q_r^{\rm sched}&=Q_r^0+Q_r^{\rm spill}, \\
Q_r^{\rm add}&=Q_r^{\rm partition\_add}+Q_r^{\rm spill}.
\end{aligned}
\tag{6}
$$

一次无 backing 的换出加恢复对应一写一读；已有 backing 时只新增恢复读取。正式 Spill 总量读取 spill_added_copy_bytes。cross_task_traffic 是单向跨域负载，结果中的 scheduled_copy_bytes 是结构 COPY 总量，二者各有口径。

### 5.4 一个计划对应一个参考状态

所有候选先执行同一规范化规则：按每块最小原操作 ID 排序，将子图编号为 $0, \ldots, S-1$；节点映射按数值 ID 排列；保留核心编号和每核列表次序。后续评分、提交和结果索引均使用规范化后的计划。核心编号保留，因为同刻事件处理顺序会影响 Cache。

由规范化计划重建块依赖，加上每核相邻块顺序边，执行 Kahn 拓扑排序：每次从没有未排前驱的块中选最小成员 ID 最小者，得到唯一的 $\pi_X$。块内也由原计算依赖、按原 ID 破同分生成唯一拓扑序。最初使用的构造种子只影响最终分块和列表，不再进入参考评分。

两个提交字段完全相同即去重。参考状态索引包含图、场景、配置、核数、规范化计划内容及代理规则版本；真实结果索引将代理版本换为官方评估器版本。用普通字典及计划内容比较即可。计划重编号发生在首次评估前，旧编号结果不能直接作为新编号计划的成绩。

### 5.5 完整四流水线代理

对完整计划建立不含 Spill 的参考执行图。域内输入 COPY 位于首次消费者之前，源写出位于生产者之后；其余计算按 $\pi_X$ 和唯一块内顺序排列。COPY 采用以下共享键：

- A：源写出为（OUT，张量，生产 Task，DDR），接收读为（IN，张量，DDR，接收 Task）。最终输出与已有源写出合并。
- B/C：跨核读写按（类型，张量，源核，目标核）建立；最终输出使用独立 FINAL_DDR 键。同生产者的多个目标按核心编号排列。

同一插入位置出现多个 COPY 时，统一按张量 ID、类型、源域、目标域排序；类型顺序固定为 IN、OUT，目标域中整数编号在前，DDR 与 FINAL_DDR 标记依次在后。这一总顺序同时用于 Pipe 投影和驻留扫描。

保留全部真实计算依赖，跨域依赖通过对应 COPY 表达。各核域序列投影到四条 Pipe，相邻同 Pipe 操作相连。A 另建 Task 首尾和激活边，B 只加入源 COPY_OUT 到目标 COPY_IN 的 500 cycles 释放边。

每条 COPY 独占带宽的工作量为 $w_e=\max(1, \lceil b_e/60\rceil)$；计算工作量为 $c_v$。两类参考节点的工作量统一记为 $c_v^{\rm ref}$，在参考 DAG 上计算

$$
\widehat F_v=c_v^{\rm ref}+
\max_{u\in\operatorname{Pred}_0(v)}(\widehat F_u+\delta_{uv}),
\qquad \widehat H_r=\max_v\widehat F_v.
\tag{7}
$$

空前驱取 0。参考图的同步条件来自第 7 节。共享 COPY 只建一次，其全部真实消费者都等待对应读取完成。

对每个域的参考序列，先申请当前输出，再释放末次使用输入；跨域和最终写出计作读取事件。令本地域副本的首次分配、末次使用位置为 $\ell_{t, d}, u_{t, d}$，定义

$$
\widehat L_{d, m}(j)=\sum_t b_t\mathbf1\{m_t=m, \ell_{t, d}\le j\le u_{t, d}\},
\quad
P_r=\sum_{d, m}\left[\max_j\widehat L_{d, m}(j)-C_m\right]_+.
\tag{8}
$$

输入在参考 COPY_IN 处出现，计算结果在生产处出现，一份源副本保留至本地消费者和全部源 COPY_OUT 的末次使用。参考扫描描述无换出的理想占位。

令 $D_r^0=\sum_{\text{基础 DDR COPY }e}\max(1, \lceil b_e/60\rceil)$，完整代理为

$$
J_r(X)=\max\{\widehat H_r, D_r^0, \max_{k, q}W_{k, q}\}+P_r/60,
\qquad r\in\{A, B\}.
\tag{9}
$$

$J_r$ 的单位为 cycles；实现保存整数 $60J_r$，精确判断持平。$P_r/60$ 将理想峰值超额按一次读取带宽换算为评分，实际 Spill 另由式（6）计算；该评分不具有时间下界保证。跨度 $b_t(u_{t, d}-\ell_{t, d}+1)$ 用于容量候选内部排序，单位是 bytes×位置。

真实执行中，DDR 读写共同分享带宽。每次发射或完成先结算旧并发下的剩余独占工作量，再重算结束时刻；剩余工作量为正的搬运才占份额，最终时刻按代码向上取整。C 的命中读另用独立共享池。完整代理省略动态争用和实际换出，差异由选择性官方比较纠正。

若参考图无法排序，记录“代理不可评分”，保留通过构造检查的提交。它可按 $Q^0$、最大 M/V 负载、计划键顺序进入备用初始竞争，官方检查决定可执行性。

## 6. 从候选构造到真实选择

### 6.1 共享结构与两种构造序

每个图只建立一次只读视图：原操作和张量属性、生产者、去重消费者、输入输出邻接表、计算依赖、原始搬运量及最终输出标记。逆拓扑计算

$$
h(v)=c_v+\max_{w\in\operatorname{succ}(v)}h(w).
\tag{10}
$$

关键路径序 H 每次从就绪节点选 $h(v)$ 最大者，同分选原 ID 较小者。驻留序 R 从这个就绪堆取前 8 个，按 $h(v)+(R_v-O_v)/60$ 降序选择，同分比较 $h(v)$ 和 ID。$R_v$ 是执行后完成末次计算消费的活跃字节，$O_v$ 是本次新开启、执行后仍有后续消费者的字节。只有选中节点更新剩余消费者与活跃集合。

分块沿构造序连续进行。以累计计算周期的等分点为中心，取满足非空和剩余块数要求、距目标最近的至多 8 个切点，再按跨点活跃张量字节、目标距离、位置升序选择。首次和末次位置通过差分扫描获得，同一张量在同一切点计一次。累计周期是切点坐标，块内 M/V 工作分别保留。

### 6.2 A/B 各自的四个起点

### 6.3 轻量试放如何更新状态

分区确定后，按全局合法块序逐块试放。复用的静态量包括原图邻接、$h$、张量大小、最终输出标记和每块 M/V 总周期。可变量包括 $W_{k, q}$、消费域计数 $N_{t, d}$、生产域、已确定边界 COPY 键、各核 M/V 参考可用时刻、已排操作的轻量完成时刻，以及核列表。

试放评分采用

$$
L_r(s, k)=\max\left\{
\max_{l, q}W'_{l, q}, \ D_{\rm partial}', \
H_{\rm partial}'
\right\}.
\tag{11}
$$

$D_{\rm partial}'$ 是当前已确定语义 COPY 的独占工作量总和。$H_{\rm partial}'$ 在 A 中取已排 Task 的估计完成最大值，包含输入输出 COPY；在 B 中取已排及当前块计算操作 $f'_v$ 的最大值。三个量都为 cycles，同分依次选较小的 $D_{\rm partial}'$、较小的最大计算负载、较小核编号。

A 的分区已经确定全部边界读写，因此每个 Task 的输入、输出独占 COPY 工作可预先取得。前缀按已放 Task 累加该工作量，源写出包含未来接收 Task 的需求。试放时按式（14）的轻量前驱完成与同核前 Task 完成确定启动，再以“输入 COPY 工作 + 两条计算 Pipe 的块内依赖排布 + 输出 COPY 工作”估计 Task 完成。这个顺序近似忽略搬运与计算重叠，用于选核；四 Pipe 完整复评恢复重叠关系。

B 按块内唯一计算拓扑序，维护 M/V 可用时刻 $A_{k, q}$。操作 $v$ 的轻量完成为
$f_v=c_v+\max\{A_{k, q_v}, \max_{t\in\operatorname{inputs}(v)}r_{t, k}\}$。
本地中间张量的就绪取生产者 $f_{u(t)}$；图输入首次读取取独占搬入周期；跨核首次读取取 $f_{u(t)}+2\max(1, \lceil b_t/60\rceil)+500$。同一 $(t, k)$ 的已有读入就绪值复用。未分配消费者不预设核心，未来接收域在确定时加入，最终输出标记始终来自整图。

消费域用整数计数维护。对受影响张量，先扣除旧域贡献，再修改计数和生产域，再按式（13）或（15）加回新贡献：

1. $0\to1$ 新增接收域，$1\to0$ 删除接收域，其他计数变化保留已有 COPY。
2. A 的源写出由“存在外域消费者或最终输出”决定；合并、拆分后重新判断该布尔条件。
3. B 的生产核迁移后，重新检查该张量全部非空消费核，原本本地的核可能变远端，原远端可能变本地；最终输出项始终保留。
4. 组迁移一次处理全部受影响关联，避免逐操作迁移中间状态造成重复收费。

试放采用局部差量覆盖表，只复制受影响计数、负载、就绪值和新 COPY 键；未选中的覆盖表直接丢弃，选中者提交。一次完整方案形成后再重建全部计数作一致性检查。

新增远端消费者会增加此前源核的 COPY_OUT，并可能改变后续 MTE3 和关键路径。轻量阶段更新 COPY 键、域计数和总工作量，暂保留此前的完成时刻；完整计划形成后，统一重建源写出、四 Pipe 顺序和依赖路径。

### 6.4 先找到可解释的修改位置

当前成功结果提供三个入口：达到全局 Makespan 的实际操作、边界字节贡献最大的张量、具有正理想容量压力或实际 Spill 的域。尾部操作包含计算、最终 COPY_OUT 和其他搬运，同分按核心、操作 ID。

尾部回溯考虑真实数据前驱、同 Pipe 前项、A 的 Task 激活以及 B/C 的源写出加 500 条件。有完整诊断时再加入内存复用边。按这些依赖确定等待来源及其涉及的块，将重叠等待区间合并后累计，总长度不超过 $F_r$；仅见空闲而缺少依赖信息的区间记为原因未定位。

标准结果提供 Spill 总量，完整记录需额外诊断。对选中的压力计划，复用官方 Task 构图和 Step1 至 Step3，取得物理图、Spill/Reload 关联及复用边；标准构图返回不足时，从重建的原 Task 图调用原 Step2 取得 spill_records。展开结果按计划复用，耗时单列。主方法最多 8 个不同计划做此类诊断，按实际 Spill 字节除以已测评估成本降序选取，同分按用例、场景、核数。C 内存路径也使用这 8 个共享诊断名额。控制方法每个设置、每个方法最多一次对应诊断，计入控制成本。

### 6.5 容量候选怎样经过 24 个到 4 个

本节规定 A/B 的局部精修。C 按第 7.3 节先筛选能够改变读取约束的调序，再在该候选池内使用容量一个加常规三个的完整评分名额。

一批最多保留 24 个不同提交计划，先给容量通道 4 个生成位置，常规通道补足剩余位置，通常最多 20 个；容量不足时余额回流常规。规范化去重发生在计入名额之前；同一候选兼具两种来源时保留容量标签，常规通道继续向后补。

容量通道按“已定位 Spill 优先、超容字节降序、张量跨度降序、原 ID 升序”选择至多 4 个不同锚点。B 对末次消费者锚点前移，对重叠大输出的生产者锚点后移；检查位移 1 至 8 的全部合法位置，先按下述容量准入条件过滤，再按容量字典序选最好的一个，没有合格位置时跳过该锚点。A 则在压力 Task 的末次消费附近按第 6.1 节选一个切点，两个新块先留原核。每个锚点最多输出一个候选，合计至多 4 个；最多 32 次位置探测及容量重扫另计成本。

对合法位置重扫受影响域的规范参考序列和张量区间，不计算最长路径。令 $\Delta f=f(X)-f(Y)$。容量候选先按受影响域峰值下降 $\Delta M$、超容面积下降 $\Delta A_{\rm over}$、目标张量跨度下降 $\Delta A_{\rm span}$ 的字典序降序排列；三项相同时，先选绝对位移较小者，再按编辑键升序。拆分候选的位移记为 0。这里 $M$ 为受影响域峰值之和，单位是 bytes，
$A_{\rm over}=\sum_{d, m, j}[\widehat L_{d, m}(j)-C_m]_+$ 和 $A_{\rm span}=\sum b_t(u-\ell+1)$ 的单位为 bytes×位置。B 要求峰值不增且至少一个后续量下降；A 的拆分以总压力 $P$ 下降作为准入。重扫使用实际规范序列长度，不把跨度直接换算成周期。

常规通道轮询尾部、通信、压力三个区域，依次产生合法的相邻合并、连续拆分与分核、单块迁核、至多 4 个消费块同迁、窗口内插入。A/B 块数上限均为 $\min(n, 16K)$。编辑键为类型、块成员最小 ID、切点、目标核、目标位置。每个区域和编辑类型轮流取候选，排序分数为

$$
C_{\rm cheap}(Y)=\Delta\max_{k, q}W_{k, q}+\Delta Q_r^0/60.
\tag{12}
$$

分数相同，先取涉及已证实尾部依赖者，再按编辑键。常规分数不要求为正。

完整代理名额固定为：先选容量排名第一的一个，再选常规排名前三个不同计划。容量首选若也在常规前三，计一次并向下补常规候选；其余容量候选可参加常规排序。没有容量候选时选四个常规候选；常规不足时用剩余容量候选补齐。每批最多四次新完整评分，已有分数直接复用。

纯调序即使 $\Delta W=\Delta Q_B^0=0$，仍可通过容量保留位置生成，并取得专用完整评分名额。

### 6.6 真实竞争与容量挑战

每个组合维护未测初始方案、入围局部方案和当前成功最好方案。真实竞争的准入规则为：

- 结构不同的初始方案正常进入，包括单块和少切分方案，允许代理更差。
- 局部方案在 $J(Y)<J(X)$ 时进入。
- 容量挑战要求 $J(Y)=J(X)$，当前官方 Spill 为正，且已有记录把编辑张量与实际 Spill/Reload 对应到同一逻辑 ID 和域；编辑使该张量末次消费跨度缩短、受影响峰值不增。每批保留容量排序最高的一个持平挑战。
- $J(Y)>J(X)$ 的容量局部方案不使用真实追加额度；结构不同初始方案的资格仍按第一条判断。

只有 Spill 总量而没有对应记录时，容量候选仍参加生成和完整评分，持平挑战等待具体诊断。参考图失败的结构不同初始方案可进入竞争；局部方案缺少比较分数时留作未评分记录。

对入队候选 $Y$，定义以下无量纲信号：

$$
\begin{aligned}
g_Y&=[J(X)-J(Y)]_+/\max(1, J(X)), \\
p_Y&=[J(Y)-J(X)]_+/\max(1, J(X)), \\
e_X&=|F_r(X)-J(X)|/\max(1, F_r(X), J(X)), \\
U(Y)&=\frac{g_Y+(1+e_X)d_Y+z_Y}{1+p_Y}.
\end{aligned}
\tag{12a}
$$

$d_Y$ 取三种结构变化比例的最大值：所属块成员集合改变的操作比例、迁核操作比例、共同块的同核前项改变比例，分母为相应对象总数，空集合取 0。$z_Y$ 为“编辑涉及的已定位 Spill 字节占总 Spill 的比例”加“涉及实际尾部回溯链的已定位等待周期占 $F_r$ 的比例”；同一事件只计一次，缺少定位证据的项取 0。$J$ 缺失时令 $g_Y=p_Y=0$，当前 $J(X)$ 缺失时令 $e_X=0$。

评估成本 $\widehat c_Y$ 取当前组合已有完整评估秒数的最大值，再乘 $\max(1, S_Y/S_X, N_{0, Y}/N_{0, X})$；$N_0$ 为参考操作数，缺少该规模时省略其比值，时间分母至少取计时器分辨率。按“本组合已用追加次数升序、$U/\widehat c$ 降序、$U$ 降序、$J(Y)$ 升序、用例/场景/核数/计划键升序”出队，缺失 $J$ 排末。$U$ 是分配机会的规则，其分量表达代理改善、结构差异、代理分歧和已有诊断。

初始竞争者已具有完整代理，可直接入队。局部候选按需生成：每个组合放一个展开记录，按追加次数升序、下式降序排列，同分按组合键：

$$
V_{\rm expand}(X)=
\frac{e_X+
Q^{\rm spill}/(60\max(1, F_r))+
[Q^0-Q^{\rm orig}]_+/(60\max(1, F_r))}
{\widehat c_X}.
\tag{12b}
$$

每次分配追加调用前，先展开排名第一的一个可用记录，将合格局部候选加入实际候选队列，再与所有未测初始方案共同按式（12a）排序。没有产生合格候选也计一次生成批次，随后评估已有队列或继续下一个展开记录。

主方法全包最多 64 批局部生成，含核心对照中主方法先使用的最多 4 批；常规 A/B 机会池另有 64 次实际追加调用。每组合最多两批、两次追加，核心对照的主追加也计入组合上限。接受后旧局部候选失效，未测初始方案保留并更新机会分数；最多再产生一批。拒绝后不围绕被拒计划生成，已有同一最好计划的其他候选可竞争第二次。连续两次拒绝、达到组合上限、无候选、额度或墙钟不足时停止。没有追加额度，返回基础及已完成追加中的最好结果。

## 7. 三个问题分别怎样求解

### 7.1 问题一：以 Task 为驻留域

问题一优化 $F_A(X)$，变量为式（1）的划分、分核和核序，满足第 5 节的覆盖、Task 依赖、Pipe 与容量约束。切分改变独立 Task 数量，也改变边界搬运和激活次数。

对输入定义 $I_A(t)=\{g(v):v\in C(t)\}$；对计算结果定义
$R_A(t)=\{g(v):v\in C(t), g(v)\ne g(u(t))\}$，令 $r_A(t)=|R_A(t)|$。官方为每个生产 Task 的边界张量写出一次，再为每个接收 Task 读入一次，最终输出与已有写出合并，因此

$$
Q_A^0(X)=
\sum_{t\in T_{\rm in}}b_t|I_A(t)|
+\sum_{t\in T_{\rm prod}}b_t
\left[r_A(t)+\mathbf1\{r_A(t)>0\lor o_t=1\}\right].
\tag{13}
$$

一个内部张量被两个外部 Task 消费，对应一写两读。同核迁移不改变接收 Task 数；合并 Task 才可能减少这部分搬运。Spill 另按式（6）计入。

令 $B_s, E_s$ 为 Task 激活和完成时刻，$\operatorname{Pred}_S(s)$ 为数据前驱 Task，$p_k(s)$ 为同核前一 Task，则

$$
B_s\ge\max\left\{
0, \max_{p\in\operatorname{Pred}_S(s)}E_p, \,
\max_{\substack{p\in\operatorname{Pred}_S(s)\\a(p)\ne a(s)}}(E_p+1000), \,
E_{p_k(s)}+100
\right\}.
\tag{14}
$$

不存在的项省略。$E_s$ 包括 Task 的全部 COPY 完成，根 Task 没有初始 100 cycles，末尾没有额外切换费，多个释放条件取最大值。

求解从 A1 至 A4 起步，先轻量选核，再按式（13）、（14）完整评分。初始真实结果建立当前最好方案；其余起点和有限合并、拆分、迁核、容量修改进入共同机会队列。正式证据为全部 100 例、2 至 5 核的 Makespan、新增搬运和统一单核加速比；代表例补充 Task 数、COPY 数及实际激活等待。

### 7.2 问题二：以核心为驻留域

问题二优化 $F_B(X)$，仍联合决定 $g, a, \sigma$。同核子图合成 Task 后，核序影响稳定分桶、Pipe 投影和片上占位。容量跨子图持续约束，合法性由扩展执行图检查。

对输入定义 $I_B(t)=\{a(g(v)):v\in C(t)\}$；对计算结果定义
$R_B(t)=\{a(g(v)):v\in C(t), a(g(v))\ne a(g(u(t)))\}$，令 $r_B(t)=|R_B(t)|$。每个远端接收核有独立的源写出和目标读入，最终输出另计：

$$
Q_B^0(X)=
\sum_{t\in T_{\rm in}}b_t|I_B(t)|
+\sum_{t\in T_{\rm prod}}b_t[2r_B(t)+o_t].
\tag{15}
$$

同一远端核的多个消费者共享一次接收；两个远端核加最终输出对应 $5b_t$。A 的源端共享写出与 B 的逐接收核写出由不同构图规则产生。

对应跨核读写满足

$$
\operatorname{start}(e^{\rm in}_{t, k, l})
\ge \operatorname{end}(e^{\rm out}_{t, k, l})+500.
\tag{16}
$$

目标读还要等待本地数据、同 Pipe 前项及内存复用依赖。500 cycles 的起点是源 COPY_OUT 完成。

B1 至 B4 提供同核驻留和调序载体。优先通过消费域计数识别可减少接收核的迁移，再结合 M/V 尾部和容量通道筛选。已有实际 Spill 时，提前末次消费者可通过式（9）的改善或第 6.6 节的持平挑战进入真实比较。结果保留 100 例、1 至 5 核的专用 B 计划与成绩，供问题二分析和问题三逐计划配对。

### 7.3 问题三：读取时序与 FIFO 机会队列

问题三先对所有冻结 $X_B$ 计算 $F_C(X_B)$，得到同计划硬件效果；再固定其 $g, a$，通过合法块插入调整 $\sigma$，目标为降低 $F_C(X_C)$。私有容量、Step2 换出、四 Pipe 和式（16）保持 B 的执行语义。Cache 状态由模拟产生。

#### 查询与驻留

COPY_IN 发射时按片上张量 logical_tid 查询，缺省使用物理 id。有效键、正字节的输入搬入、跨核搬入和 Reload 都参与查询；过大张量仍计 miss，但无法插入。读取路径一经发射即确定，同时在途的同键 miss 分别读取 DDR。COPY_OUT 走 DDR。

每条 COPY_IN 完成后都尝试插入。键仍在 Cache 中时不改变 FIFO 位置；键已在读取期间被淘汰时，完成后可重新插入。真正追加时，从队首逐项淘汰直至空间足够，再加入队尾。尺寸等于容量可以缓存，大于容量跳过。

同刻事件先退休及插入，再处理到期的跨核释放，最后发射。当前代码按核心升序及 MTE2、MTE3、M、V 的顺序退休。因此分析按 cache_events 的原列表顺序进行；一次 insert 中的 evicted_tensor_ids 给出淘汰对象。

设 $t$ 在成功追加事件 $e_i$ 开始一段驻留，$A(e_i, e)$ 为此后、查询 $e$ 之前所有成功追加的字节和。排除同键无动作和过大张量的失败插入，则本次驻留段保持的条件为

$$
b_t+A(e_i, e)\le C_{\rm Cache}.
\tag{17}
$$

较老条目先淘汰，追加在 $t$ 后面的条目在 $t$ 被淘汰前都位于它后方，因此严格超过容量时该段结束。重插开始新的驻留段。

#### 先确认移动能改变读取约束

事件按同键关联为两类机会：前次读取尚未完成就再次发射的重叠 miss，以及曾插入、后被淘汰的重复 miss。前者尝试将目标读相关块后移，后者尝试前移。可缓存条件为 $0<b_t\le C_{\rm Cache}$。

首先用消费者表重算目标核最早消费 $t$ 的子图。官方把基础 COPY_IN 归到这个块，再按核列表稳定分桶。候选移动若使目标读与被跨越同核块的基础 COPY_IN 交换先后，就改变了基础 MTE2 序列：后移须新增位于目标读之前的读，前移须减少这些前项。若另一个消费者仍更早，目标读的归属可能保持，此时不能把它计入移动机会。

对没有改变基础 MTE2 顺序的编辑，仅在已有官方诊断时检查内存路径：目标读或其 MTE2 前项存在复用依赖，被移动块包含释放来源读者，并且编辑改变了该读者的同 Pipe 位置或相关输出申请顺序。Reload 通过 spill_records 的 next_use_op 定位消费块。记录对应依赖后，才能将这些事件作为机会。普通独立计算的前移本身不足以推迟读取。

上述筛选使用张量关联、块序和已有依赖，不逐候选运行官方 Step1 至 Step3。改变基础读取约束表示存在调整空间，实际发射仍由完整官方评估确定。

#### 候选、排序与追加额度

对 500 个基础 C 结果分别遍历事件，建立上述可移动机会。窗口为 8 个块，先检查合法位置是否改变基础 COPY 相对顺序，或影响已有诊断中的内存释放路径；满足其一才进入机会集合。相同目标读和方向合并，再按可缓存字节降序、事件列表位置升序保留至多 4 个可移动锚点，形成组合摘要。没有合法移动的组合自然退出。

按潜在服务量除以成本选择下一批：

$$
V_C=
\frac{B_{\rm movable}(1/60-1/250)}
{\widehat t_C+\widehat t_B}.
\tag{18}
$$

$B_{\rm movable}$ 是已找到方向匹配、可提交移动的不同 miss 字节和；$\widehat t_C, \widehat t_B$ 分别取当前组合对应场景已测调用秒数的最大值。组合预排序统一预估一次 C 加一次 B；具体计划形成后，按结果索引扣除可复用的 B 成本。先按该组合已尝试次数升序，再按 $V_C$ 降序、用例/核数升序选择。

选中组合后，四个锚点轮询，方向内按位移 1 至 8、编辑键枚举，去重后最多生成 24 个不同调序计划。常规便宜排序使用 $B_{\rm opp}(1/60-1/250)$；$B_{\rm opp}$ 是该候选涉及的不同旧 miss 字节和，每个（核心，操作 ID）计一次。若这些合法 Cache 候选中有容量导向者，沿用容量 1 个加常规 3 个完整名额；否则用四个常规名额。完整候选用 B 结构代理计算

$$
U_C(Y)=B_{\rm opp}(Y)(1/60-1/250)
-[\widehat H_B(Y)-\widehat H_B(X)]_+
-[P_B(Y)-P_B(X)]_+/60.
\tag{19}
$$

$X$ 是该组合当前已经配对的 C 最好计划，初始为 $X_B$。保留 $U_C>0$ 者，按 $U_C/(\widehat t_C+\widehat t_{B, \rm needed})$ 降序、$U_C$ 降序、计划键升序进入全局 C 队列。服务量项用于排序，Makespan 的接受仍用式（2）。

C 阶段开放时记录可用调用数 $R_C^{\rm open}$，整个阶段最多生成 $G_C\le R_C^{\rm open}$ 批，每组合最多两批、两次 C 尝试。一次生成无合格候选仍占批次。每次正式 C 尝试前，同时锁定该次 C 以及缺少的 B 配对额度；通常需要 2 次，已有完全匹配的 B 结果则只需 1 次。墙钟预留也覆盖两次成本。

C 拒绝后归还未使用的 B 配对额度，其他已评分候选可竞争第二次。C 接受后取得同一新计划的 B 结果，再发布新的 $X_C$；旧局部候选失效，满足次数条件时才能从新事件产生第二批。B 配对失败时保存 C 最好观测和待配对标记，每个新计划最多在剩余额度和墙钟内重试 B 一次；仍失败或无额度时关闭该机会，发布方案保留旧已配对结果。每次配对或重试均计实际调用，冻结的 $X_B$ 及其硬件对照不回写。

每次分配 C 调用前，如批次额度允许，先按 $V_C$ 展开一个待生成组合。随后从有效、已评分且剩余额度和墙钟能够覆盖 C 及必要 B 配对的候选中，按上述机会与成本规则出队。没有新合格候选时使用已有队列；没有可评估候选且仍有生成额度时继续展开，直至找到候选或批次用尽。展开记录仅在初始状态及接受新配对计划后加入，用后删除，拒绝不重复生成同一批。

#### 指标与归因

若 COPY_IN 的命中和未命中字节分别为 $H, M$，字节命中率为

$$
h_{\rm byte}=
\begin{cases}H/(H+M), &H+M>0, \\0, &H+M=0.\end{cases}
\tag{20}
$$

固定同一计划时，B/C 的边界重建和 Step1 至 Step3 相同，因此

$$
Q_C^{\rm sched}(X)=Q_B^{\rm sched}(X), \qquad
Q_C^{\rm add}(X)=Q_B^{\rm add}(X).
\tag{21}
$$

在当前重建 COPY 都有 DDR 端点的条件下，派生 DDR 服务字节为
$Q_{C, \rm DDR}^{\rm derived}=Q_C^{\rm sched}-H$，并用 memory_path 核对。它与官方结构新增搬运分别列出。contest_io 的日志在缺少 physical_ddr_bytes 时回退为全部 COPY 字节，不能据该日志列直接计算 Cache 的实际服务流量。

对每个用例、核数分别报告

$$
S_{\rm hardware}=\frac{F_B(X_B)}{F_C(X_B)}, \qquad
S_{\rm order}=\frac{F_C(X_B)}{F_C(X_C)}, \qquad
S_{\rm joint}=\frac{F_B(X_B)}{F_C(X_C)}.
\tag{22}
$$

另用 $F_B(X_C)$ 判断新顺序在无 Cache 时的效果。单例有 $S_{\rm joint}=S_{\rm hardware}S_{\rm order}$，跨例均值分别计算。

## 8. 说明性手算

本节使用人为小图检查计数和决策路径。时间片段只含明确列出的操作与搬运。

### 8.1 同一个张量怎样按域收费

输入 $x=60000$ bytes 供 $A, E$ 使用；$A$ 用 M Pipe 计算 4000 cycles，产生 $z=30000$ bytes，供 $B, C, D$ 使用；$B, C, D$ 各用 V Pipe 计算 1000 cycles，$E$ 用 V Pipe 计算 4000 cycles。四个最终输出各为 6000 bytes。

取 $s_0=\{A, E\}$ 在核 0，$s_1=\{B, C\}$ 在核 1，$s_2=\{D\}$ 在核 2，无 Spill。原始搬运为 $60000+4\times6000=84000$ bytes。

| 项目 | A | B |
|---|---:|---:|
| 输入 $x$ | 60000 | 60000 |
| $z$ 的边界 COPY | 一写两读，90000 | 两对读写，120000 |
| 最终输出 | 24000 | 24000 |
| $Q^0$ | 174000 | 204000 |
| $Q^{\rm add}$ | 90000 | 120000 |

把 $s_2$ 迁到核 1，B 的 $z$ 变成一对读写，减少 60000 bytes；核 1 的 V 负载从 2000 增至 3000 cycles。A 仍有两个接收 Task，直到合并 $s_1, s_2$ 才减少一次读入。$s_0$ 内 M/V 计算工作可以重叠，计算负载尺度为 $\max(4000, 4000)=4000$ cycles。

### 8.2 少切分起点与并行机会

对同 Pipe 依赖链 $a\to t\to b$，令 $a, b$ 分别计算 1000、800 cycles，$t=12000$ bytes，一次独占 DDR 搬运为 200 cycles，无其他搬运和 Spill：

| 安排 | 手算完成周期 |
|---|---:|
| 同一 Task | $1000+800=1800$ |
| A，同核两个 Task | $1000+200+100+200+800=2300$ |
| A，跨核两个 Task | $1000+200+1000+200+800=3200$ |
| B，同核两个子图 | $1000+800=1800$ |
| B，跨核两个子图 | $1000+200+500+200+800=2700$ |

A1 直接给出第一行的单块结构，其余核心为空；A2 给出两块结构。两者都完整评分，未首选的方案通过结构差异 $d_Y>0$ 进入追加队列，获配额后用官方结果决定是否替换。这个竞争不需要先从细分方案反复合并。

再取两条互不依赖的同 Pipe 分支 $a_1\to b_1$、$a_2\to b_2$，各计算 $1000+800$ cycles，中间张量各为 36000 bytes，其余前沿占位忽略。R 序先按 ID 选 $a_1$；随后 $b_1$ 的分数为 $800+36000/60=1400$，$a_2$ 为 $1800-36000/60=1200$，因此形成 $a_1, b_1, a_2, b_2$。A2 可在零前沿的分支间切成两个块，在两核接口下并行执行；计算部分由串行 3600 变为并行 1800 cycles。实际还需计入各分支输入输出。候选集同时包含低边界和多核并行结构。

### 8.3 容量候选从生成到官方比较

UB 容量为 131072 bytes。$a$ 产生 $x$，$b_1, b_2$ 消费 $x$；独立支路 $d$ 产生 $y$，$e$ 消费 $y$；$x, y$ 各为 81920 bytes，其余占位忽略。五个操作分别属于五个单操作子图，全部放同一核，按标签书写的提交列表从

$$
[a, b_1, d, e, b_2]\quad\longrightarrow\quad[a, b_1, b_2, d, e].
\tag{23}
$$

其他核心列表为空，实际 ID 在提交前按第 5.4 节规范化。这是 B 的合法子图前移，划分和分核保持，$W$ 与 $Q_B^0$ 都不变。

旧序中 $d$ 申请 $y$ 时 $x$ 仍存活，峰值为 163840 bytes，超容 32768 bytes；新序先结束 $x$ 的末次消费，峰值为 81920 bytes，超容为 0。按五个计算位置计，$x$ 的跨度从 5 缩至 3，跨度面积减少 $81920\times2=163840$ bytes×位置。

这条候选占一个容量生成位置，按正峰值下降排在容量通道前列，再取得一个完整代理名额。若完整 $\widehat H, D^0, W$ 不变，则 $J$ 降低 $32768/60$ cycles，进入普通实际候选队列。若另一处峰值仍决定全域 $P$，使 $J$ 持平，则需要旧官方结果中与 $x$ 对应的 Spill/Reload 诊断，满足跨度缩短后进入容量挑战。两条路径都与初始竞争者共享追加额度，最终按真实 $(F, Q^{\rm add})$ 接受；无额度或真实结果不改善时保留旧方案。

当实际 Step2 的 $x$ 需要换出且无 backing，一写一读为 163840 bytes；已有 backing 时 Reload 为 81920 bytes。32768 bytes 的理想超额、81920 bytes 的张量大小和实际换出换入量分别记录。

### 8.4 FIFO 查询为什么依赖可提交的顺序

两个核心读取同一个 60000 bytes 输入，Cache 初始为空，无其他搬运。若同时在 0 发射，两次都 miss，共享 DDR 后约在 2000 cycles 完成。若合法块序使第二次读在 1000 发射，第一读恰在 1000 完成插入，第二读可命中，240 cycles 后完成，即 1240。这种变化须由 MTE2 前项或真实内存复用依赖产生，第 7.3 节先检查这些结构。

对 1 MiB FIFO，依次插入 512 KiB 的 $p$、384 KiB 的 $q$，使用量为 896 KiB；命中 $p$ 不刷新位置。再插入 256 KiB 的 $r$ 时，$512+384+256>1024$，淘汰 $p$，剩 $q, r$ 共 640 KiB。若此前对 $p$ 的命中读取尚未完成，它以后完成时可重新插入。事件分析因此同时保留查询、完成和实际追加次序。

## 9. 实验、调用预算与总计算量

### 9.1 唯一调用预算

一次调用指一次原官方完整评估入口尝试，失败也计入。规划总额为 1700 次，基础矩阵固定为 $100+400+500+500=1500$ 项。

| 归属 | 计算与用途 | 调用上限 | 保留与流转规则 |
|---|---|---:|---|
| 统一单核 | 100 例各一次 | 100 | 固定基础 |
| A 多核 | 100 例 × 2 至 5 核 | 400 | 固定基础 |
| B | 100 例 × 1 至 5 核 | 500 | 固定基础 |
| C 同计划对照 | 100 例 × 1 至 5 核，使用冻结 $X_B$ | 500 | 固定基础 |
| 微图与宿主校准 | 6 次机制微图 + 6 次相同任务的重复计时 | 12 | 必要验证预留；未用部分待阶段结束清算 |
| 基础失败修复 | 基础项的替代尝试、必要重复核对 | 24 | 保留至基础 C 覆盖结清 |
| 核心公平对照 | 4 个设置 ×（6 个控制各至多 2 次 + 主方法追加至多 1 次） | 52 | 同设置整组开展；主初始复用基础 |
| A/B 机会队列 | 初始竞争者与局部修改共同竞争 | 64 | B 冻结前使用，余额流入 C |
| C 调序及 B 配对 | C 尝试和必要新 B 配对共同扣除 | 48 | 阶段保护额度，普通 A/B 搜索不可借用 |
| **合计** | **1500 + 12 + 24 + 52 + 64 + 48** | **1700** | **一个账本，每次调用只归属一行** |

基础项的第一次尝试即占用该项；若失败，修复调用另扣。一个成功结果可以服务基准、图表、诊断和对照等多个分析，复用结果不重复扣款。重复计时、微图、失败和变化计划配对分别有真实归属。

A/B 基础、必要修复、核心对照及获配额追加完成后冻结 $X_B$。此时 A/B 与控制余额锁定给 C，暂不转账，修复池仍保留。500 项基础 C 全部结清后，一次性清算：$R_C^{\rm open}=48+u_{\rm AB}+u_{\rm control}+u_{\rm calibration}+u_{\rm repair}$，其中各 $u$ 都是已扣除支出及转作基础修复后的余额；若 48 次保护额度也曾转作基础修复，式中以其实际余额替代 48。每笔余额只合并一次。于是

$$
R_C+B_C+R_{\rm pair\_retry}\le R_C^{\rm open},
\tag{24}
$$

其中 $R_C$ 为 C 实际尝试数，$B_C$ 为新 B 配对实际尝试数，$R_{\rm pair\_retry}$ 为另列的配对重试，三者互斥记账。失败配对已经包含在 $B_C$ 中，后续重试才进入第三项。拒绝 C 归还尚未用的配对锁定额度。

若基础修复用尽 24 次，先收回未开始的 A/B 搜索，再取消未开始的完整控制组，最后缩减 C 可选搜索预留，仍保持总上限 1700。基础覆盖优先于可选分析。总额度或时间仍不足时列出真实未完成组合，不用缺失值、填零或未核对旧成绩补齐。

### 9.2 代表预跑与机制核对

代表用例沿用结构选择：case_093 小图、case_095 接近中位且无共享输入、case_014 最大图、case_025 高输入扇出、case_062 大输入字节、case_016 仅 V 计算。具体属性在实现时从原图重新统计；选取不依赖新方法收益。

先执行 36 个基础预跑：6 个统一单核，A 的 $K=2, 5$ 共 12 个，B 的 $K=1, 2, 5$ 共 18 个。后续 C 阶段再执行这六例的 $K=1, 2, 5$ 共 18 个，均占原基础项。B 冻结前不运行用于最终硬件对照的 C。

### 9.3 核心对照覆盖整个机制

选择 case_093、case_014，$K=5$，A/B 共四个设置。每个设置比较主方法和下表六个控制，均最多四个起点、两个候选比较槽，第二槽使用同样的 24 个候选、最多四个完整候选分数。失败与复用已有结果都占比较槽；只有真正调用官方入口才扣全局调用额度。生成和评估耗时分别报告。

| 控制 | 作用位置和具体规则 | 回答的问题 |
|---|---|---|
| 双 Pipe 负载优先 | 使用同一场景起点表，试放和完整候选选择均按最大 M/V 负载；常规编辑及容量候选池规模相同，第二次取未测最优候选 | 只看计算均衡与完整方法的差别 |
| 关键路径列表 | 使用同一分区起点；就绪块按剩余关键路径排序，按下述列表完成时间选核；候选重放固定的分核和顺序 | 简单依赖调度在相同尝试数下的质量和成本 |
| 去接收域共享 | 轻量计数、便宜排序和完整参考 COPY 全部改用逐消费者计数；实际提交仍由原官方程序评价 | 接收域共享是否改变选核与选解 |
| 去容量机制 | R 序改为 H 序，保留同一粒度表；去容量锚点、4 个生成保留位、1 个完整保留位、持平挑战及 $P/60$；24/4 全回流常规 | 容量机制从构造到真实比较的整体作用 |
| 完整参考试放 | 每块每核使用前缀四 Pipe 参考图选核；完整计划继续用同一 $J$ | 轻量选核节省的成本及质量代价 |
| 去完整参考复评 | 保留轻量选核和容量候选，完整阶段按固定计划重放式（11），加 $P/60$；不建四 Pipe 最长路径图 | 完整依赖与 COPY 路径是否改善完整候选排序 |

列表基线令块计算量 $w_s=\max(\sum_{v\in s, q_v=M}c_v, \sum_{v\in s, q_v=V}c_v)$，逆拓扑计算块剩余路径。试放核心 $k$ 时，以其空闲时刻 $\ell_k$ 和已排前驱完成时间为起点，再加 $w_s$；A 的非空核加 100，跨核前驱加 1000；B 跨核前驱粗略加 500。同分按核编号。该模型的 500 是轻量依赖近似，真实 B 仍按源 COPY_OUT 完成计时。局部候选重放其既有分核与块序，不重新分核覆盖编辑。

去接收域共享时，以外域消费者个数替代外域数，输入按全部消费者计读取。A 保持一次源写出，每个外域消费者独立一个读；B 每个外域消费者独立一对读写，最终输出照常另计。每个重复读只直接约束指定消费者，MTE2 队列保留对应负载；不把全部重复读变成全部消费者的共同前驱。容量视图始终按真实域中一份副本扫描，重复 COPY 的时间视图和真实容量视图分开。

完整参考试放采用确定的前缀规则：A 从完整分区预知源写出，接收读只计已安排 Task；B 只计已确定的接收核；仍有未分配消费者的张量在前缀末端加虚拟使用位置，最终输出仍按整图标记。它复用主参考函数，不运行官方 Step1 至 Step3。最后一次试放已形成完整计划时直接复用分数。

控制方法第二次尝试从未测起点与该方法局部候选中共同选择；负载、列表和去完整复评分别使用自身明确分数，其余使用对应版本的 $J$。结构不同初始方案均保留竞争资格；具有容量机制的方法保留相应持平挑战。全局分配式中的代理值替换为该方法分数。

主方法的基础及修复尝试按发生顺序占比较槽。仅当首个基础尝试成功、尚余第二槽时，才使用至多一次控制追加；已占满两槽则不再补控制槽。因此控制调用上限为 $4\times(6\times2+1)=52$，未用额度按统一规则结转。主追加同时占该组合两次追加上限。公平表冻结各方法前两个比较槽及最好成功结果，同时列实际调用；主方法后来在全局队列获得的结果另列。超出前两槽才成功的设置标明公平比较缺项。

完整控制组按“小图 A、小图 B、大图 A、大图 B”的顺序运行。压缩成本先减少设置，保留一个设置内全部方法、完整配置和相同尝试上限。已有同计划结果可复用，报告实际调用减少及命中原因。冻结候选池的不同评分排序比较另作静态分析，与端到端控制分别展示。

### 9.5 时间、空间复杂度

记 $E$ 为原始边集，$I=\sum_t(1+|C(t)|)$ 为去重关联数，$E_V$ 为计算依赖边，$E_S$ 为块依赖边。$N_0, E_0, I_0$ 是参考展开后的节点、边和张量关联数；$N', E'$ 是官方换出后规模。$I_{\rm win}$ 是拓扑就绪窗实际扫描的关联总数，重复访问重复计入。

| 步骤 | 时间与空间 |
|---|---|
| 只读图视图、原始计数 | 时间和空间 $O(n+|E|+I+|E_V|)$，保留张量倒排，避免消费者两两完全展开 |
| 两种构造序 | $O(n\log n+|E_V|+I_{\rm win})$ 时间；前沿与堆为线性空间 |
| 一次轻量试放块 $s$ | $O(n_s+I_s+K|T_s|+K)$，其中 $T_s$ 为受影响张量；本地覆盖表为相应规模 |
| 全部轻量试放 | 对实际试放求上述成本之和；不以试放次数乘全图完整建图成本 |
| 一次域计数局部修改 | $O(I_e+K|T_e|)$；重排的覆盖与块拓扑检查另为 $O(n+S+|E_S|)$ 保守上界 |
| 容量便宜扫描 | 对实际受影响域的序列和关联求和，记 $L_e+I_e^{\rm live}$；容量位置探测至多 32 次，再计常规候选中需要的重扫 |
| 一次完整参考图 | 确定性规范序 $O((n+S)\log(n+S)+|E_V|+|E_S|)$，展开、最长路及扫线 $O(N_0+E_0+I_0)$；同量级线性存储 |
| 一批局部生成 | 容量至多 32 次位置检查和重扫后输出至多 4 个，常规补到总数 24；完整参考图至多 4 个，所有探测耗时累计 |
| FIFO 整理与机会扫描 | $O(L+I_{\rm cachewin})$，$L$ 为真实事件和时间线数；窗口重复关联计入 $I_{\rm cachewin}$ |
| 官方评估与诊断 | 以实际展开规模和计时统计，不将整个入口简化为线性 |

规范排序可复用块内确定序和已排序静态邻接，表中保留未命中时的排序成本。容量位置探测需要的规范序重建和排序也计入编辑成本。局部字节更新后，对入围完整候选完整重算最长路。

官方 A 构图有 $O(S|T|)$ 的张量遍历，Step2 在压力时会搜索、排序可换出张量，Step3 和全局模拟还依赖 $N', E'$ 及事件数。拟建调度器记录每次图规模及耗时；一个 worker 同时保留当前计划和至多四个候选的必要结构，完整图用完释放。内存包括静态图、当前展开图和事件，以及 $O(\sum_p|\mathrm{plan}_p|)$ 的长期计划与摘要索引；相同计划存一份，历史大时间线按需读取。

设 $T_{\rm static}$ 为图和拓扑预处理，$T_{\rm light}$ 为轻量试放，$T_{\rm edits}$ 为局部检查与区间扫描，$T_{\rm ref}$ 为式（26）实际建图，$T_{\rm off}$ 为所有真实调用，$T_{\rm diag}$ 为额外诊断，$T_{\rm summary}$ 为汇总，则全包工作为这些实际项之和。并发后的墙钟按实际批次观测计算。

## 10. 论文怎样展开

建议题目为“基于张量驻留域的多核划分与流水线调度”。正文先解释数据跨域的代价和可提交变量，再给出共享模型及有限求解流程，随后按 A 的 Task 边界、B 的同核驻留、C 的 FIFO 读取次序展开三问。每问围绕机制变化、对应公式、可修改决策和实际证据组织。

文章需要用结果回答五个具体问题：少切分起点在哪些结构上有价值；接收域计数是否改变候选排序；容量通道是否减少真实 Spill；完整参考图相比轻量分数如何影响选择；FIFO 调序是否真正改变关键读取及总完成时间。失败或无收益的用例按实际原因分析。

| 图表 | 内容和证据 |
|---|---|
| 原图结构分布 | 操作规模、M/V 周期、输入复用和字节，解释代表例选择 |
| A/B 加速比曲线及逐例分布 | 统一单核与完整矩阵，展示 1 至 5 核趋势和困难用例 |

可直接用于方法介绍的文字：

> 我们以张量的生产域和消费域统一描述三个场景中的数据驻留。独立 Task 共享源端写出，每个接收 Task 单独读入；同核合并场景则按远端接收核建立读写对。算法沿两种拓扑序生成少量分块，以轻量负载和域计数分配核心，再用四流水线参考图和驻留峰值评价完整方案。容量调序具有独立的生成与筛选位置，结构不同的初始方案和局部修改共同竞争真实评估机会。只读 FIFO 场景保留全部同计划硬件对照，并根据实际查询、插入及可移动的读取约束选择调序，最终以官方 Makespan 确定方案。
