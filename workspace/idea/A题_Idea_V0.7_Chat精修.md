# A题 Idea V0.7：驻留域划分与有限候选调度

**题目：**2026 年“华为杯”中国研究生数学建模竞赛 A 题《通用神经网络处理器下的多核调度问题》  
**版本：**V0.7，Chat 精修版  
**日期：**2026-09-24  
**本文范围：**完整研究方案。依据当前上传的 V0.6、题面和官方附件，完成静态核对、模型推导、说明性手算及实施预算设计。

## 1. 用一段话讲清楚 Idea

这道题不是把计算量平均分到几个核上就结束了。切开计算图会增加搬运和同步，留在同一核又可能让张量占满 L1/UB，导致换出和重新读入。我们的主线是：先按张量的生产者和消费者，算清它必须经过哪些“驻留域”；再从独立计算分量、连续支路和关键路径生成少量切图方案，按预计完成时间分核，并通过有限的迁块、拆并和核内调序改善这些方案。问题 1 的驻留域是独立子图 Task，问题 2 改为同核合并 Task，问题 3 继续使用问题 2 的结构，但用 FIFO 查询与完成事件判断哪些搬入能由共享 Cache 服务。所有调整最终只写入子图归属、子图分核和同核顺序。轻量计算负责筛选，官方核内展开负责揭示真实换入换出和 Pipe 依赖，官方多核模拟负责给出最终 Makespan；在有限的已评方案中，先选 Makespan 最小者，再以官方额外搬运量破同分。

## 2. 题意、真实决策与瓶颈

### 2.1 输入和输出边界

输入计算图由操作、张量和操作—张量依赖组成。操作给出 `pipe`、`cycles`，张量给出 `pos`、`size`，其中 `size` 的单位为 bytes。本文把除 `COPY_IN`、`COPY_OUT` 外的操作称为计算操作；原始搬入搬出不参加子图归属决策。[S1，§1.2—1.4、B.3—B.5]

一个方案只输出两个顶层字段：

```json
{
  "node_to_subgraph": {"操作id的十进制字符串": 0},
  "core_schedules": [[0], []]
}
```

上面仅说明字段形状，不是可提交的具体方案。`node_to_subgraph` 必须恰好覆盖全部计算操作；每个非空子图必须且只能出现在一个核心的列表中，列表给出同核顺序，空核列表允许为空。操作发射时刻、换出对象、物理张量版本、内部预取和 Cache 替换顺序都不是可提交变量。

### 2.2 三问共用结构，但不共用一条通信公式

为方便书写，下文用 **A** 表示问题 1，用 **B** 表示问题 2，用 **C** 表示“问题 3 的场景 B 加只读 Cache”。C 只是本文的记号，不是题面新增的第三种 Task 场景。

| 对比项 | A：问题 1 | B：问题 2 | C：问题 3 |
|---|---|---|---|
| Task 组织 | 一个子图一个 Task | 同一核的所有子图合为一个 Task | 与 B 相同 |
| 同核跨子图数据 | 必须经 DDR 中转 | 可在 L1/UB 驻留，必要时换入换出 | 与 B 相同 |
| 同步条件 | 同核上一 Task 完成后至少等 100 cycles；跨核前驱 Task 完成后至少等 1000 cycles | 目标 COPY_IN 等源 COPY_OUT 完成并再等 500 cycles | 与 B 相同，命中 Cache 也不能跳过跨核释放条件 |
| 共享服务资源 | DDR 读写共享 60 bytes/cycle | 同 A | DDR 为 60 bytes/cycle；Cache 读单独共享 250 bytes/cycle |
| Cache 行为 | 无 | 无 | 容量 1048576 bytes，按逻辑 tensor id 查询，FIFO 替换 |

所有场景每核的 L1、UB 容量分别为 524288、131072 bytes。正式结果全部使用上传附件的原始 `data/config.txt`。[S1，B.4、D；S2]

官方执行链为：读取并检查方案，重建 Task 和边界 COPY，运行 Step1 生成核内顺序，运行 Step2 插入必要换入换出，运行 Step3 确定 Pipe 顺序及内存复用依赖，最后进行全局共享带宽事件模拟。B/C 还按 `core_schedules` 对 Step1 序列稳定分桶，并检查操作级跨核依赖。[S3—S8]

B/C 的子图顺序影响操作排列，但不意味着一个子图的所有 Pipe 都结束后，下一个子图才可以执行。因此，不能把 A 的整 Task 串行屏障复制到 B/C，也不能仅凭两个核心互相传数据就判定死锁。

### 2.3 当前附件的静态结构

本轮重新读取当前 ZIP 内的 100 个 JSON。材料仍为 `README.md`、`code/`、`data/`、`docs/`，正式用例为 `case_001.json` 至 `case_100.json`。以下是只读统计，不是评估器运行结果。[S2]

| 静态量 | 最小值 | 中位数 | 最大值 |
|---|---:|---:|---:|
| 非 COPY 操作数 $n$ | 552 | 3720.5 | 35705 |
| 原始张量数 | 816 | 4590.5 | 40287 |
| 原始操作—张量关联数 $I$ | 1841 | 11187 | 108272 |
| 计算依赖弱连通分量数 | 1 | 39.5 | 2666 |
| 计算依赖最长路 $L_G$，cycles | 400 | 6140 | 863040 |
| 单个图输入的最大计算扇出 | 1 | 24 | 2666 |
| $Q^{\mathrm{orig}}/(60\max\{W_M,W_V\})$ | 0.000849 | 0.050138 | 0.259988 |

这里 $W_M,W_V$ 分别为两类计算 Pipe 的原始计算周期总和，$Q^{\mathrm{orig}}$ 为原图 COPY 字节总量。统计还确认：原图没有直接的操作—操作边；每个张量至多有一个计算生产者；计算操作周期均为正；原图 COPY 的 `cycles=0` 是占位值，实际耗时按字节和带宽重算。

对 2、3、4、5 核，都有 16 个用例的计算依赖分量数少于核数。因此，分量装箱只能是一个起点，不能承担全部切分工作。`case_016` 含 17995 个计算操作，却只有一个计算依赖分量，尤其需要在拓扑序中的支路和块边界寻找并行机会。

定义静态比值

$$
r_G=\frac{Q^{\mathrm{orig}}}{60\max\{W_M,W_V\}}.
\tag{1}
$$

当 $r_G>1/K$ 时，原始搬运的带宽下界超过最大计算 Pipe 平均分摊到 $K$ 核的下界。当前数据在 2、3 核下没有这种用例；4 核下为 `case_012`；5 核下为 `case_012`、`case_044`。这只比较必要工作量，不能据此宣布实际运行一定受计算或 DDR 限制。它在本方案中的用途是解释规模与结构差异、选择代表用例，而不是给图贴上不可更改的“计算型/通信型”标签。

## 3. 参考方法及本题的改动

本版只保留两篇直接支持方法结构的原始论文，具体版本与阅读位置见 §12。它们不属于本题官方规则，也不被当作本届获奖论文。

**有向超图与无环划分。**Popp 等的 *Multilevel Acyclic Hypergraph Partitioning* 把一个生产者关联多个消费者的关系写成有向超边，要求块间商图无环，并以拓扑序构造初始划分、在合法边界附近改进划分。[R1，§2、§3.1—3.3] 本题沿用“张量对应多消费者关系”和“划分后仍可执行”的结构，但不直接最小化普通超边割代价：A 按消费 Task 计数，B/C 按消费核心计数，且 B/C 的源核写出会按目标核重复生成。本文的搬运公式由官方构图代码推导，不是从超图论文搬来的时间模型。

**少量不同起点与局部更新。**Schlag 等的 *k-way Hypergraph Partitioning via n-Level Recursive Bisection* 在初始划分和局部细化中使用不同起点、受影响超边的增益更新及局部搜索。[R2，§4.3—4.4] 本题借鉴候选多样性和边界更新方式，但只保留固定数量起点、固定轮数和严格改善的编辑，不实现论文完整的多层收缩、FM 锁定、负增益路径或回退链。

据此，本文方法称为“**驻留域划分与有限候选调度**”，而不称为 HEFT、完整 FM 或多层超图算法的复现。驻留域搬运计数、与官方 Pipe/内存依赖结合的候选筛选、以及当前代码语义下的 FIFO 回放，是针对本题形成的改动和推导。

## 4. 核心主线与贡献

### 4.1 一个主方法，三种驻留和服务规则

主方法始终按同一条路线工作：

**张量域计数 → 有结构差异的初始划分 → 分核与核内顺序 → 有界编辑 → 官方展开筛选 → 少量官方完整比较。**

值得在论文中讲清的贡献有三项。

第一，使用每个张量的生产域和去重消费域计算结构搬运，而不是给每条操作依赖重复收一次费用。它解释了“合并子图”和“迁到同核”在 A/B 中为什么不是同一种改进。

第二，把关键路径、两类计算 Pipe、驻留压力和跨核同步放进同一个候选过程。局部编辑只改提交接口允许的决策；官方展开得到的换入换出与内存依赖负责修正轻量估计。

第三，在问题 3 中把 DDR 与 Cache 当作两个独立服务池，用查询与完成事件筛掉没有实际命中依据的聚合、分散或调序方案，并分别报告硬件增益和调度适配增益。

使用 Python、调用官方评估器、保存结果和生成图表是实现工作，不列为模型创新。

### 4.2 两阶段执行，不建立隐含的核数前缀

后续实现分为 V1、V2 两个执行阶段，它们不是本文之后新增的 Idea 版本。

V1 从固定起点取得全量第一槽结果；V2 在同一批 V1 初始化上做有限改进，并最多再用一个官方比较槽。V2 不重新选择另一条初始化历史来冒充 V1 的严格对照。

本版把每个 $(G,K,\text{场景})$ 定为独立求解单元：当前核数不必先解完所有较小核数，也不以未经计费的补空核方案替换结果。这样，单独请求 5 核 C 时只需要同图、同核数的 B 初始化，不再隐藏 B 的 1—5 核前缀。批量执行仍可复用完全相同的计划和结果，但不依赖跨核数等价性来减少预算。

各组合的候选顺序、轮数、块数和名额在计时后统一冻结。其他用例的赢家、剩余墙钟或瞬时机器负载不改变某张图的候选机会。改变并发只影响执行效率，不改变候选集合。

## 5. 数学模型

### 5.1 变量与可行方案

设 $V$ 为计算操作集合，$n=|V|$；$E_{\mathrm{calc}}$ 为经张量连接得到、按操作对去重的计算依赖。$c_v$ 为操作 $v$ 的计算周期，$q_v\in\{M,V\}$ 为其计算 Pipe。当前数据的 $c_v>0$。

方案记作

$$
X=(g,a,\sigma).
\tag{2}
$$

其中 $g:V\to\mathcal S$ 给出操作所属子图，$\mathcal S$ 只含非空子图；$a:\mathcal S\to\{0,\ldots,K-1\}$ 给出分核；$\sigma_k$ 是核心 $k$ 上所有已分配子图的无重复排列。

块间依赖从实际归属派生：

$$
\mathcal E_X=\{(g(u),g(v)):(u,v)\in E_{\mathrm{calc}},\ g(u)\ne g(v)\}.
\tag{3}
$$

覆盖、唯一性、商图无环和同核依赖顺序属于提交层条件。A 还要求 $\mathcal E_X$ 与同核相邻 Task 顺序边的并图无环；B/C 要在官方核内展开后，检查局部数据/内存边、同 Pipe 相邻边及跨核 COPY 边的并图可执行。[S3—S5、S8]

实现直接维护归属映射、邻接集合和核心列表，不为这些离散关系建立未使用的大规模整数规划变量。候选属于受限构造空间；官方确认可执行的已评方案才进入正式结果集合。

### 5.2 驻留域和边界搬运

计量对象是参与计算的逻辑张量：图输入取原 COPY_IN 后的核内张量，计算结果取计算操作产生的张量，不把它与原 DDR 副本再次计数。设 $b_t$ 为张量字节数，$C(t)$ 为去重计算消费者；$T_{\mathrm{in}}$ 为无计算生产者但有计算消费者的张量集合，$T_{\mathrm{prod}}$ 为有计算生产者的张量集合，$u(t)$ 为后者唯一的计算生产者。令 $o_t=1$ 表示结果存在原 COPY_OUT，或没有后续计算消费者。

**A 的域是 Task。**定义输入接收域与结果外域

$$
I_A(t)=\{g(v):v\in C(t)\},\qquad
R_A(t)=\{g(v):v\in C(t),\ g(v)\ne g(u(t))\}.
$$

问题 1 的构图器对每个外部消费 Task 插入一次读；源 Task 只写一次，这次写也可同时承担最终输出。因此，不含 Spill 的结构 COPY 总量为

$$
Q_A^0=
\sum_{t\in T_{\mathrm{in}}}b_t|I_A(t)|+
\sum_{t\in T_{\mathrm{prod}}}b_t\left[|R_A(t)|+
\mathbf 1\{|R_A(t)|>0\ \text{或}\ o_t=1\}\right].
\tag{4}
$$

**B/C 的域是核心 Task。**定义

$$
I_B(t)=\{a(g(v)):v\in C(t)\},\qquad
R_B(t)=\{a(g(v)):v\in C(t),\ a(g(v))\ne a(g(u(t)))\}.
$$

当前 B/C 构图器对每个源核—目标核组合分别生成一对 COPY_OUT/COPY_IN，最终输出另生成 COPY_OUT。因此

$$
Q_B^0=Q_C^0=
\sum_{t\in T_{\mathrm{in}}}b_t|I_B(t)|+
\sum_{t\in T_{\mathrm{prod}}}b_t\bigl[2|R_B(t)|+o_t\bigr].
\tag{5}
$$

式（4）与式（5）的区别来自两个官方构图器，不能把 A 的“一次写、多次读”套入 B，也不能按消费者操作个数替代消费域个数。[S3，`_build_scene_a_tasks`；S4/S5，`_build_scene_b_tasks`]

当 B/C 只调整子图边界或同核顺序、不改变操作分核时，式（5）不变，但官方核内顺序、Spill、Pipe 等待及 Cache 事件仍可能改变。这正是“搬运量不变，Makespan 仍可变化”的结构原因。

### 5.3 换入换出与报告字段

$Q^{\mathrm{orig}}$ 按原图逐个 COPY_IN 的输出字节和 COPY_OUT 的输入字节相加。对 Step2 产生的每次恢复记录 $e$，$b_e$ 为恢复大小，$z_e=1$ 表示此次换出需要新写 DDR，否则使用已有持久副本。于是

$$
Q^{\mathrm{spill}}=\sum_e b_e(1+z_e),\qquad
Q^{\mathrm{sched}}=Q^0+Q^{\mathrm{spill}},\qquad
Q^{\mathrm{add}}=Q^{\mathrm{sched}}-Q^{\mathrm{orig}}.
\tag{6}
$$

三个量分别对应官方 `spill_added_copy_bytes`、`scheduled_copy_bytes`、`added_copy_bytes`。`partition_added_copy_bytes` 为 $Q^0-Q^{\mathrm{orig}}$。`cross_task_traffic` 的统计范围不同，不能拿来代替完整 COPY 字节总量。

问题 3 的官方这些搬运字段在 Cache 模拟前已经生成。对同一 $X$，加入 Cache 改变 COPY 的服务路径，不直接删除结构 COPY 或 Step2 已插入的 COPY。因此，C 的正式表格原样保留官方 `added_copy_bytes`，另记真正进入 DDR、Cache 读池的服务字节 $Q_D,Q_L$；不把官方结构搬运字段改名为“实际 DDR 流量”。[S4/S5，构图器及结果汇总]

### 5.4 硬容量与官方执行目标

给定 $X$，官方核内展开生成扩展操作集合 $\mathcal O_X$、物理张量版本、Pipe 顺序和内存复用依赖。物理版本 $\tilde t$ 在 $A_{\tilde t}$ 申请存储，在全部读者完成后的 $L_{\tilde t}$ 释放。令 $C_{L1}=524288$、$C_{UB}=131072$，必要的硬容量条件为

$$
\sum_{\tilde t:\,A_{\tilde t}\le \tau<L_{\tilde t}}
 b_{\tilde t}\,
\mathbf 1\{\mathrm{core}(\tilde t)=k,\mathrm{pos}(\tilde t)=m\}
\le C_m,
\quad m\in\{L1,UB\}.
\tag{7}
$$

输入不能在计算刚发射时就视为释放，输出 COPY_OUT 也属于读者。Step2 处理固定访问序上的容量不足；Step3 把容量复用形成的 WAR/WAW 关系写入执行依赖。候选的理想活跃峰值超过容量，只说明有驻留压力，不表示必须丢弃该候选，更不表示超出多少 bytes 就恰好换出多少 bytes。[S6/S7]

设 $S_o,D_o$ 为扩展操作开始、完成时刻，$F_r(X)=\max_oD_o$ 为场景 $r$ 的 Makespan。A 的 Task $s$ 的激活时刻满足

$$
B_s\ge\max\left\{
0,\ \max_{t\in\mathrm{Pred}(s)} E_t,\
\max_{t\in\mathrm{Pred}(s):a(t)\ne a(s)}(E_t+1000),\
E_{p(s)}+100
\right\},
\tag{8}
$$

其中 $E_t$ 为 Task 完成时刻，$p(s)$ 为同核前一个 Task；不存在的项省略，首个根 Task 不额外加 100。B/C 则对每条跨核拷贝连接要求

$$
S_{\mathrm{COPY\_IN}}\ge D_{\mathrm{COPY\_OUT}}+500.
\tag{9}
$$

大小为 $b_e$ 的搬运进入带宽为 $B_p$ 的服务池时，独占参考工作量按官方规则取

$$
w_{e,p}=\max\{1,\lceil b_e/B_p\rceil\}.
$$

该池有 $m_p(\tau)$ 个在途搬运时，各搬运剩余独占工作量 $R_e$ 按

$$
\frac{dR_e}{d\tau}=-\frac{1}{m_p(\tau)}
\tag{10}
$$

更新，并沿用官方完成时刻取整。DDR 与 Cache 读分别维护式（10），不能把两者带宽相加，也不能用所有单次搬运时长相加代替全局 Makespan。

真实优化目标为

$$
\min_{X\ \text{可执行}}\bigl(F_r(X),Q^{\mathrm{add}}(X)\bigr)
\quad\text{按字典序比较。}
\tag{11}
$$

后续程序是在固定候选预算内求式（11）的当前最好方案，不宣称求得整个离散空间的全局最优。时间、服务池状态和物理版本是官方执行递推产生的量，不是额外提交变量。

### 5.5 下界及其用途

令 $L_G$ 为原计算依赖的最长加权路径，$W_q=\sum_{v:q_v=q}c_v$，并令

$$
Q_{\min}=\sum_{t\in T_{\mathrm{in}}}b_t+
\sum_{t\in T_{\mathrm{prod}}}o_tb_t.
$$

在当前输入结构和初始空 Cache 下，每个输入至少发生首次 DDR 读取，最终输出也要写回。因此三种配置共用必要下界

$$
LB_K=\max\left\{L_G,\frac{W_M}{K},\frac{W_V}{K},\frac{Q_{\min}}{60}\right\}.
\tag{12}
$$

对已完成 C 评估的方案，还可用实际池字节检验

$$
F_C(X)\ge
\max\left\{L_G,\frac{W_M}{K},\frac{W_V}{K},\frac{Q_D}{60},\frac{Q_L}{250}\right\}.
$$

下界用于解释依赖限制、检查单位与汇总 $F_r/LB_K$；$T_1/LB_K$ 只是乐观加速比上界。它不进入另一套未实现的优化目标，也不把与下界接近直接称为已证明最优。

本题不采用穷举还有直接的结构理由：在广义 B 输入中，令两个核只执行互不相依的 M 操作，操作周期为正整数 $w_i$，则最小 Makespan 包含把 $w_i$ 分成两组、使最大组和最小的 Partition 子问题。该论证说明一般优化问题至少弱 NP 难，而不是对固定的 100 个用例作复杂度断言。

## 6. 可执行的求解过程

### 6.1 一次预处理和三种构造顺序

每张图只解析一次，保存计算邻接、张量生产者、去重消费者、原 COPY 端点、弱连通分量、各 Pipe 工作量、式（1）和式（12）所需静态量。域计数使用“张量—域—消费者数量”字典；只有数量由 0 变 1 或由 1 变 0 时，接收域集合基数才改变。

反向关键路径为

$$
h(v)=c_v+\max_{v\to u}h(u),
\tag{13}
$$

无后继时最大项为 0。**H 序**在就绪集合中按 $(-h(v),v)$ 选择操作。

**R 序**先取 H 优先级最高的至多 8 个就绪操作，再在其中按“本步释放输入字节减去新增活跃输出字节、$h(v)$、较小操作 id”依次选优。这里的释放用于构造计算序，只统计当前计算消费者关系；完整候选的容量扫描和官方展开还会计入 COPY_OUT 等读者。这个限制使容量偏好不至于任意压过关键路径。

**D 序**用于提供与 H 不同的连续支路布局：弱连通分量按 $(-\max\{W_M,W_V\},\min v)$ 排列；每个分量内部按固定 id 顺序访问根和后继，使用迭代 DFS 的逆后序得到拓扑序，再连接各分量。DFS 连续访问一条支路只是构造偏好，不代表它已经证明各支路互不依赖。

分量少于核数时不凭空补分量。D/H/R 的连续切块仍可在单分量中给出不同粒度，所有新增边界都重新计量。这取代了需要猜测“公共前段在哪里结束”的不明确步骤。

### 6.2 四个固定起点

| 起点 | 划分办法 | 分核和顺序 |
|---|---|---|
| A0 / B0 | 全图一个子图 | 放核心 0，其余核为空 |
| A1 / B1 | 完整计算分量逐个装箱；同箱分量合成一个子图 | 最多 $K$ 个非空子图，每核一个 |
| A2 | D 序连续切成最多 $2K$ 块 | 按块拓扑序逐块试放 |
| A3 | H 序连续切成最多 $4K$ 块 | 按块拓扑序逐块试放 |
| B2 | H 序连续切成最多 $4K$ 块 | 按块拓扑序逐块试放 |
| B3 | R 序连续切成最多 $8K$ 块 | 按块拓扑序逐块试放 |

块数均不超过 $n$，不存在空块。A1/B1 的装箱先最小化放置后全核最大 M/V 负载，再比较新增输入接收域字节，最后按核心号破同分。

连续切块时，设尚余 $b$ 个块、剩余两类计算量为 $M_r,V_r$，目标尺度取 $\max(M_r,V_r)/b$。在目标的 $[0.9,1.1]$ 倍窗口内，优先选择穿过切点的去重张量字节较少的位置，再比较计算量偏差与位置；窗口为空时取最近合法位置，最后一块吸收余项。每个张量按生产者及消费者在序列上的最左、最右位置形成一个区间，区间差分可计算各切点的穿越字节。该切点指标只用于构造，不代替式（4）—（5）。扫描切点属于起点生成成本，不计为免费预处理。

连续拓扑块的商图无环有直接理由：原依赖只从序列前部指向后部，不可能从编号较大的块指向较小块。这给出合法起点，不意味着后续任意拆并仍自动合法。

细分块按全局块拓扑序处理。每次分别试放到 $K$ 个核心列表末尾，用 §6.3 的轻量回放计算已放置前缀的完成时间和搬运增量，选最优位置；未来未放置块的影响在放置后重新计算。每个完整起点最后再做一次完整轻量回放。A1/B1 的分量装箱与细分起点的逐核试放分别计时，不能只把最后四个计划记作全部构造开销。

### 6.3 轻量层：筛候选，不重写评估器

轻量层根据当前 $g,a,\sigma$ 构造参考执行骨架：保留计算操作与原依赖，按式（4）或式（5）产生虚拟边界 COPY；核内计算使用构造顺序并按提交子图列表排列；输入 COPY 紧邻其首次消费者之前，输出 COPY 在生产者之后，并在各 Pipe 上建立固定相邻顺序。涉及多个 COPY 时按逻辑张量 id 破同分。它不执行官方 Step2，不生成虚构的真实 Spill。

对该骨架加入 A 的 Task 激活边，或 B/C 的跨核 COPY 释放边。参考 DAG 上每个操作的完成时间递推为

$$
\widehat D_o=d_o+
\max_{p\in\mathrm{Pred}_{\mathrm{ref}}(o)}
\bigl(\widehat D_p+\delta_{p,o}\bigr),
\tag{14}
$$

其中 $d_o$ 为计算周期或 COPY 独占参考周期，$\delta_{p,o}$ 为适用的 100、1000、500 cycles 延迟，其余边为 0；根节点前驱最大值为 0。A 为每个 Task 增加零时长起止节点，以表达式（8）的最大值关系。B/C 不增加整子图串行屏障。

记 $H_{\mathrm{light}}=\max_o\widehat D_o$，$W_D^{\mathrm{light}}$ 为骨架中所有 DDR COPY 的独占工作量之和。沿骨架访问序计算不换出的理想活跃字节，并定义

$$
\Pi(X)=\sum_{k,m}
\left[\max_j\mathrm{Live}_{k,m}(j)-C_m\right]_+.
\tag{15}
$$

$\Pi$ 是容量压力，单位为 bytes；不是实际 Spill。A 在不同 Task 之间清空驻留，B/C 则在同核合并序上扫描。A/B 的轻量数值评分为

$$
\ell_{A/B}(X)=
\left(\max\{H_{\mathrm{light}},W_D^{\mathrm{light}}\},\ Q^0,\ \Pi\right).
\tag{16}
$$

元组按字典序比较，不把 cycles 与 bytes 相加。轻量骨架有环的候选不继续投入 profile 名额，但这个淘汰仅是搜索筛选，不写成“官方已判无效”。C 的轻量服务池评分见 §7.3。

### 6.4 官方展开层：使用实际产生的顺序和换入换出

本文把一次**完整计划的官方核内展开**称为 profile。A 调用官方 `_build_scene_a_tasks`；B/C 调用各自文件的 `_build_scene_b_tasks`，取得 Task、扩展图、`seq`、`pipe_ops`、内存依赖和搬运汇总。A 构图器已执行 `validate_task_order`；B/C 还调用官方 `validate_execution(tasks, cross_links)`。本版不另建一套通用校验平台。

有两个实现细节直接影响算法和预算。

其一，`prepare_step3_execution` 内部会调用 `step3_simulation`，所以 profile 包含 Step1—3 的实际工作，不是一次低成本字段读取。

其二，构图器内部虽然产生 `spill_records`，返回的 prepared 对象并不直接保存完整记录列表。因此容量反馈优先读取返回扩展操作中的 `spill_logical_tid`、`transfer_bytes`、恢复后的物理张量及其消费者，结合官方汇总量定位大额 Reload。不得把不存在的 `prepared["spill_records"]` 写成已可用接口，也不为拿这个列表修改官方函数。[S3—S7]

从 profile 构造参考 DAG，使用官方局部数据/内存依赖、实际 Pipe 相邻顺序，再加入对应场景的 Task 或跨核释放边。按式（14）得到最长路 $H^0$，令 $W_D^0$ 为这些真实扩展 COPY 的 DDR 独占工作量。A/B 的 profile 数值评分为

$$
p_{A/B}(X)=
\left(J_{A/B},Q^{\mathrm{sched}},Q^{\mathrm{spill}}\right),
\qquad J_{A/B}=\max\{H^0,W_D^0\}.
\tag{17}
$$

$H^0$ 已包含局部 Pipe 工作与依赖，$W_D^0$ 只作为全局共享资源项取最大值，不再与最长路重复相加。它比轻量层多计真实 Spill 和内存依赖，但仍没有模拟动态共享带宽对后续就绪时刻的传播。

计划在进入任何评分之前规范化一次：按子图内最小操作 id 给非空子图确定编号，同时同步改写核心列表；之后 profile、完整评估和输出都使用这份实际编号。**不置换核心编号，不把抽象同构计划直接视作相同执行计划。**去重键为规范化提交、图标识、场景、核数、配置及当前官方代码版本的普通组合键，不额外建设哈希审计系统。

### 6.5 有界编辑：生成、接受、更新和停止

规模档只由当前图的非 COPY 操作数决定。

| 规模 | 范围 | 轻量轮数 $R$ | 每轮实例化候选上限 A / B / C |
|---|---|---:|---:|
| 小 | $n\le2000$ | 3 | 64 / 48 / 64 |
| 中 | $2000<n\le10000$ | 2 | 48 / 36 / 48 |
| 大 | $n>10000$ | 1 | 32 / 24 / 32 |

当前 100 图在三档中分别为 41、40、19 个。每个 A/B 组合在全部轮次结束后最多新增两个局部 profile；C 的 profile 总上限另见 §7.3。

编辑只保留四类：整块迁核；相邻块合并或沿现有拓扑序拆分；边界操作隔离后迁移；同核块前移或后移。A 优先整块和切点，单操作新 Task 每轮最多 8 个，并且该操作必须关联较大的跨域字节、关键路径或容量压力；B/C 一次编辑至多隔离两个操作。编辑后子图数不得超过 $\min(n,8K+16)$。

每类编辑的落点也固定。整块迁移先列出其生产者/消费者所在的不同核心，再补一个计算负载最低的其他核；目标列表只试满足同核依赖的最早、最晚插入位置，重合时只试一次。合并只取同核列表中相邻的两个块；拆分只在锚点前后最近的非空拓扑切点进行，拆出的块先相邻留在原核。隔离操作时按原块的拓扑位置保留其前后连续段，避免把不连续的剩余操作盲目合成一个可能有环的块；单操作或至多两个操作形成的待迁块，再使用上述迁移落点。同核调序只试相关生产块之后、消费块之前及容量峰值关联块两侧的位置。所有这些描述仍统一受本轮候选总上限截断，不按每类各自再享有一份上限。

锚点按用途确定：域边界取跨域关联字节最大的至多 32 个操作；路径锚点取高 $h(v)$ 的相关边界；容量锚点取当前 profile 中最大的至多 8 个带 Spill 标记的恢复操作，没有匹配 profile 时使用当前轻量序中最大的活跃峰值。候选先用轻量编辑描述排序，四类编辑轮流取一个，某类耗尽就跳过；同类按关联字节、路径值、操作 id、目标核心及插入位置破同分。达到表中上限即停止实例化，不先生成几百个完整计划再把它们的成本删掉。

每个实例化候选执行以下过程：应用编辑，规范化计划，检查提交层约束和块数，更新所有受影响张量的生产域及消费域，重放轻量时间与容量，再与当前状态比较。迁移一个操作时，它的全部输入、输出和共享消费者都属于受影响范围；不能只更新最初触发编辑的那个张量。

每轮选择数值评分严格优于当前状态的最佳候选，作为下一轮状态。完全相等的评分不接受，计划键仅用于不同候选之间破同分。接受后立即更新域、核心列表、参考时间和容量峰值；旧 profile 的 Spill 锚点不再冒充新状态的锚点。

跨轮次保存两类可能入围的状态：轻量评分最优的已接受状态，以及相对冻结 $X_0$ 的容量压力 $\Pi$ 有下降的已接受状态中最优者。两者去重后至多做两个局部 profile，且分别与初始化 profile 使用同一评分口径。由此，多轮轻量探索不等于每轮都运行两次 Step1—3。

达到固定轮数、没有严格改善、候选耗尽或块数限制后停止。未使用名额不转给其他图；失败 profile 消耗自身名额。容量下降若以更差的主时间评分为代价，不会被静默作为“收益”接受。

### 6.6 两个完整评估槽怎样使用

设 $\mathcal P_0$ 为四个起点中去重、profile 成功的集合。第一槽计划固定为

$$
X_0=\arg\min_{X\in\mathcal P_0}(p_{A/B}(X),\mathrm{key}(X)).
\tag{18}
$$

V1 对 $X_0$ 做完整官方评估并保存。V2 的初始状态仍是这个 $X_0$，不是其他用例或核数的赢家。

第二槽候选池包括：尚未与第一槽正式比较的其他成功起点，以及 profile 数值评分严格优于 $X_0$ 的局部候选。去重后按同一个 profile 元组选最好者 $Y$。这个规则给不同初始结构和局部改进同等的排序机会，**不声称局部候选必然优先于另一种起点**。只有池为空时才省略第二槽。

每个组合的完整调用上限始终为 2。第一槽失败时，第二槽优先用于尚未正式评估、profile 成功的 A0/B0；不存在这种计划时使用成功候选中的下一名。这是计入第二槽的修复，不产生第三槽。第一槽修复可先于全量 V1 结束完成，修复用掉第二槽后，V2 不再对该组合追加完整调用。所有起点 profile 都失败时，可在第一槽直接提交 A0/B0 给官方入口诊断，但不能写成已取得合法结果。

最终仅在成功的官方结果中按式（11）选优。完整评估比第一槽更慢时仍保留第一槽；两次均失败则保留失败状态并定位原因，不填零、不拿代理值替代，也不从均值分母中悄悄删去该用例。

### 6.7 复杂度与伪代码

设 $t$ 为张量数，$I$ 为操作—张量关联数，$S$ 为当前子图数，$N_X,E_X$ 为官方展开后的操作和依赖规模。静态邻接与域视图为 $O(n+t+I)$；H/R 的堆式就绪选择为 $O((n+I)\log n)$，D 序为线性遍历。切点扫描和逐核试放单独计入起点构造：最多 $S$ 个切块阶段、$SK$ 次前缀试放，每次试放最坏仍需一次参考骨架回放。

一项完整轻量候选的保守上界为

$$
O(n+t+I+S^2),
$$

其中 $S^2$ 覆盖最坏块间关系处理。域差量可减少实际更新，却不把整次合法性检查和时间重放变成常数时间。每个 A/B 组合最多执行 $Rq$ 次局部轻量回放；$q$ 为规模表对应上限。C 另有最多 16 次聚合/分散内部试放。

一次 profile 的真实代价记为 $P_r(G,X)$，它包含所有 Task 的官方构图和 Step1—3，不能以 $O(N_X+E_X)$ 的最长路计算代替整个 $P_r$。最长路和容量反馈扫描在已展开图上另需线性工作；C 的事件代理排序为 $O(N_{\mathrm{in}}\log N_{\mathrm{in}})$，$N_{\mathrm{in}}$ 为展开后的 COPY_IN 数。

```text
solve_AB_v1(G, K, scene):
    static = get_or_build_static(G)
    seeds = build_four_seeds(static, K, scene)
    for each distinct normalized seed:
        light_replay(seed)
        profile(seed) with official construction and applicable checks
    X0 = best successful seed by profile numeric tuple, then exact plan key
    evaluate X0 in official slot 1
    if slot 1 fails:
        use at most slot 2 for the defined valid-seed repair
    save X0, successful seed profiles, official results, slot usage

refine_AB_v2(saved_v1):
    if no successful initialization or both slots already consumed: stop
    current = frozen X0
    accepted = bounded_rounds(current, strict light improvement)
    profile at most two distinct retained local states
    pool = untested alternative seeds + eligible improving local profiles
    if pool nonempty: evaluate best(pool) in remaining slot 2
    return best successful official result by (makespan, added_copy_bytes)

solve_C_v1(G, K, saved_B_v1):
    XB0 = successful B V1 result at exactly this G and K
    if that B unit has never run: build and charge it once
    if the B unit exhausted its slots without success: record dependency failure and stop
    build C base profile for XB0; obtain FIFO proxy
    evaluate XB0 under default Cache in C slot 1
    save the frozen baseline and its C result

refine_C_v2(saved_C_v1):
    generate bounded aggregate/disperse edits and bounded local rounds
    profile at most three new C states in total
    if a valid state strictly improves the base C profile tuple:
        evaluate the best such state in C slot 2
    retain the best successful C result; do not replace frozen XB0
```

上面是拟实现伪代码，不是本轮已运行的程序。官方完整入口会重新构图，如何计费及如何避免误用 prepared，见 §9 和 §11。

## 7. 问题 1、2、3 如何递进

### 7.1 问题 1：切开以后值不值得

A 的关键决策是 Task 粒度。一次拆分会同时改变输入接收域、结果外域、同核 Task 间的 100 cycles、跨核前驱的 1000 cycles，以及各 Task 内的容量压力。因此，A 的第一类机会是把独立分量分开执行，第二类机会是在连续支路或关键路径附近切出确有并行机会的块，第三类机会才是利用拆分改善过大的核内工作集。

A1 用粗粒度分量装箱减少 Task 数；A2/A3 用不同拓扑序和粒度提供更细的并行机会。局部过程只有在整个轻量元组改善时才接受新边界。将一个子图移到同一核的另一个位置不会自动消除边界 COPY；要消除这类搬运，需要相应张量的生产、消费操作真正进入同一个 Task。

第一槽和第二槽的官方比较同时回答两件事：并行缩短了哪些路径，以及增加的搬运、同步和容量变化是否抵消了这些收益。论文不将“切出更多块”单独当作贡献。

### 7.2 问题 2：从 Task 边界转向核心驻留和顺序

B 不再为同核子图间的依赖生成边界 COPY，因此沿用 A 的构造框架，但用式（5）替换式（4），用式（9）替换 A 的 Task 等待，并在同核合并访问序上扫描容量。

此时两个操作即使分属不同子图，只要在同核就有复用机会；反之，把共享输入的消费者迁到另一核，会增加新的输入接收域。B2/B3 保留多个子图，是为了通过提交顺序影响官方稳定分桶，而不是错误地把多个子图当成多个独立核心 Task。

容量编辑重点是把一个大张量的末次消费者提前，或将另一大张量的生产推迟，缩短两者驻留区间的重叠。能否这样移动由依赖决定；是否减少真实 Reload 由新 profile 的 `spill_added_copy_bytes` 和扩展操作决定。B3 的 R 序为这类编辑提供不同起点，不能把 H/R 本身说成参赛者可直接控制的最终操作顺序。

### 7.3 问题 3：Cache 改变哪一步选择

#### （1）先固定同方案硬件对照

对同一图和核数，记 V1 中成功的 B 基准计划为 $X_B^0$。C 的第一槽始终评估这个计划，在不改变提交结构的条件下观察共享 Cache 的作用。V2 可以改进 B 得到 $X_B^*$，也可以从冻结的 $X_B^0$ 生成 C 挑战得到 $X_C^*$，但不把新的 $X_B^*$ 偷换进已有 C 第一槽。

#### （2）按当前代码完整定义查询与插入

当前问题 3 的 `cache_eligible` 按操作类型判断，范围是 **COPY_IN**，不只限于原图输入。跨核搬入以及 Step2 生成的恢复 COPY_IN，只要发射时具有有效逻辑键、正传输字节，都参与 Cache 查询和命中统计。键由核内张量的 `logical_tid` 取得；没有这个字段时使用其 tensor id。[S5，`copy_tensor_info`、`cache_eligible`、`issue`]

查询发生在发射时。命中进入 Cache 读池，不刷新 FIFO 顺序；未命中进入 DDR 池。没有“在途相同 miss 合并”：同一逻辑张量在首次插入之前被两个核心同时查询，两次都可以 miss。跨核 COPY_IN 无论命中与否，都要先满足 500 cycles 的释放条件。

完成处理还有一个不能略去的代码细节：`retire` 会对**每个 COPY_IN 的完成**调用 `insert_cache`。该函数在键仍存在时直接返回，在键已不存在且大小可容纳时按 FIFO 规则重新插入。于是，命中读在途期间若原条目被其他插入淘汰，它完成时也可能把这个键重新插入队尾。通常条目尚在时仍是“命中不刷新”；这不是自行设计的写回或预取策略，而是当前附件的实际完成处理路径。COPY_OUT 不因此成为 Cache 填充操作，超过容量的对象不插入。[S5，`insert_cache`、`retire`]

#### （3）轻量层分开两个资源池

对图输入 $t$，令 $r_t=|I_B(t)|$，$C_L=1048576$。轻量层使用“首读 DDR、其余接收核读 Cache”的乐观输入复用假设：

$$
(d_t,\ell_t)=
\begin{cases}
(0,0),&r_t=0,\\
\bigl(\lceil b_t/60\rceil,(r_t-1)\lceil b_t/250\rceil\bigr),
 &r_t\ge1,\ 0<b_t\le C_L,\\
\bigl(r_t\max\{1,\lceil b_t/60\rceil\},0\bigr),&\text{其他情况}.
\end{cases}
\tag{19}
$$

首个参考查询按轻量到达时刻、核心号、稳定顺序确定。其他边界搬运在这一层先按 DDR 工作量 $O_D$ 计；完整 profile 再判断中间搬入与 Reload 的 Cache 可能性。令

$$
W_D^{\mathrm{light}}=\sum_t d_t+O_D,\qquad
W_L^{\mathrm{light}}=\sum_t\ell_t,
$$

并用相应参考 COPY 时长重算式（14），得到 $H_{\mathrm{light},C}$。C 的轻量元组为

$$
\ell_C(X)=\left(
\max\{H_{\mathrm{light},C},W_D^{\mathrm{light}},W_L^{\mathrm{light}}\},\
W_D^{\mathrm{light}}+W_L^{\mathrm{light}},\ \Pi
\right).
\tag{20}
$$

两个池的总和只作次级比较，不作为主时间。式（19）没有检查首次插入之前的并发 miss 和淘汰，不是正式命中预测，也不是对完整系统的严格下界。

#### （4）只生成有明确作用的三类 C 候选

**聚合路径**按输入大小乘以消费块数选共享输入，尝试把一个消费块迁入已有消费者工作量最大的核。每次只移动一块，每条聚合路径最多 8 次完整轻量试放；所有受影响的输入、输出域和容量都要重算。

**分散路径**尝试把较重消费块的一个连续拓扑段放到计算负载较低的其他核，前提是存在两个非空段、确实新增接收核心且提交层合法。目标核按最大计算 Pipe 负载、核心号确定，不为每个输入无限枚举全部划分。整条分散路径也最多 8 次完整轻量试放。

**顺序与边界局改**使用 §6.5 的规模档，重点取 C 基准 profile 里重复 miss 的逻辑张量与容量锚点。只有提交调整确实改变轻量骨架的 MTE2 先后或其依赖时，才把它作为错峰候选；通过 profile 再检查官方 Pipe 顺序是否改变。不添加接口外的主动等待，不把“让两个核晚一点读”当作可以直接填写的参数。

聚合、分散两条路径都从冻结基准出发；有严格轻量改善时保留其最后一个成功状态。普通局改也从冻结基准出发，保留一个最佳已接受状态。三者去重后最多产生三个新 C profile，加上 C 基准 profile，每个组合总计不超过四个。

#### （5）一次 FIFO 事件代理与一次重加权

对每个 C profile，先在其真实扩展依赖及 Pipe 序上假设 COPY 使用 DDR 独占参考时长，计算一遍查询、完成参考时间。固定这份事件流，先处理同刻完成，再处理同刻查询，并按官方核心号、Pipe 顺序和稳定次序破同分。对全部符合条件的 COPY_IN 回放上述 FIFO 规则，包括完成时重新插入的路径，得到预计命中集合 $\hat h$。

随后只进行一次时长重加权：预计命中的 COPY_IN 改用 Cache 参考时长，其余 COPY 仍按 DDR；重新求参考最长路 $H_C^{(1)}$。记 $W_D(\hat h),W_L(\hat h)$ 为两个池的预计独占工作量，$\hat Q_D$ 为预计 DDR 服务字节，$\hat Q_H$ 为预计命中字节，定义

$$
p_C(X)=\left(
\max\{H_C^{(1)},W_D(\hat h),W_L(\hat h)\},\
\hat Q_D/60,\ -\hat Q_H,\ Q^{\mathrm{spill}}
\right).
\tag{21}
$$

这一步不反复求 Cache 状态的固定点；重加权后事件顺序可能改变，所以 $\hat h$ 是筛选信息，真实命中仍由官方完整模拟决定。第二槽只评估 profile 数值元组严格优于冻结 C 基准的最佳挑战；没有符合条件的挑战就保留第一槽。

### 7.4 三类加速比不能混成一个

对每个图、每个核数，分别计算

$$
S^{\mathrm{hw}}=\frac{F_B(X_B^0)}{F_C(X_B^0)},\qquad
S^{\mathrm{adapt}}=\frac{F_C(X_B^0)}{F_C(X_C^*)},\qquad
S^{\mathrm{opt}}=\frac{F_B(X_B^*)}{F_C(X_C^*)}.
\tag{22}
$$

第一项是同方案硬件对照；第二项是启用 Cache 后的方案适配收益；第三项是两种配置分别优化后的方案对照。前两项相乘的分子仍是 $F_B(X_B^0)$，不一定等于第三项。三条口径都有已包含在主矩阵中的结果，不需为解释这一区别再增加全量实验。

正式无 L2 使用 B 入口，正式 Cache 使用 C 入口的原始配置。容量为 0 的 C 入口只做小范围配对核对；它不是替换全部 B 正式结果的理由。

## 8. 说明性手算：同一张小图贯穿切分、分核与 Cache

本节数字用于核对决策与计数。除明确隔离出的子系统计算外，不把它们称为官方共享带宽 Makespan。

### 8.1 小图、操作与容量

图输入 $x$ 为 60000 bytes，位于 UB。操作 $p$ 使用 $x$，计算 1000 cycles，产生 30000 bytes 的 $z$；操作 $a,b$ 均使用 $x,z$，各计算 800 cycles，分别产生 6000 bytes 的最终结果 $y_a,y_b$。三个操作都使用 V Pipe。依赖为

```text
x ──→ p ──→ z ──→ a ──→ ya ──→ DDR
│            └──→ b ──→ yb ──→ DDR
├────────────────→ a
└────────────────→ b
```

每个操作自身的输入与输出总量均小于 UB 容量。例如 $a$ 的合计为 $60000+30000+6000=96000$ bytes。原始 COPY 总量为

$$
Q^{\mathrm{orig}}=60000+6000+6000=72000\ \text{bytes}.
$$

### 8.2 把子图放在同核，并不等于合并子图

比较以下方案的**不含 Spill 的结构字节**。

| 方案 | A 的 $Q_A^0$ | B 的 $Q_B^0$ | 变化来自哪里 |
|---|---:|---:|---|
| 全图一个子图，核心 0 | 72000 | 72000 | 输入一次、最终输出两次 |
| 三个子图 $\{p\},\{a\},\{b\}$，全在核心 0 | 282000 | 72000 | A 仍有三个输入消费 Task 和两个外部消费 Task；B 为一个核心域 |
| 三个子图分别在三个核心 | 282000 | 312000 | B 对 $z$ 的两个目标核分别生成写读对 |
| 子图不合并，但把 $a,b$ 放同一核心，$p$ 留另一核心 | 282000 | 192000 | B 的输入接收域和 $z$ 目标核都减少一个 |
| 进一步把 $a,b$ 合成一个子图 | 192000 | 192000 | A 此时才减少消费 Task；B 的结构计数不再变化 |

以“三个子图分别在三个核心”为例，A 的费用为

$$
\underbrace{3\times60000}_{x\text{ 的三次读}}+
\underbrace{30000+2\times30000}_{z\text{ 的一次写、两次读}}+
\underbrace{2\times6000}_{\text{最终输出}}
=282000.
$$

B 的费用为

$$
3\times60000+
\underbrace{2\times(30000+30000)}_{z\text{ 的两个跨核写读对}}+
2\times6000=312000.
$$

将 $b$ 迁到 $a$ 所在核后，B 变为

$$
2\times60000+(30000+30000)+2\times6000=192000.
$$

一次迁核减少 120000 bytes，新增搬运由 $312000-72000=240000$ 降为 $192000-72000=120000$ bytes。这正是局部迁核需要重新计算所有相关张量域的原因。

但两个分支原本可以在两个核并行，迁到同核后要竞争同一条 V Pipe。只看计算，分支并行的依赖路径为 $1000+800=1800$ cycles，同核三项计算总量为 $2600$ cycles；只看上述 B 结构字节，DDR 独占工作量分别为 $312000/60=5200$ 与 $192000/60=3200$ cycles。这些相反方向的变化由同一个候选过程比较，不能只凭节省字节就宣布实际 Makespan 一定下降。

### 8.3 A 的等待项和 B 的驻留项

单看 $p\to a$ 这条链、暂不计 COPY，同一 Task 内计算路径为 $1000+800=1800$ cycles。A 切成同核两个 Task 后，参考路径至少为 $1000+100+800=1900$；放到不同核后至少为 $1000+1000+800=2800$。真实方案还需要加上相应 COPY 及共享带宽影响。B 则等待具体源 COPY_OUT 完成后再加 500，不能用整 Task 的 1000 替代。

容量编辑可用另一个局部状态说明：某核先后产生两个各 81920 bytes 的 UB 输出，如果前一个尚未完成末次使用，理想活跃峰值为 163840，超出容量 32768 bytes。若第一个张量可被换出且没有 DDR 副本，对它完整写回并恢复的字节为 $2\times81920=163840$，不是超额的 32768。若已有副本，恢复可只新增 81920 bytes。将末次消费者合法前移，有机会消除重叠；是否发生上述换出，由实际 profile 决定。

### 8.4 查询时间为什么重要

回到 60000 bytes 的 $x$。隔离观察三个核心的读入，不放入其他传输：单次 DDR 独占工作量为 1000 cycles，单次 Cache 读为 240 cycles。

若三次查询都在初始时刻发射，Cache 为空，三次都 miss；三个相等读公平共享 DDR，在这个隔离子系统里各于 3000 cycles 完成。若第一读在 0 时刻发射并于 1000 完成插入，另两次查询恰好在此后发射且没有淘汰，它们都 hit，两个 240 cycles 的 Cache 工作共享带宽，经过 480 cycles，于 1480 完成。

这里的 3000 和 1480 是给定查询时刻的读入子系统手算，不是上面整张计算图的评估结果。算法不能直接提交“延迟 1000 cycles”；它只能通过合法的块顺序、依赖和分核改变实际查询时刻，再由完整评估判断是否出现这种访问关系。

最后用默认容量说明完成时插入的特殊路径。设三个逻辑张量 $x',y',z'$ 各为 400000 bytes，FIFO 当前为 $[x',y']$。一次 $x'$ 命中读开始后顺序不变；若另一次 $z'$ 搬入先完成，插入 $z'$ 会淘汰 $x'$，队列变为 $[y',z']$；随后在途 $x'$ 命中读完成，当前代码发现键已不存在，会插入 $x'$ 并淘汰 $y'$，队列变为 $[z',x']$。这个队列状态例子说明：仅在 miss 完成时更新 FIFO，会与当前官方代码产生不同的后续命中预测。

## 9. 后续实验、完整覆盖与 8 小时预算

### 9.1 先测实现成本，再冻结运行协议

本节是后续执行设计。最小验证从提交合法性、边界 COPY 计数、B 的跨核释放、容量反馈和 C 的查询/完成事件开始，优先复用官方检查和手写小方案，不运行随机暴力搜索。

按照非 COPY 操作数及 case id 的固定排序，计时样本取最小图 `case_093`、最接近中位数的 `case_034`、最大图 `case_014`。每图观察统一单核 $T_1$，A 的 2/5 核，B 的 1/5 核，C 的 1/5 核，共 21 个观测。计划由本方案的固定 V1 起点及评分规则确定并保存，后续全量主矩阵复用完全相同的首槽输入和结果；计时样本不是另行人工挑一个更好跑的计划。

另外预留 6 次完全相同入口的计时复测，用于观察冷启动、并发下的峰值内存和实际吞吐。构造起点、逐核试放、轻量回放、profile、官方完整入口、C 代理事件排序、结果写入分别计时。一次官方完整入口内的 Step1—3 只记在该入口耗时里，不再在同一时间账中重复加一次。

这 21 个观测附着在正式覆盖内，6 次复测另计。若计时后统一改变候选协议，使某个首槽计划发生变化，旧调用不能再冒充新协议正式结果：优先精确复用仍相同的计划，不同计划占用明确的诊断或重算名额，并重新计算总上限。

### 9.2 必须完成的正式矩阵与统计

100 个用例各取得一次官方统一单核基准 $T_{1,i}$。A 正式多核方案覆盖 2—5 核；B 覆盖 1—5 核，其中 1 核是问题 3 的无 L2 比较所需；C 覆盖 1—5 核，同一冻结 B 计划在 Cache 下的结果和至多一个 C 挑战都归入主矩阵。

问题 1、2 的 1—5 核平均加速比使用题面口径：

$$
\overline S_{r,K}=\frac{1}{100}\sum_{i=1}^{100}
\frac{T_{1,i}}{F_{r,i,K}},\quad r\in\{A,B\},\ K=2,3,4,5;
\qquad \overline S_{r,1}=1.
\tag{23}
$$

B 在 1 核下自行优化出的结果不替代统一 $T_1$。固定单核启发式可能使多核加速比超过核数，这不是自动判错条件。[S1，问题 1—2 脚注；S9]

问题 3 逐例报告 B/C 的 Makespan、官方额外搬运量和 Cache 命中率，并对式（22）分别求逐例比值的算术平均。Cache 命中率按 `hit_bytes/(hit_bytes+miss_bytes)`，没有访问时沿用官方值；B 没有 Cache 的列标为“不适用”，不伪造命中观测。另用 C 的操作服务路径统计 $Q_D,Q_L$，解释命中收益是否真正缓解了 DDR 等待。

每个正式组合同时保存 V1 首槽、最终选择、第二槽是否改善、真实增益、失败状态和额外运行时间。第一槽到最终槽的差异表示“相同 V1 初始化上的有限改进收益”，不把它说成两个独立算法完整运行的消融。

再从六图、2/5 核、A/B/C 各保留一个已生成但未获正式槽位的候选作代理诊断，最多 36 次。记录它与主方案的真实顺序是否一致，诊断结果不反向替换冻结的主结果。缺少不同候选时省略，不为了填满数量新增搜索。

### 9.4 微图与补充核对的边界

微图预算为 6 对、每对 2 次完整调用，共 12 次。覆盖：A 的同核 Task 边界；B 的接收核计数；跨核 COPY 释放；UB 容量调序；C 的查询先后；同计划 C 零容量与 B 配对。

FIFO 在途命中完成后重新插入、逻辑 id 复用、输出写回不填 Cache等局部状态，可直接依据小规模事件记录与 §8 的手算核对。它们不形成新的 100 图矩阵。若某项需要追加完整官方调用，就从上述 12 次或诊断名额中替换一项，不出现未计费的“顺手再测”。

### 9.5 完整调用与 profile 的上限

正式比较以官方完整入口调用数计，失败调用也占槽。相同输入、配置、核心号和完整计划的结果可精确复用；单纯核心数不同、场景不同或候选结构相似，不计作一次结果复用。

| 项目 | 数量来源 | 官方完整调用上限 |
|---|---|---:|
| 统一单核基准 | $100\times1$ | 100 |
| A 主矩阵 | $100\times4$ 个核数 $\times2$ 槽 | 800 |
| B 主矩阵 | $100\times5$ 个核数 $\times2$ 槽 | 1000 |
| C 固定方案与挑战 | $100\times5\times2$ 槽 | 1000 |
| **正式主矩阵** | 以上合计 | **2900** |
| 去接收域引导，A/B | $6\times2$ 核数 $\times2$ 场景 $\times2$ 槽 | 48 |
| 去容量引导，B | $6\times2\times2$ | 24 |
| 轻量排序，A | $6\times2\times2$ | 24 |
| Cache 单因素诊断 | $6\times4$ | 24 |
| 代理候选诊断 | $6\times2\times3\times1$ | 36 |
| 机制微图 | $6$ 对 $\times2$ | 12 |
| 计时复测 | 6 次，21 个首轮观测已附着主矩阵 | 6 |
| **完整官方调用合计** | $2900+48+24+24+24+36+12+6$ | **3074** |

其中常规第一槽覆盖为 $100+400+500+500=1500$ 次，其余主矩阵名额最多 1400 次。第一槽失败后的修复提前使用这 1400 次中的相应第二槽，不增加主矩阵总数，因此“第一阶段恰好最多 1500 次”只在不发生提前修复时成立。

独立 profile 另计，不能和上述官方完整调用混为同一层：

| 独立 profile 项目 | 上限来源 | 次数 |
|---|---|---:|
| A/B 主矩阵 | $900$ 组合 $\times(4$ 起点 $+2$ 局部$)$ | 5400 |
| C 主矩阵 | $500\times(1$ 基准 $+3$ 新候选$)$ | 2000 |
| 去接收域控制 | $24$ 组合 $\times6$ | 144 |
| 去容量控制 | $12$ 组合 $\times6$ | 72 |
| 代理诊断额外展开 | 最多 36 个缺少可复用摘要的候选 | 36 |
| **独立 profile 合计** | $5400+2000+144+72+36$ | **7652** |

轻量排序控制不做独立 profile；它的完整官方调用已经包含官方展开。单因素诊断只用冻结计划直接进入完整入口，不另做优化 profile。微图和复测同理。C 基准 profile 在上限中仍按一次独立展开计费，不预先扣除跨入口复用。

**当前官方 `evaluate_scene_a`、`evaluate_scene_b`、`evaluate_problem_3` 都会在内部重新调用构图器，不接受外部 prepared 参数。**因此，独立 profile 之后再完整评估同一方案，仍会重复一次官方核内展开。按最坏上限，计划级构图/Step1—3 过程最多被调用

$$
7652+3074=10726\ \text{次}.
\tag{24}
$$

每次还可能包含多个 Task。这个总数是预算核算，不是声称每次开销相等；准确工时仍按实际图、Task 数、扩展规模和运行阶段统计。

轻量工作量单列：A/B 每组合有四个起点、起点内部的装箱/逐核试放、至多 $Rq$ 个局部候选；C 有基准轻量状态、最多 16 次聚合/分散内部试放和至多 $Rq$ 个局部候选。控制方法重走自己的流程。候选即使未进入 profile，它的实例化、约束检查、域更新和重放也要计时。

### 9.6 8 小时墙钟如何判断可达

总目标为 28800 s，预留 3600 s 给环境准备、汇总和必要返工，工作阶段预算为 25200 s。V1 覆盖、V2 改进、控制与诊断的初始设计配额分别为 10800、9000、5400 s；它们是待计时验证的配额，不是实测承诺。

对阶段 $s$，把互斥计算时间记为

$$
W_s=\sum_j\left(
 t_{\mathrm{seed},j}+t_{\mathrm{light},j}+t_{\mathrm{profile},j}+
 t_{\mathrm{official},j}+t_{\mathrm{FIFOproxy},j}+t_{\mathrm{IO},j}
\right).
\tag{25}
$$

静态解析每张图一次，另记在串行准备或所在 worker 的首次成本中。$t_{\mathrm{official}}$ 已包含该完整入口内部的构图、Step1—3 与全局模拟；$t_{\mathrm{profile}}$ 只计额外的独立展开；$t_{\mathrm{FIFOproxy}}$ 只计本文新增的参考事件回放，不重复加入官方 Cache 模拟时间。

设系统与主进程占用为 $M_0$，内存预留为 $M_{\mathrm{res}}$，本阶段单 worker 最大增量 RSS 为 $m_s$，实际可用的进程并发上限为 $p_{\mathrm{hw}}$，则

$$
p_{\mathrm{eff},s}=\min\left\{p_{\mathrm{hw}},
\left\lfloor\frac{48\,\mathrm{GiB}-M_0-M_{\mathrm{res}}}{m_s}\right\rfloor\right\}.
\tag{26}
$$

从串行和少量并发计时取得这些量，不预设某个 M4 Pro 核心规格或把 48GB 全部分配给 worker。若一个 worker 都装不下，先减少同时保留的展开图并复测，不能简单把计算为 0 的并发数改成“已可串行”。

实际墙钟近似受总工作与最长依赖链共同约束：

$$
\widehat T_{\mathrm{wall}}=
T_{\mathrm{prepare}}+T_{\mathrm{summary}}+
\sum_s\left[T_{\mathrm{serial},s}+
\max\left\{\frac{W_s}{p_{\mathrm{eff},s}},\ T_{\mathrm{chain},s}\right\}\right].
\tag{27}
$$

$T_{\mathrm{chain},s}$ 包括同图、同核数 B 初始化之后才能开始的 C 基准和挑战，不将这条依赖链除以任意大的 worker 数。任务规模不均和并发争用会使近似出现偏差，后续用分规模实际完成时间校正预测。

将全部伴随工作按 3074 个完整调用折算，25200 s 工作预算要求平均综合处理量满足

$$
\bar t_{\mathrm{combined}}\le
\frac{25200\,p_{\mathrm{eff}}}{3074}
\approx8.198\,p_{\mathrm{eff}}\quad\text{s/完整调用}.
\tag{28}
$$

例如有效并发为 2、4 时，阈值约为 16.40、32.79 s。这里的“综合”同时包含独立 profile、候选和写入摊销，不是只要求最后一次模拟足够快。

单独请求 C 的成本也明确包含同核数的 B 初始化：

$$
T_{C,\mathrm{cold}}(G,K)=
T_{B,\mathrm{V1}}(G,K)+T_{C,\mathrm{base}}(G,K)+
T_{C,\mathrm{refine}}(G,K)+T_{\mathrm{cold\ start}}.
\tag{29}
$$

已有完全相同的 B V1 记录时才扣除第一项；不把它隐藏到别的批次。题面的单例约 5—10 分钟是效率建议，与总墙钟预算一并检查。

若计时预测超过预算，先移除候选诊断和非默认参数诊断，再统一减少独立 profile 的入围数量或局部轮数，并重新冻结版本及核算上限。不能在运行中让晚处理的图少拿候选，也不能删掉统一单核、100 图正式配置覆盖或全部核心机制对照来声称“完成 8 小时”。预算紧张时优先完成合法 V1 全覆盖，V2 是否全量执行由冻结后的可达性预测决定；关闭 V2 或减少候选时，结论和结果记录同步标明实际执行协议，不继续使用未运行的算法名称。

### 9.7 状态保存和四天安排

内存只保留当前 worker 正在处理的图与必要展开状态。V1 持久化候选计划、评分摘要、至多 8 个容量/Cache 锚点、官方结果与名额状态；不把几千个 prepared 对象长期留在内存，也不为所有候选保存一套重复的完整图。V2 需要新计划的 profile 时正常调用并计费。轻量状态可从原图和计划恢复，恢复耗时记入相应工作项。

| 日期顺序 | 主要交付 | 必要依赖 |
|---|---|---|
| 第一天 | 静态特征、方案编码、官方入口接入、机制小检查和计时 | 先确认有效结果与成本，再冻结并发和候选预算 |
| 第二天 | 四起点、统一单核及 V1 全量第一槽 | 所有计划与实际状态先保存 |
| 第三天 | V2 有界改进、C FIFO 代理和第二槽比较 | 使用冻结 V1 基准，不另建热启动历史 |
| 第四天 | 核心对照、少量参数点、全部表格与论文图 | 只汇总已有官方结果，核对统计口径 |

四天是组织窗口，累计正式实验墙钟仍按式（25）—（29）核算，不能把每天各自的 8 小时叠加成预算。

## 10. 论文怎样讲

### 10.1 模型名称与章节主线

论文工作名称采用“**驻留域约束下的多核划分与 FIFO Cache 感知调度**”。正文先解释三个真实决策和官方计时，再给出统一模型；随后依次讨论 A 的 Task 粒度、B 的核心驻留与顺序、C 的查询事件和两服务池。算法部分按候选生成、筛选、官方比较展开，不把初始化、局部改进和 Cache 拆成互不相关的三套方法。

最重要的论证顺序是：同一张量为什么不能按普通边数重复收费；A 与 B 的源写出规则为何不同；B 的结构字节不变时为何仍可通过调序改善；Cache 命中为何取决于查询和完成次序；独立 profile 的质量收益是否覆盖新增计算成本。这些问题都能落回式（4）—（5）、式（14）—（21）和对应官方结果。

参数来源也按用途解释。$2K,4K,8K$ 提供随核数线性增长的粗、中、细粒度；H 前 8 个候选中的 R 选择保留关键路径优先；切点的 ±10% 窗口只允许小幅负载偏差来换取较好的边界；局部轮数和候选上限由总成本预算控制。这些是可复现的设计常数，不写成由理论证明的最优超参数。保留它们之前先检查全量运行成本，正式运行中不逐例调参。

### 11.4 输出字段与服务字节的计算

完整结果直接取 `makespan` 和 `data_movement_bytes`，后者读取 `original_graph_copy_bytes`、`scheduled_copy_bytes`、`added_copy_bytes`、`partition_added_copy_bytes`、`spill_added_copy_bytes`。C 读取 `cache_stats.hit_bytes`、`cache_stats.miss_bytes`、`cache_stats.hit_rate`、`cache_events` 和 `per_core_timeline`。

当前构图器生成的结构和 Spill COPY 每次涉及一份 DDR 相关张量，命中只将这次服务转到 Cache。因此，在当前输入与构图条件下，可由官方结果计算

$$
Q_L=\mathrm{cache\_stats.hit\_bytes},\qquad
Q_D=Q^{\mathrm{sched}}-Q_L.
\tag{30}
$$

`per_core_timeline` 中操作的 `memory_path` 用来解释与抽查服务路径。不能把含共享等待的 `duration` 乘以总带宽当作该操作字节数，也不能假装时间线每条操作都带有未输出的 `transfer_bytes`。

简短日志中的 `physical_ddr_bytes` 在字段缺失时会回退到 `scheduled_copy_bytes`，因此不以该日志回退值作为问题 3 的实际 DDR 服务量。式（30）得到的字段由新汇总程序单独命名，原官方字段原样保存。[S5、S10]

### 11.5 实现顺序与完成判据

先实现静态视图、规范化计划和官方入口，使用少量明确小方案核对 §5 与 §8 的字节及等待；随后完成四起点、轻量回放和 profile 摘要，并执行计时。冻结预算后先完成 V1 全量记录，再实现有界局改、C 事件代理及 V2；最后运行冻结的对照和汇总。

每个阶段的完成判据是实际产物：V1 要有全量计划、官方状态和相应结果；V2 要有第二槽用量及真实比较；汇总要能从保存结果重新生成所有表格。官方非法输入、依赖环或执行失败保留错误类别，不吞异常、不填零，也不为了得到“成功”修改配置。

相同组合的候选编号、实际计划和官方输出之间用普通索引关联即可。存储 profile 摘要时记录其计划身份；轻量编辑改变计划后，不能继续把旧摘要当作新方案的真实容量或 Cache 状态。
