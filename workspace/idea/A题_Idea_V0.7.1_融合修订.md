# A题 Idea V0.7.1：驻留域划分与有限候选调度

**题目：**2026 年“华为杯”中国研究生数学建模竞赛 A 题《通用神经网络处理器下的多核调度问题》  
**版本：**V0.7.1，融合修订版  
**日期：**2026-09-24  
**阅读方式：**§1–8 介绍问题、模型与算法，§9–11 给出实验和实现安排，§12 列出来源与进度，§13–14 说明相对 V0.7 的改动及优秀论文的具体借鉴。本文以 V0.7 为底稿，吸收 V0.6 的独立容量探索，并结合 2024 年数模之星论文和 Alpa 补充模型、算法的选择依据。

## 1. 用一段话讲清楚 Idea

切开计算图可以增加并行，也会增加搬运和同步；留在同一核能够复用张量，却可能让 L1/UB 驻留重叠，引发换出和重新读入。我们的主线是：先按张量的生产者和消费者，算清它必须经过哪些“驻留域”；再从独立计算分量、连续支路和关键路径生成少量切图方案，按预计完成时间分核，并通过有限的迁块、拆并和核内调序改善这些方案。问题 1 的驻留域是独立子图 Task，问题 2 改为同核合并 Task，问题 3 继续使用问题 2 的结构，并按 FIFO 查询与完成事件评价共享 Cache。普通候选按轻量评分逐轮改善，容量下降和查询时序改变的候选另有有限的官方展开机会。所有调整最终只写入子图归属、子图分核和同核顺序，由官方多核模拟给出 Makespan；在有限的已评方案中，先选 Makespan 最小者，再以官方额外搬运量破同分。

## 2. 题意、调度决策与瓶颈

### 2.1 输入图与提交方案

输入计算图由操作、张量和操作与张量之间的依赖组成。操作给出 `pipe`、`cycles`，张量给出 `pos`、`size`，其中 `size` 的单位为 bytes。本文把除 `COPY_IN`、`COPY_OUT` 外的操作称为计算操作；原始搬入搬出不参加子图归属决策。[S1，§1.2–1.4、B.3–B.5]

一个方案只输出两个顶层字段：

```json
{
  "node_to_subgraph": {"操作id的十进制字符串": 0},
  "core_schedules": [[0], []]
}
```

上例展示提交字段的格式。具体方案中，`node_to_subgraph` 恰好覆盖全部计算操作；每个非空子图在一个核心的列表中出现一次，列表给出同核顺序，空核用空列表表示。官方评估器根据方案生成操作发射时刻、换出对象、物理张量版本、内部预取和 Cache 替换顺序。

### 2.2 三问的驻留与通信规则

下文用 **A** 表示问题 1，用 **B** 表示问题 2，用 **C** 表示“问题 3 的场景 B 加只读 Cache”。C 沿用 B 的 Task 组织。

| 对比项 | A：问题 1 | B：问题 2 | C：问题 3 |
|---|---|---|---|
| Task 组织 | 一个子图一个 Task | 同一核的所有子图合为一个 Task | 与 B 相同 |
| 同核跨子图数据 | 必须经 DDR 中转 | 可在 L1/UB 驻留，必要时换入换出 | 与 B 相同 |
| 同步条件 | 同核上一 Task 完成后至少等 100 cycles；跨核前驱 Task 完成后至少等 1000 cycles | 目标 COPY_IN 等源 COPY_OUT 完成并再等 500 cycles | 与 B 相同，Cache 命中后仍需满足跨核释放条件 |
| 共享服务资源 | DDR 读写共享 60 bytes/cycle | 同 A | DDR 为 60 bytes/cycle；Cache 读单独共享 250 bytes/cycle |
| Cache 行为 | 无 | 无 | 容量 1048576 bytes，按逻辑 tensor id 查询，FIFO 替换 |

所有场景每核的 L1、UB 容量分别为 524288、131072 bytes。正式结果全部使用当前官方附件的原始 `data/config.txt`。[S1，B.4、D；S2]

官方执行链为：读取并检查方案，重建 Task 和边界 COPY，运行 Step1 生成核内顺序，运行 Step2 插入必要换入换出，运行 Step3 确定 Pipe 顺序及内存复用依赖，最后进行全局共享带宽事件模拟。B/C 还按 `core_schedules` 对 Step1 序列稳定分桶，并检查操作级跨核依赖。[S3–S8]

B/C 的子图列表影响核内操作排列，执行时各 Pipe 按自身顺序和依赖推进，相邻子图的操作可以重叠。A 则以整个 Task 的完成作为下一 Task 的激活条件。B/C 是否发生死锁，需要检查操作级执行依赖中的环。

### 2.3 当前附件的静态结构

以下统计来自当前官方 ZIP 中的 100 个计算图，用例为 `case_001.json` 至 `case_100.json`。附件包括 `README.md`、`code/`、`data/`、`docs/`，来源与统计范围见 §12。[S2]

| 静态量 | 最小值 | 中位数 | 最大值 |
|---|---:|---:|---:|
| 非 COPY 操作数 $n$ | 552 | 3720.5 | 35705 |
| 原始张量数 | 816 | 4590.5 | 40287 |
| 原始操作与张量的关联数 $I$ | 1841 | 11187 | 108272 |
| 计算依赖弱连通分量数 | 1 | 39.5 | 2666 |
| 计算依赖最长路 $L_G$，cycles | 400 | 6140 | 863040 |
| 单个图输入的最大计算扇出 | 1 | 24 | 2666 |
| $Q^{\mathrm{orig}}/(60\max\{W_M,W_V\})$ | 0.000849 | 0.050138 | 0.259988 |

这里 $W_M,W_V$ 分别为两类计算 Pipe 的原始计算周期总和，$Q^{\mathrm{orig}}$ 为原图 COPY 字节总量。统计还确认：原图没有直接连接两个操作的边；每个张量至多有一个计算生产者；计算操作周期均为正；原图 COPY 的 `cycles=0` 是占位值，实际耗时按字节和带宽重算。

对 2、3、4、5 核，都有 16 个用例的计算依赖分量数少于核数。因此，除分量装箱外，还需要在分量内部构造切分起点。`case_016` 含 17995 个计算操作，却只有一个计算依赖分量，尤其需要在拓扑序中的支路和块边界寻找并行机会。

定义静态比值

$$
r_G=\frac{Q^{\mathrm{orig}}}{60\max\{W_M,W_V\}}.
\tag{1}
$$

当 $r_G>1/K$ 时，原始搬运的带宽下界超过最大计算 Pipe 平均分摊到 $K$ 核的下界。当前数据在 2、3 核下没有这种用例；4 核下为 `case_012`；5 核下为 `case_012`、`case_044`。该比值比较两类必要工作量，用于解释图的结构差异和选择代表用例。实际瓶颈还取决于依赖、容量和动态带宽共享，由后续执行结果判断。

## 3. 参考方法及本题的改动

模型和算法的选择从计算对象、执行机制和求解成本三个方面展开。V0.7 中的两篇超图划分论文提供结构参考；本版进一步结合 2024 年数模之星论文的模型取舍经验，以及 Alpa 的分层执行计划设计。来源和原文位置见 §12、§14。

**有向超图与无环划分。**Popp 等的 *Multilevel Acyclic Hypergraph Partitioning* 把一个生产者关联多个消费者的关系写成有向超边，要求块间商图无环，并以拓扑序构造初始划分、在合法边界附近改进划分。[R1，§2、§3.1–3.3] 本题沿用张量与多个消费者的关联表示及无环划分结构，并根据官方构图规则计算搬运：A 按消费 Task 计数，B/C 按消费核心计数，且 B/C 的源核写出会按目标核重复生成。

**少量不同起点与局部更新。**Schlag 等的 *k-way Hypergraph Partitioning via n-Level Recursive Bisection* 在初始划分和局部细化中使用不同起点、受影响超边的增益更新及局部搜索。[R2，§4.3–4.4] 本题借鉴候选多样性和边界更新方式，采用固定数量起点、固定轮数的普通改善链及有限机制探索；探索候选经官方展开后才竞争完整评估名额。

本文方法称为“**驻留域划分与有限候选调度**”。其核心是驻留域搬运计数、结合官方 Pipe 与内存依赖的候选筛选，以及按官方事件规则进行的 FIFO 回放。

### 3.1 为什么这样建立模型

同一个张量可能被多个操作使用，而一份片上副本能服务哪些消费者，取决于 Task 与核心的组织。因此，建模先保留生产者、张量与消费者之间的关系，再将消费者投影到相应驻留域。这样可以在同一对象上连接划分、通信、容量和 Cache。

| 需要描述的关系 | 选择的数学对象 | 选择理由 |
|---|---|---|
| 一个生产者对应多个消费者 | 张量超边与去重消费域 | 直接统计一份张量要进入多少个域，保留共享读取关系 |
| 可提交的划分、分核和顺序 | $X=(g,a,\sigma)$ | 三个分量分别对应真实可调决策，执行时刻由它们共同决定 |
| A 与 B/C 的边界搬运 | 按官方构图规则推导的两套域计数式 | 源写出次数和复用范围随场景变化，公式与硬件语义对应 |
| 驻留重叠与换入换出 | 轻量活跃峰值、官方物理版本和内存依赖 | 峰值定位可改进的区域，展开给出具体搬运与等待 |
| 多核同时访存 | DDR、Cache 两个事件服务池 | 表达带宽竞争、读入完成和后续查询之间的耦合 |
| 最终方案优劣 | Makespan 主目标，额外搬运破同分 | 与题目交付直接对应，减少人为权重的标定工作 |

2024 年冠军 C 题将原公式的求解器比较与温度修正形式比较分开：固定原模型时，四种求解器的拟合指标相近；加入合适的温度关系后，拟合出现明显变化。[H1，物理页 25–28] 对本题的启发是先把重复读取、真实 Spill 和 Cache 事件放进评价，再讨论搜索算法。§5 的域计数与执行递推承担这一建模工作。

### 3.2 为什么选择有限构造与局部编辑

本题的困难集中在“一个提交方案会展开成什么执行过程”。改变子图后，官方程序会重新生成 COPY、物理版本、Pipe 次序与内存依赖，完整模拟还要处理共享带宽。因此，本方案通过有结构差异的起点覆盖主要选择，再把较贵的评价集中到少量候选。

| 选择环节 | 本版做法 | 对应的结构理由 |
|---|---|---|
| 初始解 | 分量装箱与 D/H/R 连续切块 | 分别利用独立分量、支路连续性、关键路径和驻留释放，产生不同的并行与复用布局 |
| 搜索动作 | 迁块、拆并、边界操作迁移、同核调序 | 每类编辑都对应提交中的具体变化，可同时追踪受影响张量 |
| 搜索范围 | 普通改善链加容量、时序探索代表 | 普通链快速取得改善，探索代表覆盖轻量层暂时看不到的收益 |
| 评价层次 | 轻量回放、官方核内展开、完整模拟 | 按成本逐步补充结构代价、真实 Spill 和动态共享服务 |
| 精确求解器的适用性 | 主流程采用上述有限搜索 | 将完整执行改写为统一 MILP 还需表达方案相关的展开、换出和 FIFO 状态；当前官方入口已经提供可直接利用的精确执行语义 |
| 全局元启发式的取舍 | 采用固定起点和有物理含义的局部动作 | 在既定调用预算内，把搜索机会用于可解释的划分与时序变化 |

Alpa 在上层选择图的阶段划分与设备分配，由下层产生执行计划，并通过编译后 profiling 提供时延和内存成本。[R3，§3、§5.1–5.2] 这支持本题将“提交决策”和“执行代价”分层处理。两者的具体求解不同：Alpa 的 DP 面向微批流水线和阶段设备映射，其 ILP 面向算子内分片；本题以完整操作为单位，存在全局带宽共享与 FIFO 事件耦合，采用完整计划的 profile 和模拟来比较候选。

2024 年西安邮电 B 题在不同 AP 场景、不同预测任务中保留不同模型，选择依据来自各自的对照。[H4，物理页 24–25、38] 本题对应的做法是共用提交表示和搜索框架，由 A/B/C 各自的通信与服务规则评分，并通过 §9 的既有对照判断各模块的收益与成本。

## 4. 核心主线与贡献

### 4.1 一个主方法，三种驻留和服务规则

主方法始终按同一条路线工作：

**张量域计数 → 有结构差异的初始划分 → 分核与核内顺序 → 有界编辑 → 官方展开筛选 → 少量官方完整比较。**

这一过程围绕三个问题展开。

第一，按每个张量的生产域和去重消费域计算结构搬运，使同域共享读取得到合并计数，并解释“合并子图”与“迁到同核”在 A/B 中产生的不同作用。

第二，把关键路径、两类计算 Pipe、驻留压力和跨核同步放进同一个候选过程。在普通改善链之外，保留一个容量探索代表，使轻量时间暂未改善、但驻留压力下降的计划也能接受官方展开检查。局部编辑只改提交接口允许的决策。

第三，在问题 3 中把 DDR 与 Cache 当作两个独立服务池，为重复 miss 相关的时序编辑保留展开机会，再用 FIFO 回放和官方结果判断其收益；通过参数化评分分析资源变化如何影响候选选择，并分别报告硬件增益和调度适配增益。

### 4.2 两阶段执行与独立求解单元

后续实现分为 V1、V2 两个执行阶段。

V1 从固定起点取得全量第一槽结果；V2 沿用这批初始化做有限改进，并最多再用一个官方比较槽。两阶段的比较反映相同初始化上的改进效果。

每个 $(G,K,\text{场景})$ 都是独立求解单元，可以直接求解指定核数。单独请求 5 核 C 时，其初始化来自同图、同核数的 B 方案。批量执行按当前组合计费，精确相同的计划与结果可以复用；跨核数方案按各自调用计入预算。

计时后统一确定各组合的候选顺序、轮数、块数和名额，正式运行沿用这一配置。候选集合独立于其他用例的结果、剩余墙钟和瞬时负载；并发数用于调整执行效率。

## 5. 数学模型

### 5.1 变量与可行方案

设 $V$ 为计算操作集合，$n=|V|$；$E_{\mathrm{calc}}$ 为经张量连接得到、按操作对去重的计算依赖。$c_v$ 为操作 $v$ 的计算周期，$q_v\in\{M,V\}$ 为其计算 Pipe。当前数据的 $c_v>0$。

方案记作

$$
X=(g,a,\sigma).
\tag{2}
$$

其中 $g:V\to\mathcal S$ 给出操作所属子图，$\mathcal S$ 只含非空子图；$a:\mathcal S\to\{0,\ldots,K-1\}$ 给出分核；$\sigma_k$ 是核心 $k$ 上所有已分配子图的无重复排列。

块间依赖从实际归属派生：

$$
\mathcal E_X=\{(g(u),g(v)):(u,v)\in E_{\mathrm{calc}},\ g(u)\ne g(v)\}.
\tag{3}
$$

覆盖、唯一性、商图无环和同核依赖顺序属于提交层条件。A 还要求 $\mathcal E_X$ 与同核相邻 Task 顺序边的并图无环；B/C 要在官方核内展开后，检查局部数据/内存边、同 Pipe 相邻边及跨核 COPY 边的并图可执行。[S3–S5、S8]

实现直接维护归属映射、邻接集合和核心列表，在后文定义的构造空间内搜索。正式结果从官方确认可执行的已评方案中选择。

### 5.2 驻留域和边界搬运

计量对象是参与计算的逻辑张量：图输入取原 COPY_IN 后的核内张量，计算结果取计算操作产生的张量；逻辑张量及其原 DDR 副本按同一对象计数。设 $b_t$ 为张量字节数，$C(t)$ 为去重计算消费者；$T_{\mathrm{in}}$ 为无计算生产者但有计算消费者的张量集合，$T_{\mathrm{prod}}$ 为有计算生产者的张量集合，$u(t)$ 为后者唯一的计算生产者。令 $o_t=1$ 表示结果存在原 COPY_OUT，或没有后续计算消费者。

**A 的域是 Task。**定义输入接收域与结果外域

$$
I_A(t)=\{g(v):v\in C(t)\},\qquad
R_A(t)=\{g(v):v\in C(t),\ g(v)\ne g(u(t))\}.
$$

问题 1 的构图器对每个外部消费 Task 插入一次读；源 Task 只写一次，这次写也可同时承担最终输出。因此，不含 Spill 的结构 COPY 总量为

$$
Q_A^0=
\sum_{t\in T_{\mathrm{in}}}b_t|I_A(t)|+
\sum_{t\in T_{\mathrm{prod}}}b_t\left[|R_A(t)|+
\mathbf 1\{|R_A(t)|>0\ \text{或}\ o_t=1\}\right].
\tag{4}
$$

**B/C 的域是核心 Task。**定义

$$
I_B(t)=\{a(g(v)):v\in C(t)\},\qquad
R_B(t)=\{a(g(v)):v\in C(t),\ a(g(v))\ne a(g(u(t)))\}.
$$

当前 B/C 构图器对每个源核与目标核的组合分别生成一对 COPY_OUT/COPY_IN，最终输出另生成 COPY_OUT。因此

$$
Q_B^0=Q_C^0=
\sum_{t\in T_{\mathrm{in}}}b_t|I_B(t)|+
\sum_{t\in T_{\mathrm{prod}}}b_t\bigl[2|R_B(t)|+o_t\bigr].
\tag{5}
$$

式（4）与式（5）均按去重后的消费域计数。A 的源 Task 写出一次，B 的源核心则为每个远端接收核分别写出；这一差别来自两个官方构图器。[S3，`_build_scene_a_tasks`；S4/S5，`_build_scene_b_tasks`]

当 B/C 只调整子图边界或同核顺序、不改变操作分核时，式（5）不变，但官方核内顺序、Spill、Pipe 等待及 Cache 事件仍可能改变。这正是“搬运量不变，Makespan 仍可变化”的结构原因。

### 5.3 换入换出与报告字段

$Q^{\mathrm{orig}}$ 按原图逐个 COPY_IN 的输出字节和 COPY_OUT 的输入字节相加。对 Step2 产生的每次恢复记录 $e$，$b_e$ 为恢复大小，$z_e=1$ 表示此次换出需要新写 DDR，否则使用已有持久副本。于是

$$
Q^{\mathrm{spill}}=\sum_e b_e(1+z_e),\qquad
Q^{\mathrm{sched}}=Q^0+Q^{\mathrm{spill}},\qquad
Q^{\mathrm{add}}=Q^{\mathrm{sched}}-Q^{\mathrm{orig}}.
\tag{6}
$$

三个量分别对应官方 `spill_added_copy_bytes`、`scheduled_copy_bytes`、`added_copy_bytes`。`partition_added_copy_bytes` 为 $Q^0-Q^{\mathrm{orig}}$。`cross_task_traffic` 另按其跨 Task 范围统计。

问题 3 的官方搬运字段在 Cache 模拟前生成。对同一 $X$，结构 COPY 与 Step2 插入的 COPY 保持不变，Cache 决定各次读入由哪个服务池承担。因此，C 的正式表格保留官方 `added_copy_bytes`，并以 $Q_D,Q_L$ 分别记录实际进入 DDR 和 Cache 读池的服务字节。[S4/S5，构图器及结果汇总]

### 5.4 硬容量与官方执行目标

给定 $X$，官方核内展开生成扩展操作集合 $\mathcal O_X$、物理张量版本、Pipe 顺序和内存复用依赖。物理版本 $\tilde t$ 在 $A_{\tilde t}$ 申请存储，在全部读者完成后的 $L_{\tilde t}$ 释放。令 $C_{L1}=524288$、$C_{UB}=131072$，必要的硬容量条件为

$$
\sum_{\tilde t:\,A_{\tilde t}\le \tau<L_{\tilde t}}
 b_{\tilde t}\,
\mathbf 1\{\mathrm{core}(\tilde t)=k,\mathrm{pos}(\tilde t)=m\}
\le C_m,
\quad m\in\{L1,UB\}.
\tag{7}
$$

存储释放要等待全部读者完成，其中也包括输出 COPY_OUT。Step2 处理固定访问序上的容量不足；Step3 把容量复用形成的 WAR/WAW 关系写入执行依赖。理想活跃峰值超过容量的候选仍可保留：峰值用于定位驻留压力，具体换出对象和搬运字节由 Step2 确定。[S6/S7]

设 $S_o,D_o$ 为扩展操作开始、完成时刻，$F_r(X)=\max_oD_o$ 为场景 $r$ 的 Makespan。A 的 Task $s$ 的激活时刻满足

$$
B_s\ge\max\left\{
0,\ \max_{t\in\mathrm{Pred}(s)} E_t,\
\max_{t\in\mathrm{Pred}(s):a(t)\ne a(s)}(E_t+1000),\
E_{p(s)}+100
\right\},
\tag{8}
$$

其中 $E_t$ 为 Task 完成时刻，$p(s)$ 为同核前一个 Task；不存在的项省略，首个根 Task 不额外加 100。B/C 则对每条跨核拷贝连接要求

$$
S_{\mathrm{COPY\_IN}}\ge D_{\mathrm{COPY\_OUT}}+500.
\tag{9}
$$

大小为 $b_e$ 的搬运进入带宽为 $B_p$ 的服务池时，独占参考工作量按官方规则取

$$
w_{e,p}=\max\{1,\lceil b_e/B_p\rceil\}.
$$

该池有 $m_p(\tau)$ 个在途搬运时，各搬运剩余独占工作量 $R_e$ 按

$$
\frac{dR_e}{d\tau}=-\frac{1}{m_p(\tau)}
\tag{10}
$$

更新，并沿用官方完成时刻取整。DDR 与 Cache 读各自按式（10）维护服务池，完整事件推进共同决定全局 Makespan。

真实优化目标为

$$
\min_{X\ \text{可执行}}\bigl(F_r(X),Q^{\mathrm{add}}(X)\bigr)
\quad\text{按字典序比较。}
\tag{11}
$$

后续程序在固定候选预算内，按式（11）选择已评集合中的最好方案。时间、服务池状态和物理版本均由官方执行递推产生。

### 5.5 下界及其用途

令 $L_G$ 为原计算依赖的最长加权路径，$W_q=\sum_{v:q_v=q}c_v$，并令

$$
Q_{\min}=\sum_{t\in T_{\mathrm{in}}}b_t+
\sum_{t\in T_{\mathrm{prod}}}o_tb_t.
$$

在当前输入结构和初始空 Cache 下，每个输入至少发生首次 DDR 读取，最终输出也要写回。因此三种配置共用必要下界

$$
LB_K=\max\left\{L_G,\frac{W_M}{K},\frac{W_V}{K},\frac{Q_{\min}}{60}\right\}.
\tag{12}
$$

对已完成 C 评估的方案，还可用实际池字节检验

$$
F_C(X)\ge
\max\left\{L_G,\frac{W_M}{K},\frac{W_V}{K},\frac{Q_D}{60},\frac{Q_L}{250}\right\}.
$$

下界用于解释依赖限制、检查单位，并通过 $F_r/LB_K$ 描述方案与必要下界的距离；$T_1/LB_K$ 给出乐观加速比上界。方案选择仍使用式（11）。

有限搜索也有计算复杂度方面的依据：在广义 B 输入中，令两个核只执行互不相依的 M 操作，操作周期为正整数 $w_i$，则最小 Makespan 包含把 $w_i$ 分成两组、使最大组和最小的 Partition 子问题。该归约说明广义 B 优化问题至少弱 NP 难。

## 6. 可执行的求解过程

### 6.1 一次预处理和三种构造顺序

每张图只解析一次，保存计算邻接、张量生产者、去重消费者、原 COPY 端点、弱连通分量、各 Pipe 工作量、式（1）和式（12）所需静态量。域计数存入字典，键为张量和域，值为消费者数量；只有数量由 0 变 1 或由 1 变 0 时，接收域集合基数才改变。

反向关键路径为

$$
h(v)=c_v+\max_{v\to u}h(u),
\tag{13}
$$

无后继时最大项为 0。**H 序**在就绪集合中按 $(-h(v),v)$ 选择操作。

**R 序**先取 H 优先级最高的至多 8 个就绪操作，再在其中按“本步释放输入字节减去新增活跃输出字节、$h(v)$、较小操作 id”依次选优。这里的释放用于构造计算序，只统计当前计算消费者关系；完整候选的容量扫描和官方展开还会计入 COPY_OUT 等读者。这一选择先关注关键路径，再在优先级接近的操作中寻找释放机会。

**D 序**用于提供与 H 不同的连续支路布局：弱连通分量按 $(-\max\{W_M,W_V\},\min v)$ 排列；每个分量内部按固定 id 顺序访问根和后继，使用迭代 DFS 的逆后序得到拓扑序，再连接各分量。该顺序倾向于连续安排支路操作，支路之间的依赖仍由原图保留。

分量少于核数时，D/H/R 的连续切块仍可在单分量中提供不同粒度的划分。每次新增边界都重新计算域计数和搬运。

### 6.2 四个固定起点

| 起点 | 划分办法 | 分核和顺序 |
|---|---|---|
| A0 / B0 | 全图一个子图 | 放核心 0，其余核为空 |
| A1 / B1 | 完整计算分量逐个装箱；同箱分量合成一个子图 | 最多 $K$ 个非空子图，每核一个 |
| A2 | D 序连续切成最多 $2K$ 块 | 按块拓扑序逐块试放 |
| A3 | H 序连续切成最多 $4K$ 块 | 按块拓扑序逐块试放 |
| B2 | H 序连续切成最多 $4K$ 块 | 按块拓扑序逐块试放 |
| B3 | R 序连续切成最多 $8K$ 块 | 按块拓扑序逐块试放 |

块数均不超过 $n$，不存在空块。A1/B1 的装箱先最小化放置后全核最大 M/V 负载，再比较新增输入接收域字节，最后按核心号破同分。

连续切块时，设尚余 $b$ 个块、剩余两类计算量为 $M_r,V_r$，目标尺度取 $\max(M_r,V_r)/b$。在目标的 $[0.9,1.1]$ 倍窗口内，优先选择穿过切点的去重张量字节较少的位置，再比较计算量偏差与位置；窗口为空时取最近合法位置，最后一块吸收余项。每个张量按生产者及消费者在序列上的最左、最右位置形成一个区间，区间差分可计算各切点的穿越字节。切点指标用于选择初始边界，完整方案的搬运仍按式（4）–（5）计量。切点扫描计入起点生成成本。

连续拓扑块具有无环商图：原依赖沿序列向后，因此块间边也沿块编号递增。后续拆分或合并改变了归属，需要重新检查商图。

细分块按全局块拓扑序处理。每次分别试放到 $K$ 个核心列表末尾，用 §6.3 的轻量回放计算已放置前缀的完成时间和搬运增量，选最优位置；未来未放置块的影响在放置后重新计算。每个完整起点最后再做一次完整轻量回放。起点构造耗时包括 A1/B1 的分量装箱、细分起点的逐核试放及完整轻量回放。

### 6.3 轻量层：构造参考执行时间

轻量层根据当前 $g,a,\sigma$ 构造参考执行骨架：保留计算操作与原依赖，按式（4）或式（5）产生虚拟边界 COPY；核内计算使用构造顺序并按提交子图列表排列；输入 COPY 紧邻其首次消费者之前，输出 COPY 在生产者之后，并在各 Pipe 上建立固定相邻顺序。涉及多个 COPY 时按逻辑张量 id 破同分。这一层省去 Step2，以理想活跃字节描述容量压力。

对该骨架加入 A 的 Task 激活边，或 B/C 的跨核 COPY 释放边。参考 DAG 上每个操作的完成时间递推为

$$
\widehat D_o=d_o+
\max_{p\in\mathrm{Pred}_{\mathrm{ref}}(o)}
\bigl(\widehat D_p+\delta_{p,o}\bigr),
\tag{14}
$$

其中 $d_o$ 为计算周期或 COPY 独占参考周期，$\delta_{p,o}$ 为适用的 100、1000、500 cycles 延迟，其余边为 0；根节点前驱最大值为 0。A 为每个 Task 增加零时长起止节点，以表达式（8）的最大值关系。B/C 按操作级依赖连接各子图。

记 $H_{\mathrm{light}}=\max_o\widehat D_o$，$W_D^{\mathrm{light}}$ 为骨架中所有 DDR COPY 的独占工作量之和。沿骨架访问序计算不换出的理想活跃字节，并定义

$$
\Pi(X)=\sum_{k,m}
\left[\max_j\mathrm{Live}_{k,m}(j)-C_m\right]_+.
\tag{15}
$$

$\Pi$ 衡量理想活跃峰值超过容量的字节数，用于定位容量压力。A 在不同 Task 之间清空驻留，B/C 则在同核合并序上扫描。A/B 的轻量数值评分为

$$
\ell_{A/B}(X)=
\left(\max\{H_{\mathrm{light}},W_D^{\mathrm{light}}\},\ Q^0,\ \Pi\right).
\tag{16}
$$

元组按字典序比较，各字段保留自己的单位。普通改善链根据该元组更新；容量探索的独立准入见 §6.5。轻量骨架有环的候选在筛选阶段淘汰，官方执行合法性由后续检查判定。C 的轻量服务池评分见 §7.3。

### 6.4 官方展开层：使用实际产生的顺序和换入换出

本文把一次**完整计划的官方核内展开**称为 profile。A 调用官方 `_build_scene_a_tasks`；B/C 调用各自文件的 `_build_scene_b_tasks`，取得 Task、扩展图、`seq`、`pipe_ops`、内存依赖和搬运汇总。A 构图器已执行 `validate_task_order`；B/C 还调用官方 `validate_execution(tasks, cross_links)`。

有两个实现细节直接影响算法和预算。

其一，`prepare_step3_execution` 内部会调用 `step3_simulation`，因此 profile 的成本包括 Step1–3 的完整执行。

其二，`spill_records` 是构图器内部的临时记录，prepared 返回对象提供的是扩展操作与汇总结果。容量反馈从这些操作中读取 `spill_logical_tid`、`transfer_bytes`、恢复后的物理张量及其消费者，结合官方汇总量定位大额 Reload，直接使用现有官方接口。[S3–S7]

从 profile 构造参考 DAG，使用官方局部数据/内存依赖、实际 Pipe 相邻顺序，再加入对应场景的 Task 或跨核释放边。按式（14）得到最长路 $H^0$，令 $W_D^0$ 为这些真实扩展 COPY 的 DDR 独占工作量。A/B 的 profile 数值评分为

$$
p_{A/B}(X)=
\left(J_{A/B},Q^{\mathrm{sched}},Q^{\mathrm{spill}}\right),
\qquad J_{A/B}=\max\{H^0,W_D^0\}.
\tag{17}
$$

$H^0$ 包含局部 Pipe 工作与依赖，$W_D^0$ 描述全局共享资源工作量，两者取最大值。这一层加入真实 Spill 和内存依赖；动态共享带宽对后续就绪时刻的影响留给完整模拟。

计划在进入任何评分之前规范化一次：按子图内最小操作 id 给非空子图确定编号，同时同步改写核心列表；之后 profile、完整评估和输出都使用这份实际编号。核心编号保持原样；去重按规范化提交、图标识、场景、核数、配置及当前官方代码版本组成的键判断。

### 6.5 有界编辑：生成、接受、更新和停止

规模档只由当前图的非 COPY 操作数决定。

| 规模 | 范围 | 轻量轮数 $R$ | 每轮实例化候选上限 A / B / C |
|---|---|---:|---:|
| 小 | $n\le2000$ | 3 | 64 / 48 / 64 |
| 中 | $2000<n\le10000$ | 2 | 48 / 36 / 48 |
| 大 | $n>10000$ | 1 | 32 / 24 / 32 |

当前 100 图在三档中分别为 41、40、19 个。每个 A/B 组合在全部轮次结束后最多新增两个局部 profile；C 的 profile 总上限另见 §7.3。

编辑只保留四类：整块迁核；相邻块合并或沿现有拓扑序拆分；边界操作隔离后迁移；同核块前移或后移。A 优先整块和切点，单操作新 Task 每轮最多 8 个，并且该操作必须关联较大的跨域字节、关键路径或容量压力；B/C 一次编辑至多隔离两个操作。编辑后的子图数上限为 $\min(n,8K+16)$。

每类编辑的落点也固定。整块迁移先列出其生产者/消费者所在的不同核心，再补一个计算负载最低的其他核；目标列表只试满足同核依赖的最早、最晚插入位置，重合时只试一次。合并只取同核列表中相邻的两个块；拆分只在锚点前后最近的非空拓扑切点进行，拆出的块先相邻留在原核。隔离操作时，剩余操作按原块的拓扑位置保留为前后连续段；单操作或至多两个操作形成的待迁块，再使用上述迁移落点。同核调序只试相关生产块之后、消费块之前及容量峰值关联块两侧的位置。四类编辑共用本轮候选总上限。

锚点按用途确定：域边界取跨域关联字节最大的至多 32 个操作；路径锚点取高 $h(v)$ 的相关边界；容量锚点取当前 profile 中最大的至多 8 个带 Spill 标记的恢复操作，没有匹配 profile 时使用当前轻量序中最大的活跃峰值。候选先用轻量编辑描述排序，四类编辑轮流取一个，某类耗尽就跳过；同类按关联字节、路径值、操作 id、目标核心及插入位置破同分。达到表中上限即停止实例化。

每个实例化候选执行以下过程：应用编辑，规范化计划，检查提交层约束和块数，更新所有受影响张量的生产域及消费域，重放轻量时间与容量，再与当前状态比较。迁移一个操作时，更新范围包括它的全部输入、输出和共享消费者。

**普通改善链。**每轮在合法、轻量骨架无环的候选中，选择数值评分严格优于当前状态的最佳者作为下一轮状态；完全相等不更新。接受后立即更新域、核心列表、参考时间和容量峰值。Spill 锚点仅在其 profile 的计划身份与当前状态一致时使用，其他状态按自身轻量容量峰值定位。跨轮保留轻量元组最小的已接受状态 $X_{\mathrm{ord}}$，计划键只破候选间同分。

**容量探索。**在同一批完成合法性检查与轻量回放的候选中，另行保留满足 $\Pi(X)<\Pi(X_0)$ 的计划。轻量主时间或 $Q^0$ 暂时变差的候选也可进入这一集合。按容量下降量 $\Pi(X_0)-\Pi(X)$ 降序，再按轻量元组和计划键升序，选出代表 $X_{\mathrm{cap}}$。比较基准始终是冻结的 $X_0$，容量值来自候选自身的回放。容量代表进入待展开集合，后续轮次仍从普通链状态继续生成候选。

A/B 的两个局部 profile 名额分别留给 $X_{\mathrm{cap}}$ 和 $X_{\mathrm{ord}}$。先登记容量代表，再登记普通代表；同一计划同时满足两类时只展开一次并保留两类来源标记。某类为空或两者重合时不另造候选补足；与起点 profile 精确相同时复用已有摘要。失败展开消耗所用名额且不另选替代者。两个代表均按式（17）与初始化比较，只有 profile 数值严格改善者才按 §6.6 竞争第二槽。这让容量候选获得实际 Spill 与内存依赖的评价机会。

达到固定轮数、某轮无普通严格改善、候选耗尽或块数限制后结束轻量链，再处理已经保留的探索代表。每个 A/B 组合跨全部轮次仍至多新增两个局部 profile；探索不增加表中的候选实例数、轮数或官方调用。C 的局部代表与聚合、分散共同使用 §7.3 的三个新 profile 名额。

### 6.6 两个完整评估槽怎样使用

设 $\mathcal P_0$ 为四个起点中去重、profile 成功的集合。第一槽计划固定为

$$
X_0=\arg\min_{X\in\mathcal P_0}(p_{A/B}(X),\mathrm{key}(X)).
\tag{18}
$$

V1 对 $X_0$ 做完整官方评估并保存。V2 沿用这个 $X_0$ 作为初始状态。

第二槽候选池包括：尚未与第一槽正式比较的其他成功起点，以及 profile 数值评分严格优于 $X_0$ 的普通或容量局部代表。去重后按同一个 profile 元组选最好者 $Y$。不同起点与局部代表按同一规则排序。只有池为空时才省略第二槽；容量探索的准入本身不增加完整评估名额。

每个组合的完整调用上限始终为 2。第一槽失败时，第二槽优先用于尚未正式评估、profile 成功的 A0/B0；不存在这种计划时使用成功候选中的下一名。修复计入第二槽。第一槽修复可先于全量 V1 结束完成，修复用掉第二槽后，V2 不再对该组合追加完整调用。所有起点 profile 都失败时，可在第一槽直接提交 A0/B0 给官方入口诊断，并以该入口返回的状态记录结果。

最终仅在成功的官方结果中按式（11）选优。完整评估比第一槽更慢时仍保留第一槽；两次均失败时，保存失败状态与原因，该用例的正式数值保持缺失；汇总保留该用例及题面规定的统计分母。

### 6.7 复杂度与伪代码

设 $t$ 为张量数，$I$ 为操作与张量的关联数，$S$ 为当前子图数，$N_X,E_X$ 为官方展开后的操作和依赖规模。静态邻接与域视图为 $O(n+t+I)$；H/R 的堆式就绪选择为 $O((n+I)\log n)$，D 序为线性遍历。切点扫描和逐核试放单独计入起点构造：最多 $S$ 个切块阶段、$SK$ 次前缀试放，每次试放最坏仍需一次参考骨架回放。

一项完整轻量候选的保守上界为

$$
O(n+t+I+S^2),
$$

其中 $S^2$ 覆盖最坏块间关系处理。域差量可减少实际更新工作，完整候选仍需执行合法性检查和时间重放。每个 A/B 组合最多执行 $Rq$ 次局部轻量回放；$q$ 为规模表对应上限。C 另有最多 16 次聚合/分散内部试放。

一次 profile 的代价记为 $P_r(G,X)$，包括所有 Task 的官方构图和 Step1–3。随后在已展开图上计算最长路和扫描容量反馈，另需 $O(N_X+E_X)$ 的工作；官方展开成本仍以 $P_r$ 计量。C 的事件代理排序为 $O(N_{\mathrm{in}}\log N_{\mathrm{in}})$，$N_{\mathrm{in}}$ 为展开后的 COPY_IN 数。

```text
solve_AB_v1(G, K, scene):
    static = get_or_build_static(G)
    seeds = build_four_seeds(static, K, scene)
    for each distinct normalized seed:
        light_replay(seed)
        profile(seed) with official construction and applicable checks
    X0 = best successful seed by profile numeric tuple, then exact plan key
    evaluate X0 in official slot 1
    if slot 1 fails:
        use at most slot 2 for the defined valid-seed repair
    save X0, successful seed profiles, official results, slot usage

refine_AB_v2(saved_v1):
    if no successful initialization or both slots already consumed: stop
    current = frozen X0
    Xord, Xcap = bounded_rounds(
        current, ordinary=strict_light_improvement,
        capacity=best_pressure_drop_from_all_instantiated_candidates)
    profile distinct(Xcap, Xord) at most once each, including failed attempts
    pool = untested alternative seeds + eligible improving local profiles
    if pool nonempty: evaluate best(pool) in remaining slot 2
    return best successful official result by (makespan, added_copy_bytes)

solve_C_v1(G, K, saved_B_v1):
    XB0 = successful B V1 result at exactly this G and K
    if that B unit has never run: build and charge it once
    if the B unit exhausted its slots without success: record dependency failure and stop
    build C base profile for XB0; obtain FIFO proxy
    evaluate XB0 under default Cache in C slot 1
    save the frozen baseline and its C result

refine_C_v2(saved_C_v1):
    aggregate = bounded_aggregate_path(frozen_baseline, at_most_8_trials)
    disperse = bounded_disperse_path(frozen_baseline, at_most_8_trials)
    Xord, Xcap, Xtime = bounded_local_rounds(frozen_baseline)
    local = first_available(Xtime, Xcap, Xord)
    profile distinct(local, aggregate, disperse), at most three new C states
    if a valid state strictly improves the base C profile tuple:
        evaluate the best such state in C slot 2
    retain the best successful C result; do not replace frozen XB0
```

伪代码中的名额是实际调用上限，失败与去重的处理同正文。官方完整入口重新构图的成本见 §9 和 §11。

## 7. 问题 1、2、3 如何递进

### 7.1 问题 1：切开以后值不值得

A 的关键决策是 Task 粒度。一次拆分会同时改变输入接收域、结果外域、同核 Task 间的 100 cycles、跨核前驱的 1000 cycles，以及各 Task 内的容量压力。因此，A 的第一类机会是把独立分量分开执行，第二类机会是在连续支路或关键路径附近切出确有并行机会的块，第三类机会才是利用拆分改善过大的核内工作集。

A1 用粗粒度分量装箱减少 Task 数；A2/A3 用不同拓扑序和粒度提供更细的并行机会。普通局部链按轻量元组改善，容量探索则保留一个待官方展开判断的新边界。同核调序会保留子图边界 COPY；将相应张量的生产、消费操作合入同一个 Task，才能消除这类搬运。

第一槽和第二槽的官方比较用于分析拆分的净收益：并行缩短了哪些路径，增加的搬运、同步和容量变化又带来了多少开销。

### 7.2 问题 2：从 Task 边界转向核心驻留和顺序

B 在同核子图间保留核内数据，因此沿用 A 的构造框架，用式（5）计量边界 COPY，用式（9）表达跨核等待，并在同核合并访问序上扫描容量。

此时两个操作即使分属不同子图，只要在同核就有复用机会；反之，把共享输入的消费者迁到另一核，会增加新的输入接收域。B2/B3 通过多个子图的提交顺序影响官方稳定分桶；同核子图共同构成一个核心 Task。

容量编辑重点是把一个大张量的末次消费者提前，或将另一大张量的生产推迟，缩短两者驻留区间的重叠。依赖决定能否移动，新的 `spill_added_copy_bytes` 和扩展操作决定真实 Reload 是否减少。§6.5 的容量代表可在轻量时间暂时变差时进入 profile，B3 的 R 序则提供另一个容量导向起点。H/R 用于构造，最终操作顺序仍由官方展开产生。

### 7.3 问题 3：Cache 改变哪一步选择

#### （1）先固定同方案硬件对照

对同一图和核数，记 V1 中成功的 B 基准计划为 $X_B^0$。C 的第一槽始终评估这个计划，以相同提交结构观察共享 Cache 的作用。V2 可以改进 B 得到 $X_B^*$，也可以从冻结的 $X_B^0$ 生成 C 挑战得到 $X_C^*$，新的 $X_B^*$ 用于分别优化后的对照，C 第一槽继续使用冻结基准。

#### （2）查询与完成时插入的执行规则

当前问题 3 的 `cache_eligible` 按操作类型判断，范围是全部 **COPY_IN**，包括原图输入、跨核搬入和恢复操作。各类 COPY_IN 在发射时具有有效逻辑键且传输字节为正时，均参与 Cache 查询和命中统计。键由核内张量的 `logical_tid` 取得；没有这个字段时使用其 tensor id。[S5，`copy_tensor_info`、`cache_eligible`、`issue`]

查询发生在发射时。命中进入 Cache 读池，并保持原有 FIFO 插入次序；未命中进入 DDR 池。每次 miss 独立服务：同一逻辑张量在首次插入之前被两个核心同时查询，两次都可以 miss。跨核 COPY_IN 无论命中与否，都要先满足 500 cycles 的释放条件。

`retire` 在**每个 COPY_IN 完成**时调用 `insert_cache`。该函数在键仍存在时直接返回，在键已不存在且大小可容纳时按 FIFO 规则重新插入。于是，命中读在途期间若原条目被其他插入淘汰，它完成时也可能把这个键重新插入队尾。条目尚在时，其 FIFO 次序保持不变。Cache 填充由 COPY_IN 完成触发，COPY_OUT 负责写回 DDR；大小超过 Cache 容量的对象保持未缓存状态。[S5，`insert_cache`、`retire`]

#### （3）轻量层分开两个资源池

对图输入 $t$，令 $r_t=|I_B(t)|$，$C_L=1048576$。轻量层使用“首读 DDR、其余接收核读 Cache”的乐观输入复用假设：

$$
(d_t,\ell_t)=
\begin{cases}
(0,0),&r_t=0,\\
\bigl(\lceil b_t/60\rceil,(r_t-1)\lceil b_t/250\rceil\bigr),
 &r_t\ge1,\ 0<b_t\le C_L,\\
\bigl(r_t\max\{1,\lceil b_t/60\rceil\},0\bigr),&\text{其他情况}.
\end{cases}
\tag{19}
$$

首个参考查询按轻量到达时刻、核心号、稳定顺序确定。其他边界搬运在这一层先按 DDR 工作量 $O_D$ 计；完整 profile 再判断中间搬入与 Reload 的 Cache 可能性。令

$$
W_D^{\mathrm{light}}=\sum_t d_t+O_D,\qquad
W_L^{\mathrm{light}}=\sum_t\ell_t,
$$

并用相应参考 COPY 时长重算式（14），得到 $H_{\mathrm{light},C}$。C 的轻量元组为

$$
\ell_C(X)=\left(
\max\{H_{\mathrm{light},C},W_D^{\mathrm{light}},W_L^{\mathrm{light}}\},\
W_D^{\mathrm{light}}+W_L^{\mathrm{light}},\ \Pi
\right).
\tag{20}
$$

主时间取参考路径与两个池工作量的最大值，池工作量总和用于次级比较。式（19）采用乐观输入复用假设；首次插入前的并发 miss 和后续淘汰由 FIFO profile 与完整模拟处理，该式用于轻量排序，完整系统下界采用 §5.5 的计算口径。

#### （4）聚合、分散与顺序调整

**聚合路径。**共享图输入按“字节数乘以不同消费块数”降序、张量 id 升序排列；其消费块按 $\max\{W_M,W_V\}$ 降序、块内最小操作 id 升序排列。目标取该输入的计算消费者总周期最多的核心，同分取核心号小者；跳过已在该核的块。每次只移动一块，依次试满足同核依赖的最早、最晚插入位置，重合时只试一次。

**分散路径。**从含至少两个共享图输入消费操作的块中，按 $\max\{W_M,W_V\}$ 降序、块内最小操作 id 升序选择。将全局 H 序限制到当前块，复用 §6.2 的连续切点规则，目标块数固定为 2：在半数剩余计算量的 $[0.9,1.1]$ 倍窗口内比较穿越张量字节、计算量偏差与位置，窗口为空取最近合法切点，得到唯一的非空前段和后段。先试前段、再试后段；其他核心按当前 $\max\{W_{k,M},W_{k,V}\}$ 升序、核心号升序排列，各自依次试最早、最晚合法插入位置。分散迁移使至少一个共享输入新增接收核心，同时在原接收核保留该输入的消费者。

两条路径各自从冻结 $X_B^0$ 出发，按上述顺序逐项实例化并做完整轻量回放，接受第一个严格改善当前轻量元组的合法候选，再按新状态重建编辑顺序。每条路径累计最多实例化 8 次，无效尝试也占次数；相同规范化计划只回放一次。所有受影响的输入、输出域和容量均重算，遍历与去重也计时。候选耗尽或用完次数即停止，最后一个已接受状态为该路径代表；未接受任何编辑则代表为空。

**顺序与边界局改。**仍使用 §6.5 的轮数、四类编辑和每轮总上限，同时保留普通代表 $X_{\mathrm{ord}}$、容量代表 $X_{\mathrm{cap}}$ 和时序探索代表 $X_{\mathrm{time}}$。容量代表按自身 $\Pi$ 与冻结基准比较，压力下降即可获得独立候选资格。时序锚点来自已完成的 C 第一槽官方 `cache_events`：对至少出现两次 miss 的逻辑张量，按首次 miss 之后的 miss 字节总和降序、逻辑 id 升序，取至多 8 个。第一槽失败或没有有效记录时，时序锚点为空；既有容量和普通规则仍可使用。基准 miss 用于定位编辑对象，编辑后的访问情况由新计划评估。

在原有四类编辑轮流取候选的规则内，同核调序类在原有名额内先处理时序锚点，再处理容量等锚点。对合法且轻量骨架无环的实例化计划，若它相对冻结基准改变至少一个时序锚点的参考 COPY_IN 查询时刻、MTE2 相对次序或跨核释放依赖，即获得时序探索资格，**轻量评分暂时变差的计划也可入选**。按受影响锚点的基准重复 miss 字节总和降序，再按轻量元组和计划键升序，选 $X_{\mathrm{time}}$。探索代表进入待展开集合；普通链继续按严格改善规则更新，沿用原有轮数。

局改只占一个新 profile 名额，优先取 $X_{\mathrm{time}}$，为空则取 $X_{\mathrm{cap}}$，再为空才取 $X_{\mathrm{ord}}$。按“局改、聚合、分散”的顺序登记三个代表；相同计划只展开一次并保留全部来源标记，与基准相同时复用已有摘要。空缺或重复的名额保持闲置，失败展开消耗对应名额后结束该次尝试。这样最多产生三个新 C profile，加上基准总计不超过四个。时序代表展开后记录官方 MTE2 次序、释放依赖或参考查询时间是否发生改变；错峰归因以这一变化记录为依据。所有代表仍须通过式（21）的改善条件才能竞争第二槽，最终提交只包含划分、分核和顺序。

#### （5）一次 FIFO 事件代理与一次重加权

对每个 C profile，先在其真实扩展依赖及 Pipe 序上假设 COPY 使用 DDR 独占参考时长，计算一遍查询、完成参考时间。固定这份事件流，先处理同刻完成，再处理同刻查询，并按官方核心号、Pipe 顺序和稳定次序破同分。对全部符合条件的 COPY_IN 回放上述 FIFO 规则，包括完成时重新插入的路径，得到预计命中集合 $\hat h$。

随后只进行一次时长重加权：预计命中的 COPY_IN 改用 Cache 参考时长，其余 COPY 仍按 DDR；重新求参考最长路 $H_C^{(1)}$。记 $W_D(\hat h),W_L(\hat h)$ 为两个池的预计独占工作量，$\hat Q_D$ 为预计 DDR 服务字节，$\hat Q_H$ 为预计命中字节，定义

$$
p_C(X)=\left(
\max\{H_C^{(1)},W_D(\hat h),W_L(\hat h)\},\
\hat Q_D/60,\ -\hat Q_H,\ Q^{\mathrm{spill}}
\right).
\tag{21}
$$

回放与重加权各执行一次。重加权后事件顺序可能改变，因此 $\hat h$ 用于筛选，真实命中由官方完整模拟确定。第二槽只评估 profile 数值元组严格优于冻结 C 基准的最佳挑战；没有符合条件的挑战就保留第一槽。

### 7.4 三类加速比及对应对照

对每个图、每个核数，分别计算

$$
S^{\mathrm{hw}}=\frac{F_B(X_B^0)}{F_C(X_B^0)},\qquad
S^{\mathrm{adapt}}=\frac{F_C(X_B^0)}{F_C(X_C^*)},\qquad
S^{\mathrm{opt}}=\frac{F_B(X_B^*)}{F_C(X_C^*)}.
\tag{22}
$$

第一项是同方案硬件对照；第二项是启用 Cache 后的方案适配收益；第三项是两种配置分别优化后的方案对照。前两项相乘的分子仍是 $F_B(X_B^0)$，不一定等于第三项。三条口径均由主矩阵中的已有结果计算。

正式无 L2 使用 B 入口，正式 Cache 使用 C 入口的原始配置。容量为 0 的 C 入口用于小范围配对核对，B 正式结果统一来自 B 入口。

### 7.5 资源变化如何改变方案排序

固定计划的参数诊断衡量硬件响应，比较不同结构在参数变化下的评分则解释方案选择。下面直接使用式（19）至式（20），给出可复算的参考子系统：一个 60000 bytes 的共享输入、五个互不依赖的 V 操作，每个计算 100 cycles，$K=5$；暂不纳入输出搬运和其他依赖。

把五个操作聚合到同一核，只读一次 DDR，参考路径为 $1000+5\times100$，因此

$$
J_{\mathrm{agg}}^{\mathrm{light}}=1500.
\tag{22a}
$$

分散到五核，每核一个操作。Cache 能容纳该输入时，沿用轻量层一次 DDR、四次 Cache 的假设。令 $d_L=\lceil60000/B_L\rceil$，参考最长路为 $\max\{1100,d_L+100\}$，两池工作量分别为 1000 和 $4d_L$，故

$$
J_{\mathrm{disp}}^{\mathrm{light}}
=\max\{1100,d_L+100,1000,4d_L\}
=\max\{1100,4d_L\}.
\tag{22b}
$$

| Cache 带宽 $B_L$，bytes/cycle | 单次 Cache 工作量 $d_L$ | 聚合主评分 | 分散主评分 | 轻量层优先方案 |
|---|---:|---:|---:|---|
| 125 | 480 | 1500 | 1920 | 聚合 |
| 250 | 240 | 1500 | 1100 | 分散 |
| 500 | 120 | 1500 | 1100 | 分散 |

容量小于 60000 bytes 时，分散方案的五次读都计入 DDR，主评分为 5000，聚合仍为 1500，排序重新偏向聚合。这说明资源参数能够改变模型中的结构选择：带宽增大可支持更多接收核，容量不足则削弱共享输入分散的价值。

表中数值是轻量模型在乐观输入复用假设下的参考评分。实际查询同时发生时，分散方案可能出现五次 miss。分核与合法调序决定实际查询关系，FIFO profile 和完整评估分别给出事件代理与正式结果。实际硬件响应由 §9.3 既定的固定计划参数点诊断。

## 8. 说明性手算：同一张小图贯穿切分、分核与 Cache

本节通过结构字节、计算路径和隔离读入子系统的手算，说明划分、分核与查询时序的作用；整图 Makespan 由官方共享带宽模拟计算。

### 8.1 小图、操作与容量

图输入 $x$ 为 60000 bytes，位于 UB。操作 $p$ 使用 $x$，计算 1000 cycles，产生 30000 bytes 的 $z$；操作 $a,b$ 均使用 $x,z$，各计算 800 cycles，分别产生 6000 bytes 的最终结果 $y_a,y_b$。三个操作都使用 V Pipe。依赖为

```text
x ──→ p ──→ z ──→ a ──→ ya ──→ DDR
│            └──→ b ──→ yb ──→ DDR
├────────────────→ a
└────────────────→ b
```

每个操作自身的输入与输出总量均小于 UB 容量。例如 $a$ 的合计为 $60000+30000+6000=96000$ bytes。原始 COPY 总量为

$$
Q^{\mathrm{orig}}=60000+6000+6000=72000\ \text{bytes}.
$$

### 8.2 同核放置与子图合并的搬运差异

比较以下方案的**不含 Spill 的结构字节**。

| 方案 | A 的 $Q_A^0$ | B 的 $Q_B^0$ | 变化来自哪里 |
|---|---:|---:|---|
| 全图一个子图，核心 0 | 72000 | 72000 | 输入一次、最终输出两次 |
| 三个子图 $\{p\},\{a\},\{b\}$，全在核心 0 | 282000 | 72000 | A 仍有三个输入消费 Task 和两个外部消费 Task；B 为一个核心域 |
| 三个子图分别在三个核心 | 282000 | 312000 | B 对 $z$ 的两个目标核分别生成写读对 |
| 子图不合并，但把 $a,b$ 放同一核心，$p$ 留另一核心 | 282000 | 192000 | B 的输入接收域和 $z$ 目标核都减少一个 |
| 进一步把 $a,b$ 合成一个子图 | 192000 | 192000 | A 此时才减少消费 Task；B 的结构计数不再变化 |

以“三个子图分别在三个核心”为例，A 的费用为

$$
\underbrace{3\times60000}_{x\text{ 的三次读}}+
\underbrace{30000+2\times30000}_{z\text{ 的一次写、两次读}}+
\underbrace{2\times6000}_{\text{最终输出}}
=282000.
$$

B 的费用为

$$
3\times60000+
\underbrace{2\times(30000+30000)}_{z\text{ 的两个跨核写读对}}+
2\times6000=312000.
$$

将 $b$ 迁到 $a$ 所在核后，B 变为

$$
2\times60000+(30000+30000)+2\times6000=192000.
$$

一次迁核减少 120000 bytes，新增搬运由 $312000-72000=240000$ 降为 $192000-72000=120000$ bytes。这正是局部迁核需要重新计算所有相关张量域的原因。

但两个分支原本可以在两个核并行，迁到同核后要竞争同一条 V Pipe。只看计算，分支并行的依赖路径为 $1000+800=1800$ cycles，同核三项计算总量为 $2600$ cycles；只看上述 B 结构字节，DDR 独占工作量分别为 $312000/60=5200$ 与 $192000/60=3200$ cycles。候选评分同时比较这两类变化，最终 Makespan 由完整评估确定。

### 8.3 A 的等待项和 B 的驻留项

单看 $p\to a$ 这条链、暂不计 COPY，同一 Task 内计算路径为 $1000+800=1800$ cycles。A 切成同核两个 Task 后，参考路径至少为 $1000+100+800=1900$；放到不同核后至少为 $1000+1000+800=2800$。真实方案还需要加上相应 COPY 及共享带宽影响。B 的释放条件落在具体源 COPY_OUT 上，完成后再等待 500 cycles。

容量编辑可用另一个局部状态说明：某核先后产生两个各 81920 bytes 的 UB 输出，如果前一个尚未完成末次使用，理想活跃峰值为 163840，超出容量 32768 bytes。若第一个张量可被换出且没有 DDR 副本，对它完整写回并恢复的字节为 $2\times81920=163840$；这里的 32768 bytes 是容量超额量，换出则以完整张量计费。若已有副本，恢复可只新增 81920 bytes。将末次消费者合法前移，有机会消除重叠；即使轻量时间略增，容量代表仍可接受 profile 检查，真实换出量由该展开确定。

### 8.4 查询时间为什么重要

回到 60000 bytes 的 $x$。隔离观察三个核心的读入，不放入其他传输：单次 DDR 独占工作量为 1000 cycles，单次 Cache 读为 240 cycles。

若三次查询都在初始时刻发射，Cache 为空，三次都 miss；三个相等读公平共享 DDR，在这个隔离子系统里各于 3000 cycles 完成。若第一读在 0 时刻发射并于 1000 完成插入，另两次查询恰好在此后发射且没有淘汰，它们都 hit，两个 240 cycles 的 Cache 工作共享带宽，经过 480 cycles，于 1480 完成。

3000 和 1480 对应上述给定查询时刻的读入子系统。实际方案通过合法的块顺序、依赖和分核间接改变查询时刻，提交接口提供的控制量仍是划分、分核和顺序。§7.3 的时序探索让已有重复 miss 线索的合法编辑有机会进入 FIFO profile，即使乐观轻量评分暂时看不出收益；完整评估再判断实际访问关系。

最后用默认容量说明完成时插入的特殊路径。设三个逻辑张量 $x',y',z'$ 各为 400000 bytes，FIFO 当前为 $[x',y']$。一次 $x'$ 命中读开始后顺序不变；若另一次 $z'$ 搬入先完成，插入 $z'$ 会淘汰 $x'$，队列变为 $[y',z']$；随后在途 $x'$ 命中读完成，当前代码发现键已不存在，会插入 $x'$ 并淘汰 $y'$，队列变为 $[z',x']$。这个例子说明，后续命中预测需要处理全部 COPY_IN 的完成插入，包括在途命中读完成后的重新插入。

### 9.2 必须完成的正式矩阵与统计

100 个用例各取得一次官方统一单核基准 $T_{1,i}$。A 正式多核方案覆盖 2至5 核；B 覆盖 1至5 核，其中 1 核是问题 3 的无 L2 比较所需；C 覆盖 1至5 核，同一冻结 B 计划在 Cache 下的结果和至多一个 C 挑战都归入主矩阵。

$$
\overline S_{r,K}=\frac{1}{100}\sum_{i=1}^{100}
\frac{T_{1,i}}{F_{r,i,K}},\quad r\in\{A,B\},\ K=2,3,4,5;
\qquad \overline S_{r,1}=1.
\tag{23}
$$

问题 3 逐例报告 B/C 的 Makespan、官方额外搬运量和 Cache 命中率，并对式（22）分别求逐例比值的算术平均。Cache 命中率按 `hit_bytes/(hit_bytes+miss_bytes)`，没有访问时沿用官方值；B 的 Cache 列标为“不适用”。另用 C 的操作服务路径统计 $Q_D,Q_L$，解释命中收益是否真正缓解了 DDR 等待。

每个正式组合同时保存 V1 首槽、最终选择、第二槽是否改善、真实增益、失败状态和额外运行时间。第二槽记录一个互斥的主来源：替代起点、普通编辑、容量探索、C 聚合、C 分散或时序探索；同时保存可并存的机制标记。重复计划以最先登记该计划的名额作为主来源，其他身份仅补标记，避免一次收益重复计数。第一槽到最终槽的差异表示“相同 V1 初始化上的有限改进收益”；替代起点与局部搜索的收益按各自主来源统计。

### 9.6 8 小时墙钟如何判断可达

总目标为 28800 s，预留 3600 s 给环境准备、汇总和必要返工，工作阶段预算为 25200 s。V1 覆盖、V2 改进、控制与诊断的初始设计配额分别为 10800、9000、5400 s；这些设计配额将在计时后校准。

对阶段 $s$，把互斥计算时间记为

$$
W_s=\sum_j\left(
 t_{\mathrm{seed},j}+t_{\mathrm{light},j}+t_{\mathrm{profile},j}+
 t_{\mathrm{official},j}+t_{\mathrm{FIFOproxy},j}+t_{\mathrm{IO},j}
\right).
\tag{25}
$$

静态解析每张图一次，另记在串行准备或所在 worker 的首次成本中。$t_{\mathrm{official}}$ 已包含该完整入口内部的构图、Step1 至 Step3 与全局模拟；$t_{\mathrm{profile}}$ 只计额外的独立展开；$t_{\mathrm{FIFOproxy}}$ 计本文新增的参考事件回放，官方 Cache 模拟时间计入完整入口。

设系统与主进程占用为 $M_0$，内存预留为 $M_{\mathrm{res}}$，本阶段单 worker 最大增量 RSS 为 $m_s$，实际可用的进程并发上限为 $p_{\mathrm{hw}}$，则

$$
p_{\mathrm{eff},s}=\min\left\{p_{\mathrm{hw}},
\left\lfloor\frac{48\,\mathrm{GiB}-M_0-M_{\mathrm{res}}}{m_s}\right\rfloor\right\}.
\tag{26}
$$

上述参数通过串行与少量并发计时取得，并为系统、主进程和必要余量保留内存。若计算出的并发数为 0，先减少同时保留的展开图，再复测单 worker 的内存可行性。

实际墙钟近似受总工作与最长依赖链共同约束：

$$
\widehat T_{\mathrm{wall}}=
T_{\mathrm{prepare}}+T_{\mathrm{summary}}+
\sum_s\left[T_{\mathrm{serial},s}+
\max\left\{\frac{W_s}{p_{\mathrm{eff},s}},\ T_{\mathrm{chain},s}\right\}\right].
\tag{27}
$$

$T_{\mathrm{chain},s}$ 包括同图、同核数 B 初始化之后才能开始的 C 基准和挑战，该链作为独立时间约束保留。任务规模不均和并发争用会使近似出现偏差，后续用分规模实际完成时间校正预测。

将全部伴随工作按 3074 个完整调用折算，25200 s 工作预算要求平均综合处理量满足

$$
\bar t_{\mathrm{combined}}\le
\frac{25200\,p_{\mathrm{eff}}}{3074}
\approx8.198\,p_{\mathrm{eff}}\quad\text{s/完整调用}.
\tag{28}
$$

例如有效并发为 2、4 时，阈值约为 16.40、32.79 s。这一综合处理时间包括独立 profile、候选处理和结果写入的摊销。

单独请求 C 的成本也明确包含同核数的 B 初始化：

$$
T_{C,\mathrm{cold}}(G,K)=
T_{B,\mathrm{V1}}(G,K)+T_{C,\mathrm{base}}(G,K)+
T_{C,\mathrm{refine}}(G,K)+T_{\mathrm{cold\ start}}.
\tag{29}
$$

第一项计入本次求解成本；存在完全相同、可复用的 B V1 记录时扣除。题面的单例约 5至10 分钟是效率建议，与总墙钟预算一并检查。

若计时预测超过预算，先移除候选诊断和非默认参数诊断，再统一减少独立 profile 的入围数量或局部轮数，并重新冻结版本及核算上限。候选协议在正式运行前统一冻结，对相同规模的图使用相同候选上限；统一单核、100 图正式配置覆盖和核心机制对照继续列为交付内容。预算紧张时优先完成合法 V1 全覆盖，V2 是否全量执行由冻结后的可达性预测决定；关闭 V2 或减少候选时，算法名称、结论和结果记录同步标明实际执行协议。

### 11.4 输出字段与服务字节的计算

完整结果直接取 `makespan` 和 `data_movement_bytes`，后者读取 `original_graph_copy_bytes`、`scheduled_copy_bytes`、`added_copy_bytes`、`partition_added_copy_bytes`、`spill_added_copy_bytes`。C 读取 `cache_stats.hit_bytes`、`cache_stats.miss_bytes`、`cache_stats.hit_rate`、`cache_events` 和 `per_core_timeline`。

当前构图器生成的结构和 Spill COPY 每次涉及一份 DDR 相关张量，命中只将这次服务转到 Cache。因此，在当前输入与构图条件下，可由官方结果计算

$$
Q_L=\mathrm{cache\_stats.hit\_bytes},\qquad
Q_D=Q^{\mathrm{sched}}-Q_L.
\tag{30}
$$

`per_core_timeline` 中操作的 `memory_path` 用来解释与抽查服务路径。`duration` 包含共享等待，单次操作字节数依据张量大小计算；时间线记录中没有逐操作的 `transfer_bytes` 字段。

简短日志中的 `physical_ddr_bytes` 在字段缺失时会回退到 `scheduled_copy_bytes`，该回退值表示调度 COPY 总量；问题 3 的实际 DDR 服务量由式（30）计算。式（30）得到的字段由新汇总程序单独命名，原官方字段原样保存。[S5、S10]

### 11.5 实现顺序与完成判据

先实现静态视图、规范化计划和官方入口，使用少量明确小方案核对 §5 与 §8 的字节及等待；随后完成四起点、轻量回放和 profile 摘要，并执行计时。冻结预算后先完成 V1 全量记录，再实现有界局改、C 事件代理及 V2；最后运行冻结的对照和汇总。

### 14.3 借鉴如何落实到当前方案

这些参考主要增强了 V0.7.1 的模型选择解释和验证设计。驻留域搬运式来自当前官方构图规则；容量独立探索吸收自 V0.6；Cache 时序入口和资源排序手算由本次对 V0.7 的逻辑核对形成。优秀论文帮助组织“为什么这样建、怎样比较、用什么结果作决定”，各项技术来源因此可以分别追溯。

参考取舍仍由数学结构决定。例如，H3 在给定风速和总功率、采用其既定简化系数后，功率分配目标为线性目标配合总和及上下界约束；这类结构可以直接采用线性规划或排序分配。该文采用 GA 的事实提示我们先识别结构，再选择算法。本题则包含划分、分核、顺序与共享资源事件，有限结构搜索能直接使用官方执行链，因而保留这一主线。

Alpa 的 DP 依赖其阶段流水线时间模型，ILP 处理的是算子内分片选择。本题的操作保持完整，张量搬运、Spill 和 Cache 由提交方案展开产生。这里吸收的是上下层代价反馈的组织方式，具体搜索仍按本题三种场景的执行规则设计。
