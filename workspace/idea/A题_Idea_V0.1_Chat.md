# A题 Idea V0.1｜张量计数驱动的拓扑分块与驻留感知调度

**题目：2026 年“华为杯”中国研究生数学建模竞赛 A 题《通用神经网络处理器下的多核调度问题》**  
**版本标识：ChatGPT6.0 Pro 独立构思版；2026-09-23。**  
**阶段：Idea。** 本文给出模型、求解步骤、三问递进关系、后续实验预算和实现蓝图。正文中“拟建”“后续运行”对应尚未实施的算法与实验。公式中的时间均以 cycles 计，数据量均以 bytes 计，KiB、MiB 分别表示 $2^{10}$、$2^{20}$ bytes。

## 1. 用一段人话讲清楚这条思路

这道题不是把计算量平均分给几个核就结束了。同一份数据交给几个任务读取、一个中间结果跨几次任务边界、一个大张量在核内等多久，都会改变实际搬运；搬运集中发生时，又会挤占共享 DDR。我们的做法是：先从原图建立“一个张量对应一个生产者和一组消费者”的数据关系，沿合法拓扑序组成大小适中的子图；分核时同时看 Cube、Vector 两条计算流水线，而不是只看操作数量；排顺序时让已经占着 L1/UB 的数据尽快被用完，减少无谓换入换出。先用这些结构信息生成少量完整方案，后续再根据官方时间线找到真正拖慢结束时间的任务边界、跨核读取或长驻留张量，只修改相关的小段。问题 3 进一步调整合法的子图先后次序，让重复读取尽量落在首次读取完成之后、FIFO 淘汰之前。所有修改最终都落实到题目允许提交的两个 JSON 字段，不增加预取指令、手工发射时间或自定缓存策略。

这条主线称为**张量计数驱动的拓扑分块与驻留感知调度**。它的重点不是增加搜索次数，而是让每次修改都对应一笔可以解释的通信代价、一段等待，或一段可以缩短的驻留时间。

### 2.2 决策边界

输入图包含操作节点、张量节点和有向依赖。真正提交的决策是操作到子图的映射、子图到核心的分配，以及每个核心上的子图顺序。输出必须且只能包含：

```json
{
  "node_to_subgraph": {"非COPY操作id": 0},
  "core_schedules": [[0], []]
}
```

上面只是字段示意，不是本包任何用例的完整方案。操作 id 应按真实输入输出为十进制字符串，映射必须恰好覆盖所有需要分配的操作；每个子图只能出现一次。子图数不等于核数，也不要求每个核心非空。[题面 §1.3、附录 B.5；附件 `derive_multicore_plan`]

官方程序还会重建边界搬运，执行 Step1、Step2、Step3，再进行多核事件模拟。因此，操作发射时间、内部张量的物理版本、换出对象、每条 Pipe 的最终顺序和 Cache 命中，都是提交方案经过官方程序后得到的量，不是独立可写入的决策。

### 2.3 三问的差别不只是通信系数不同

**问题 1：任务边界本身要付费。** 一个子图就是一个 Task。跨子图数据一律经 DDR，即使两个子图在同一个核心。除搬运外，同核前一个 Task 完成后需等待 100 cycles；跨核前驱 Task 完成后需等待 1000 cycles。Task 激活取相关约束的最大值，而不是把所有前驱等待相加。[题面附录 D.2]

**问题 2：同核驻留取代同核边界搬运。** 一个核心上的所有子图合成一个 Task。同核子图切得更细不会因此增加 100 cycles 的 Task 切换等待，也不会自动插入同核边界 COPY。但是，`core_schedules` 会影响合并 Task 的确定性操作顺序，进而影响数据驻留、换出与 Pipe 队首等待。跨核读取等待的是对应源 `COPY_OUT` 完成再加 500 cycles，不是整个源核心完成。[题面附录 C.1、D.2；附件问题 2 评估器]

**问题 3：改变读取路径，且路径由事件时序决定。** Cache 的 250 bytes/cycle 带宽与 DDR 的 60 bytes/cycle 带宽独立，不能把所有搬运统一按 310 bytes/cycle 计算。COPY_OUT 仍走 DDR；COPY_IN 发射时才判断命中，命中不刷新 FIFO 排序。多核同时首次读取同一张量，首次读取尚未完成时，后发射的读取仍可能未命中。[题面附录 D.5；附件问题 3 评估器]

固定配置为 L1=524288、UB=131072、DDR 带宽=60、Cache 容量=1048576、Cache 带宽=250。正式结果始终使用上传包原始 `data/config.txt`。[题面附录 B.4]

### 2.4 五类相互影响的代价

**边界搬运与共享读取。** 一条逻辑数据依赖是否产生 COPY，取决于 Task 或核心归属。多个消费者在同一接收单位内，只需要重建一次输入搬运；把同一输入的消费者分散到更多单位，就增加重复读取。具体写出次数在 A、B 中还不同，见第 5 节。

**双 Pipe 负载与依赖。** Cube、Vector 可以并行，但仅当数据与内存条件允许。因此，单核计算工作量至少要用二维向量表示，还要保留关键依赖路径。两个互不依赖的 4000-cycle 操作分别使用 Cube、Vector，与两个都使用 Cube 的操作不是同一种负载。[题面 §1.2、算法优化方向]

**驻留跨度与换入换出。** 一个 64 KiB 张量被生产后，跨过很多无关子图才再次使用，会长时间占用核内空间。真正有用的量是“某个时刻同时活着多少数据”和“数据两次使用之间隔了多远”，而不是全图张量大小之和。当前操作的输出申请完成时，末次使用的输入尚未释放，瞬态峰值必须同时包含二者。[附件 `schedule_step2.py`]

**同步等待与尾部关键任务。** 相同搬运总量，落在非关键分支与落在最后一条未完成分支上，对 Makespan 的影响不同。对 A，合并能减少 Task 激活边界；对 B，应优先看跨核数据释放和 Pipe 队首被阻塞，而不是机械合并所有重边两端。

**DDR 争用与 FIFO 到达顺序。** 相同通信量也可能形成不同的搬运波峰。问题 3 中更要区分“其他核已经读过”和“其他核已经读完并插入 Cache”。FIFO 复用还取决于期间插入了哪些张量，不能用 LRU 的最近访问距离代替。[题面附录 D；附件问题 3 评估器]

原图能直接给出张量尺寸、生产消费关系、计算 Pipe、固定计算周期和原始 COPY 字节数。划分及顺序确定后，才能计算重复读取单位数、边界写出次数和候选驻留区间。正式的换出记录、执行合法性、共享带宽下的结束时间及 Cache 命中，则以官方展开和事件模拟为准。

## 3. 参考方法，以及本题怎样改

本节只保留五份有实际用途的原文。前两份研究论文提供结构工具，三份上传作品提供建模与求解组织方式；原作中的物理模型不迁入本题。

### 3.1 有向超图：一份张量对应一组消费者

Popp 等的《Multilevel Acyclic Hypergraph Partitioning》在 §2 使用超边连接相关节点，以触及分块数构造 connectivity 代价，并约束商图无环；§3.1 给出基于拓扑序的初始划分。[R1]

**原文机制 → 适用前提 → 本题变量 → 改动：** 当数据由多个操作共享时，以一条超边而不是多条独立通信边记账；本题对应逻辑张量 $t$、消费者集合 $C(t)$ 和触及 Task/核心的集合。本题不直接使用原文的 $(\lambda-1)b_t$ 作为完整通信量，而是根据两种官方边界构造分别计算读、写次数，再加原始 I/O 和换入换出。原文的均衡权重改为 Cube、Vector 两类周期；不引入其整套多层种群搜索。

### 3.2 无环划分：用可维护的拓扑位置约束修改

Özkaya、Çatalyürek 的《A Simple and Elegant Mathematical Formulation for the Acyclic DAG Partitioning Problem》在 §4 利用分块商图可以拓扑排序的性质，让跨块依赖只朝拓扑编号增大的方向。[R2]

**原文机制 → 适用前提 → 本题变量 → 改动：** 对需要无环的子图商图，维护子图拓扑位置 $\rho(s)$，新边仍从小位置指向大位置时，不会引入商图环。本题用它构造连续拓扑块，并限制合并、切分和重排；核心编号不充当拓扑位置，也不要求核心间通信图无环。原文的整数规划不是本题整图求解器。

### 3.3 2024 冠军作品：先改遗漏的机制，再换优化器

山东大学张良收、赵佳、王硕的《基于多因素分析与深度学习的磁芯损耗建模》在 §5.2.4 比较同一基础方程的不同参数寻优方法，在 §5.2.5 把温度因素写入方程后再比较。其 PDF 第 25 页的表 5.2、5.3，以及第 26 页开始的修正方程，形成了“保持模型换求解器”和“改变模型再求解”的区分。该队 2024 年“数模之星”冠军身份由山东大学校方材料确认。[R3；R3a]

### 3.4 一等奖及答辩提名作品：把容易保持的约束放进解的表示

西北农林科技大学杨磊、林炅、刘冠麟的《风电场有功功率分配优化模型》在 §6.5.4 把功率分配转为权重变量，§6.6.1 在生成新解后进行归一化及越界筛除；PDF 第 33 页的算法步骤明确保留了后续边界检查。其一等奖及“数模之星”答辩提名由校方材料确认。[R4；R4a]

### 3.5 浙江大学参考作品：维护局部状态，避免反复从头计算

许诺、孟旭瑶、刘相万的《风电场有功功率优化分配》在 §3.3.2—3.3.3 用滑动时间窗和前一时刻的状态组织计算，同时比较时间与误差；PDF 第 14 页图 5 展示了逐窗口更新流程。[R5]

**迁移方式：** 本题维护“张量在每个 Task/核心内有几个消费者”的计数，迁移一个子图时只更新关联张量；移动顺序时先重算受影响的局部驻留区间。不过，局部次序改变可能影响后面的内存状态和全局带宽，所以进入官方评估的候选仍完整评估，不把局部估算当全局真值。该上传作品的具体获奖等级未由本轮校方材料核实，本文仅按用户提供的参考作品使用。

上述迁移只覆盖原文能够支撑的机制。本题的 A/B 多消费者搬运公式、基于官方时间线的有限修改规则，以及 FIFO 读取窗口处理，是结合本届材料提出的设计，不归为历届论文已经给出的结论。

## 4. 主线选择与可落地的贡献

### 4.1 三条完整路线的比较

| 路线 | 输入到输出 | 主要收益与瓶颈 | 三问适配及计算成本 |
|---|---|---|---|
| 静态划分后分核 | 原图 → 张量关联划分 → 按负载列表分核 → 两字段 JSON | 能减少静态通信；遗漏顺序、换出和到达时间 | A/B 可换通信公式，C 很难仅靠静态目标处理；构造便宜，但可能优化了错误的次要量 |
| **拓扑分块、驻留感知构造、时间线定点修改** | 原图 → 两个有限构造候选 → 代理筛选 → 官方初评 → 小段修改 → 官方择优 | 同时处理通信计数、双 Pipe、驻留与关键等待；需要一次真实时间线判断修改位置 | 三问共享结构，改变 Task 组织和读取路径；默认每组合一次初评，至多一次额外定点评估 |
| 对提交方案反复做全图黑盒搜索 | 原图 → 大量划分/分核/排列 → 每个都官方模拟 → 最优已评估 JSON | 直接针对真目标，但大部分时间消耗在低价值候选上 | 三问可直接切换评估器；难覆盖全包全核数并把总墙钟控制在 8 小时 |

选择第二条。第一条保留为简化对照，第三条不作为主算法。不引入全图强化学习训练、种群演化或通用黑盒优化平台。

### 4.2 三个具体贡献判断

**第一，决定“哪些消费者放一起”，而不是只决定“哪条边不切”。** 同一张量在一个接收核心内有多个消费者时，迁走其中一个消费者不一定减少任何搬运；必须改变被触及的核心集合。按张量计数可以识别真正减少读写的迁移。必要对照是在相同构造流程中改成逐边累计通信。

**第二，决定“数据何时用完”，而不是把同核复用一概视为免费。** 同核复用减少边界 COPY，但长时间占位可能挤出其他数据。顺序修改优先缩短导致换出的驻留间隔；必要对照固定划分和分核，只取消驻留相关的重排。

**第三，问题 3 决定“重复读取何时到达”，而不是把共享输入都预测成命中。** 利用已有独立工作推迟重复输入的首次使用，让其落入实际可命中的窗口；必要对照固定方案比较有无 Cache，再比较分别优化后的方案。它不依赖提交接口之外的空等或预取。

这些是后续可逐项检验的机制判断。算法不是把三个独立优化器串起来，而是用同一套张量和次序状态解释、产生并筛选修改。

## 5. 数学模型：真实目标与求解代理分开

### 5.1 统一符号与解表示

令 $V$ 为需要分配的核内操作集合，$n=|V|$。令 $\mathcal T$ 为与这些操作相关的逻辑片上张量集合，$b_t$ 为张量 $t$ 的大小，$p_t\in\{\mathrm{L1},\mathrm{UB}\}$ 为其存储位置，$C(t)\subseteq V$ 为不同消费者操作组成的集合。本包静态检查未发现一个张量由两个不同核内操作生产，因此对计算结果使用唯一生产者 $u(t)$；无核内生产者且由原始 COPY_IN 搬入者组成输入集合 $\mathcal I$，有核内生产者者组成 $\mathcal P$。

对 $t\in\mathcal P$，记 $f_t=1$ 表示原图具有该张量的最终 COPY_OUT，否则为 0；令 $o_t=1$ 表示 $f_t=1$ 或没有核内消费者，否则为 0。引入 $o_t$ 是为了与官方对终端结果的输出重建一致，不自行删去无下游的计算输出。

操作 $v$ 的给定周期为 $c_v$，实际参考计算时长按代码取 $\bar c_v=\max(1,c_v)$，计算 Pipe 为 $q_v\in\{M,V\}$。$K\in\{1,2,3,4,5\}$ 为核心数。

方案写为

$$
X=(g,a,\pi),
$$

其中 $g(v)$ 是操作 $v$ 的子图，$a(s)$ 是子图 $s$ 的核心，$\pi_k$ 是核心 $k$ 上的子图顺序。$\rho(s)$ 表示子图商图的一种全局拓扑位置，**不是核心编号，也不是执行起始时间**。

用 $h_A(v)=g(v)$ 表示 A 中操作所属 Task；用 $h_B(v)=a(g(v))$ 表示 B/C 中操作所属 Task。它们的差别必须一直保留。

### 5.2 真实优化目标

把固定原图、配置和原始官方代码下的评估映射记为 $\mathcal E_r(G,X)$，其中 $r\in\{A,B,C\}$ 分别对应问题 1、2、3。其返回的 Makespan 为 $F_r(X)$、新增 COPY 字节数为 $Q_r^{\mathrm{add}}(X)$。

$$
\min_{X\in\mathcal F_r} F_r(X).
$$

$\mathcal F_r$ 是能够通过本问题完整官方流程且执行结束的方案集合。同一 Makespan 时，优先新增 COPY 更少的方案，再以确定性的字典序破同分。这里不把加速比、额外搬运与命中率组成任意加权“官方分数”，因为题面只明确 Makespan 为首要目标、搬运和命中率为辅助指标。

后续搜索输出的是**已成功评估候选中的最好方案**。未穷尽所有合法方案，不写全局最优；有限邻域未找到更好候选，也不宣称已达到所有邻域下的局部最优。

### 5.3 张量通信计数：A 与 B 必须分别推导

对输入 $t\in\mathcal I$，定义消费者触及的执行单位集合：

$$
I_r(t)=\{h_r(v):v\in C(t)\},\qquad r\in\{A,B\}.
$$

对计算结果 $t\in\mathcal P$，定义不含生产单位的接收集合及其数量：

$$
R_r(t)=\{h_r(v):v\in C(t),\ h_r(v)\ne h_r(u(t))\},\qquad m_r(t)=|R_r(t)|.
$$

**A 的原始 I/O 与边界 COPY 总量，不含换出：**

$$
Q_A^{\mathrm{part}}(X)
=\sum_{t\in\mathcal I} b_t|I_A(t)|
+\sum_{t\in\mathcal P}b_t\left[m_A(t)+\mathbf 1\{o_t=1\ \lor\ m_A(t)>0\}\right].
$$

理由是：共享输入在每个消费者 Task 搬入一次；计算结果向每个外部消费者 Task 搬入一次；生产 Task 只要需要向外提供结果，就写出一次。当前 A 构造器中，源端写出不随接收 Task 个数重复；最终输出与边界输出满足同一个输出边界条件时，也只构建这一份写出。[附件问题 1 评估器 `_build_scene_a_tasks`]

**B 的原始 I/O 与边界 COPY 总量，不含换出：**

$$
Q_B^{\mathrm{part}}(X)
=\sum_{t\in\mathcal I}b_t|I_B(t)|
+\sum_{t\in\mathcal P}b_t\left[o_t+2m_B(t)\right].
$$

这里的 $2m_B(t)$ 来自当前代码对每个不同目标核心分别建立一对 COPY_OUT/COPY_IN。一个源核心向两个目标核心发送同一结果，会产生两次源端写出和两次目标端读取，而不是一次写出供所有目标共享。最终输出另外构建，因此也不能直接套用 A 的一次写出公式。[附件问题 2 评估器 `_build_scene_b_tasks`，问题 3 同名函数]

这两个公式以本包“单核内生产者、原始 I/O 由 COPY 连接”的实际结构为前提。代码实现应从原始 COPY 关系识别输入、输出，不能根据张量 id 大小或节点出现顺序猜测。

原图搬运量 $Q^{\mathrm{orig}}$ 直接采用原始 COPY 节点对应的字节总量，与官方 `_copy_traffic_bytes` 对齐。设官方换出记录集合为 $\mathcal S_r$，记录 $e$ 的字节数为 $b_e$，是否需要真实写回新 DDR 后备区为 $d_e\in\{0,1\}$，则

$$
Q_r^{\mathrm{spill}}=\sum_{e\in\mathcal S_r} b_e(1+d_e),
$$

$$
Q_r^{\mathrm{add}}=Q_r^{\mathrm{part}}+Q_r^{\mathrm{spill}}-Q^{\mathrm{orig}}.
$$

已有 DDR 后备区时，换出后重新使用只增加读取，不应每次都按“两倍张量大小”统计。当前官方 `cross_task_traffic` 是另一种单向跨单位数据统计，不等于 `scheduled_copy_bytes`，不能拿来直接计算题目要求的新增搬运。

### 5.4 双 Pipe 工作量与依赖约束

对子图 $s$ 定义

$$
W_{s,M}=\sum_{v:g(v)=s,q_v=M}\bar c_v,\qquad
W_{s,V}=\sum_{v:g(v)=s,q_v=V}\bar c_v.
$$

对子图内部操作依赖 DAG，计算只含计算周期的最长路径 $L_s$。一个用于观察计算规模的量为

$$
D_s^{\mathrm{comp}}=\max\{W_{s,M},W_{s,V},L_s\}.
$$

它不是该子图正式时长，因为尚未计入搬运、内存依赖和等待。核负载同样使用 $(W_{k,M},W_{k,V})$，不把 $W_{k,M}+W_{k,V}$ 当成必然串行的时长。

全图计算下界可以写为

$$
\mathrm{LB}_{\mathrm{comp}}(K)
=\max\left\{\frac{\sum_v\bar c_v\mathbf1\{q_v=M\}}K,
\frac{\sum_v\bar c_v\mathbf1\{q_v=V\}}K,
L_G\right\},
$$

其中 $L_G$ 是原图核内计算依赖路径的最大周期和。该下界用于解释串行性和计算负载，不把启发式单核结果当成数学下界，也不据此假定加速比必须小于核数。

### 5.5 容量约束与驻留代价

对一个给定候选的 Task 操作序列 $\sigma$，设张量 $t$ 的首次申请位置为 $\alpha_t$，最后一次使用位置为 $\omega_t$。不考虑换出时，第 $j$ 个操作执行前的理想同时驻留量为

$$
P_p(j;\sigma)=\sum_{t:p_t=p}b_t\mathbf1\{\alpha_t\le j\le\omega_t\}.
$$

闭区间用于保留“当前输出已经申请、末次输入尚未释放”的瞬态峰值。第一次 COPY_IN、生产者，以及必要的输出 COPY 都须纳入序列。仅统计相邻两个子图之间的驻留会漏掉子图内部峰值。

理想驻留超过容量不等于候选非法：官方允许换出与换入。构造时它是产生重排、拆分或迁移候选的信号。进入最终评估后，记 $k(\tilde t)$ 为官方物理张量版本 $\tilde t$ 所在核心，$\mathrm{alloc}_{\tilde t}$、$\mathrm{free}_{\tilde t}$ 分别为其实际申请与释放时刻，按官方生成的依赖保证

$$
\sum_{\tilde t:\ \mathrm{alloc}_{\tilde t}\le\tau<\mathrm{free}_{\tilde t}}
 b_{\tilde t}\mathbf1\{p_{\tilde t}=p,\ k(\tilde t)=k\}\le C_p,
\quad \forall k,p,\tau.
$$

这里 $C_{\mathrm{L1}}=524288$、$C_{\mathrm{UB}}=131072$。此约束由官方展开和内存复用依赖落实，不通过在提交中添加“缓存分配变量”实现。

进一步定义驻留跨度诊断量

$$
A_p(\sigma)=\sum_{t:p_t=p} b_t(\omega_t-\alpha_t+1).
$$

其量纲为 bytes×序列位置，只用于定位“大且久不使用”的张量，不能与 cycles 直接相加。候选打分中的换出代价须转换为搬运周期。

### 5.6 Task 激活、跨核释放及执行合法性

A 中设 $s^-$ 为同核前一 Task，$\operatorname{Pred}(s)$ 为前驱 Task 集合，$T_s^{\mathrm{start}}$、$T_s^{\mathrm{end}}$ 为其实际起止时间，则

$$
T_s^{\mathrm{start}}\ge
\max\left\{0,
T_{s^-}^{\mathrm{end}}+100,
\max_{u\in\operatorname{Pred}(s),a(u)\ne a(s)}(T_u^{\mathrm{end}}+1000),
\max_{u\in\operatorname{Pred}(s),a(u)=a(s)}T_u^{\mathrm{end}}
\right\}.
$$

不存在的前项从最大值中省略。B/C 的每条跨核拷贝链 $\ell$ 则满足

$$
S_{\ell,\mathrm{in}}\ge F_{\ell,\mathrm{out}}+500,
$$

同时还要满足本核前驱、Pipe 队首及内存依赖；因此“加 500”只是就绪条件的一部分。

划分约束要求每个操作恰好属于一个子图，每个子图恰好属于一个核心并在其列表出现一次。商图依赖满足

$$
g(u)\ne g(v),\ u\to v
\ \Longrightarrow\ \rho(g(u))<\rho(g(v)).
$$

A 再检查商图依赖与同核 Task 顺序的并图。B/C 再检查核内数据依赖、Pipe 顺序、内存复用边及跨核 COPY 边组成的操作级图。正常的双向核心通信不等于操作级死锁。最终采用原始 `validate_task_order`、`validate_execution` 及对应评估入口的结果，不另建通用审计系统。[附件 `evaluation_validation.py`]

### 5.7 共享带宽与 Cache 状态

对某个正在 DDR 池中执行的 COPY，官方以独占带宽参考周期表示剩余工作量。其初始值按 `_op_duration` 对 COPY 字节数除带宽向上取整并至少取 1。若时段内在途 DDR 搬运数为 $n_D(\tau)$，剩余工作量 $w_e$ 按

$$
\frac{\mathrm d w_e}{\mathrm d\tau}=-\frac1{n_D(\tau)}
$$

推进；Cache 读池独立采用同一规则。完成与新发射均会改变后续共享比例。因而即使写出一个以总字节除带宽表示的容量下界，也不能把它当成所有操作逐个完成的事件模型。[附件三题评估器]

问题 3 定义 $\mathcal C(\tau)$ 为 FIFO 有序队列。一次具有有效逻辑键且字节数为正的 COPY_IN $e$ 在发射时刻 $S_e$ 查询逻辑键 $\ell(e)$：

$$
H_e=\mathbf1\{\ell(e)\in\mathcal C_e^{\mathrm{query}}\}.
$$

$\mathcal C_e^{\mathrm{query}}$ 表示按照官方事件顺序、处理完同一时刻的完成与插入事件后，发射读取 $e$ 前的队列。不能把它理解为尚未处理同一时刻完成事件的左极限；首次填充恰在该时刻完成时，后续发射已经可以命中。命中进入 Cache 读池，否则进入 DDR 池。命中不把键移动到队尾；未命中时没有对在途同键读取进行合并。完成事件负责按容量执行插入和先进先出淘汰。

当前代码还有两项应明确保留的实现细节。其一，可查询对象是所有满足条件的 COPY_IN，而不只原始共享输入；跨核 COPY_IN 和换入 COPY_IN 也在范围内。正字节访问计入命中率，超过 Cache 容量的张量可以计为未命中，但不会插入。其二，`retire` 对完成的 COPY_IN 都调用 `insert_cache`；键仍在队列中时不改变顺序，若一个先前命中的键在该读取完成前已被淘汰，完成时可以重新插入。候选的 FIFO 回放保留这一细节，而非自行换成标准 LRU 或“只允许 miss 填充”的其他实现。[附件问题 3 评估器 `copy_tensor_info`、`insert_cache`、`retire`、`issue`]

官方命中率为

$$
\mathrm{HitRate}=\frac{\mathrm{hit\_bytes}}
{\mathrm{hit\_bytes}+\mathrm{miss\_bytes}},
$$

分母为零时按官方返回 0。不要改成命中次数比例。

**搬运统计单独处理。** 对同一个方案，B 与 C 的结构展开相同，因此当前代码返回的 `scheduled_copy_bytes`、`added_copy_bytes` 不因 Cache 命中而减少。题面称其为额外 DDR 搬运量，结果表按官方字段原样报告；另加“实际 DDR 路径字节数”诊断列时，将最终时间线的 `(core_id, op_id)` 与该次官方扩展图中的 COPY 关联，按 `memory_path` 为 DDR 的 COPY 实际字节数求和，并写明是独立诊断口径。时间线没有直接给出的字节数从相连张量获取，不能把持续时间乘 60 当成每个并发 COPY 的字节数。不能悄悄用这列替换官方指标。

### 5.8 用于筛选候选的低成本代理

构造阶段不对每个局部选择运行官方模拟。对完整候选，建立一个**临时参考展开**，具体位置规则如下。

先保留块内构造拓扑序，并按当前全局块序串接它们。每份边界 COPY_IN 放在其接收 Task/核心的第一次消费之前；每份边界 COPY_OUT 放在生产者之后，若有多个目标核心则按目标编号排列，随后仍允许各 Pipe 按依赖并行。A 的输入、输出各按第 5.3 节的 Task 规则去重；B/C 按核心规则去重，并保留每个目标核心的独立 COPY 对。新 COPY 的逻辑张量 id 和原操作 id 一起用作稳定的破同分键。

然后在各核投影得到参考序列，对同一 Pipe 的相邻操作连接先后边。A 为每个 Task 增加开始、结束虚拟节点，开始指向其操作、所有操作指向结束，并按第 5.6 节连接带 100/1000 延迟的 Task 边；B/C 只给对应源 COPY_OUT 到目标 COPY_IN 加 500 延迟，不增加子图完成屏障。全部真实数据边同时保留。若临时参考图因新增 Pipe 次序出现环，就把这个候选的代理记为不可用，并改用另一个合法结构候选，而不是在有环图上计算最长路径。

对无环的参考图，COPY 暂用独占带宽参考时长，按前驱结束时刻加边延迟的最大值递推最早开始时刻，得到 $\widehat H_r(X)$。它包含四条 Pipe，而不是把搬入、计算、搬出全部串成一段。这套位置规则是本方代理的确定性约定，不是对官方 Step1 发射次序的重定义。

在这个候选顺序上执行计数式驻留扫描，估计换入换出工作量 $\widehat D_{\mathrm{spill}}$。预先为每个张量建立后续使用位置列表；逐操作先恢复不在片上的所需输入，再为尚未申请的输出申请空间。一次操作处理期间，把该操作的所有输入、输出排除在换出候选之外；容量不足时，选择未来下一次使用最远的驻留张量移出，平局按进入驻留集合的次序确定。已有 DDR 有效副本就只记录释放；没有副本时计入一次写出并把后备状态置为有效。被移出的张量下次使用时计一次换入。处理完当前操作的申请后，再释放最后一次使用的输入；L1、UB 分开维护。

若当前操作的必要输入输出本身无法容纳，扫描返回明确的不可用状态，不填一个零代价。扫描同时保存所估换入、换出对应的逻辑张量、字节数和序列位置，供问题 3 的参考回放使用；不生成官方物理版本图。其顺序可能不同于官方 Step1，故估计量不直接填入结果表，正式换出量仍取原始 Step2。

设所有基础 DDR COPY 的独占参考工作量之和为 $D_{\mathrm{base}}$。用临时展开的参考时间线把区间 $[0,\widehat H_r]$ 划分为 32 个等长区间，宽度为 $\delta=\widehat H_r/32$。对每个区间，累计各 DDR COPY 参考执行区间与其重叠的长度 $U_j$，定义

$$
\Omega_D(X)=\max_j[U_j-\delta]_+.
$$

它表示最拥挤区间超出一个共享 DDR 池服务能力的参考工作量，而不是实际等待时间。完整候选代理为

$$
J_r(X)=\max\{\widehat H_r(X),D_{\mathrm{base}}(X),\max_{k,p\in\{M,V\}}W_{k,p}\}
+\widehat D_{\mathrm{spill}}(X)+\Omega_D(X).
$$

各项都使用 cycles，系数先固定为 1，不做大范围调参。基础搬运只在第一项的最大值中比较，不同时把完整计算时长、完整搬运时长再次相加。换出扫描不重复计入 $\widehat H_r$ 的基础图。

问题 3 初始沿用 B 方案。取得该方案的 Cache 官方时间线后，后续局部候选按第 7 节的固定参考时序 FIFO 回放估计读路径。设 $D_D^{\mathrm{base}}$、$D_L^{\mathrm{base}}$ 分别为基础 COPY 被分到 DDR、Cache 读池后的独占参考工作量，$D_D^{\mathrm{spill}}$、$D_L^{\mathrm{spill}}$ 为所估换出换入在这两个池中的工作量；换出始终属于 DDR。对两个池分别计算 $\Omega_D$、$\Omega_L$，使用

$$
J_C(X)=\max\left\{\widehat H_C(X),D_D^{\mathrm{base}}(X),D_L^{\mathrm{base}}(X),\max_{k,p\in\{M,V\}}W_{k,p}\right\}
+D_D^{\mathrm{spill}}(X)+D_L^{\mathrm{spill}}(X)+\Omega_D(X)+\Omega_L(X).
$$

参考回放只做一次路径判定，再用所判路径更新 COPY 时长和参考最长路径，不循环迭代到某个自称精确的命中结果。这样同时保留两个共享池的总工作量约束，既不忽略 Cache 读池自身的争用，也不把 DDR 与 Cache 带宽合成一个池。上述代理只负责有限候选排序，最终接受依据始终是 $F_r$。

## 6. 可执行的求解过程

### 6.1 先建立一次可复用的图视图

读取图后，建立操作前驱/后继、张量生产者/消费者、操作输入/输出、张量到相关子图的倒排表。保持张量消费者列表，不把一个 2666 消费者输入展开为约 355 万个消费者对。依赖遍历只沿真实生产消费关系进行。

按反向拓扑序计算操作的剩余计算路径：

$$
\operatorname{rank}(v)=\bar c_v+\max_{w\in\operatorname{Succ}(v)}\operatorname{rank}(w),
$$

无后继时最大值取 0。该 rank 只表示计算路径，不预先给每条逻辑边乘一个统一跨核费率。

维护以下状态即可：每个操作的剩余前驱数；每个张量尚未处理的消费者数；当前前沿张量集合；各子图的两类周期与边界张量；每个张量在各 Task/核心中的消费者计数；每核子图列表。使用普通数组、字典、集合和优先队列，不引入额外平台。

### 6.2 生成两个有明确区别的拓扑顺序

**顺序一：关键路径优先。** 用 Kahn 拓扑过程，每次从就绪操作中选择 rank 最大者，相同 rank 按 id 破同分。

**顺序二：关键路径候选中的驻留收尾优先。** 每次只取 rank 最大的前 8 个就绪操作。在当前全局构造前沿，记执行 $v$ 后可以结束最后一次消费的张量总字节数为 $B_{\mathrm{close}}(v)$，其新产生且后面仍需使用的张量总字节数为 $B_{\mathrm{open}}(v)$，它可复用的已在前沿输入字节数为 $B_{\mathrm{reuse}}(v)$。选取

$$
\operatorname{rank}(v)+
\frac{B_{\mathrm{close}}(v)+B_{\mathrm{reuse}}(v)-B_{\mathrm{open}}(v)}{60}
$$

最大的操作。这个前沿是构造次序的结构状态，并非已经在某个真实核心内分配的缓存。它让计算路径相近的分支尽量先用完已有数据，避免一直生产新结果而不收尾。两种顺序都只从就绪集合选点，天然满足操作拓扑依赖。

这两种顺序属于同一构造方法的两个固定种子，不再用不同随机种子重复几十次。初始单核固定基准不采用它们，而使用题目规定的官方整图启发式结果。

### 6.3 从拓扑顺序形成适度大小的子图

设 $W_M,W_V$ 为全图两条计算 Pipe 的周期和，先取

$$
\tau_r=\frac{\max(W_M,W_V)}{b_rK},
\qquad b_A=4,\quad b_B=8.
$$

$\tau_r$ 是构造用的目标计算规模，不是内存容量或任务实际执行时间。B 取更细的目标，是因为子图在同核合为 Task，不增加 A 的 Task 切换费用，可以用较细子图表达顺序。每块最多包含 512 个核内操作，用于约束构造和修改的粒度，不把“512 个操作”解释成硬件限制。

沿顺序扩展当前块，直到两类周期的较大值达到 $\tau_r$，或操作数达到 512，或到达图尾。结束位置并不直接固定：在当前末尾向前最多 8 个非空切点中，计算

$$
\phi(j)=\frac{B_{\mathrm{frontier}}(j)}{60}
+\left|\max(W_{s,M}(j),W_{s,V}(j))-\tau_r\right|
+\frac{\sum_p[\widehat P_{s,p}(j)-C_p]_+}{60}.
$$

$B_{\mathrm{frontier}}(j)$ 是该前缀与后面操作之间仍需传递的不同逻辑张量字节数；同一张量只计一次。$\widehat P_{s,p}(j)$ 是按构造顺序及其临时边界 COPY 得到的理想驻留峰值。选择 $\phi(j)$ 最小的切点，剩余操作留给下一块。每次至少完成一个操作。

这一步的前沿字节项只用于挑选切点，不冒充 A/B 的正式通信公式。完整划分形成后，一律回到第 5.3 节重新计算 Task/核心计数。对于 A，块内最终操作序仍由官方 Step1 决定；对于 B，子图顺序影响官方稳定分桶后的顺序，因此同样不能假定构造顺序就是最终发射顺序。

连续拓扑区间组成的子图商图必然无环：跨区间边只能从先出现的区间指向后出现的区间。这个表示减少了非法候选，但固定一个拓扑序会限制可搜索的划分，所以保留两个结构不同的顺序，而不声称它们包含所有可行划分。

### 6.4 分核：同时比较两条计算 Pipe、输入复用和释放等待

按子图全局拓扑顺序分配，每个子图在 $K$ 个核心中择一并追加到该核列表。对每个候选核心 $k$，临时放入该块，更新二维负载与关联张量计数。

令 $A_{s,k}$ 为该块输入的参考就绪时间。A 按第 5.6 节的 Task 完成及 100/1000 等待约束估计；B 对跨核输入使用生产操作的参考结束时刻、源端 COPY_OUT、500 同步延迟及目标读取，不使用整个源核心的完工时刻。

令 $L_{k,p}$ 为参考日历中 Pipe $p$ 的可用时间，$\widehat W_{s,k,p}$ 为临时新增的该 Pipe 工作量，包含应新增的读写。一个用于选择核心的局部参考完成量为

$$
\widehat E_{s,k}
=\max\left\{A_{s,k}+L_s,
\max_{p\in\{M,V,\mathrm{MTE2},\mathrm{MTE3}\}}
\bigl[\max(A_{s,k},L_{k,p})+\widehat W_{s,k,p}\bigr]\right\}.
$$

这一式在局部选核时把输入就绪概括成一个时间，目的是便宜地比较候选；不将这种概括写成 B 的正式子图屏障。完整方案的临时展开及官方评估均保留操作级依赖。

选核评分取候选加入后的参考最长结束时间、基础 DDR 工作量和两类核负载的最大值，再加入当前驻留前沿造成的正容量超额除以 60。相同得分时依次选新增边界字节更少、驻留超额更小、编号更小的核心。一次选核只更新关联张量，不重新计算整个超图。

**多消费者迁移的关键是计数从 1 到 0 或从 0 到 1。** 对某张量，某核心已经有消费者时，再分配一个消费者不增加该核的首次读取；最后一个消费者离开时，才消除该核的读取。计算结果还要更新源核心改变后对应的跨核目标集合。这比“每迁走一条边都获得通信收益”的估计更准确。

两个种子各得到一个完整方案，用 $J_r$ 选择初始提交候选。另一个保存为明确的备用结构候选，而不是同时展开无上限搜索。

### 6.5 后续首次官方评估：找真正影响结束时间的位置

实现阶段，对初始完整候选调用对应官方入口。成功后记录 Makespan、分块与换出新增字节、每核四条 Pipe 的时间线、跨核传输释放时间；C 另记录 Cache 事件。

定位修改位置时使用三类证据。

**尾部等待。** 从最后完成的操作或 Task 往前查看数据前驱及同 Pipe 前项，优先查看其前面最大的可见空档。A 结合 Task 激活约束区分是前驱未完成还是同核切换；B/C 结合 `cross_core_transfers` 的 release/start 信息识别跨核读取等待。不是把所有空闲都归因于通信。

**换出压力。** 官方 `spill_added_copy_bytes` 较大时，用候选驻留跨度和大张量下一次使用位置定位应调整的区间。需要准确物理生命周期图的少数诊断用例，额外调用原始 Task 构造函数获得扩展图，再与正式操作时间线对齐；这是额外的诊断展开，计入预算。正式结果 JSON 并不自动提供完整 spill_records，不能假装已经能从一个结果字段直接取得它。

**读取波峰及 Cache 冷启动。** 利用 COPY 时间区间、Cache 的 hit/miss/insert 事件与逻辑键，定位重复冷读、FIFO 淘汰前后的重复读取。观测到 COPY 变慢后，再结合其他在途搬运判断 DDR 争用，不能仅看总字节推断。

### 6.6 每轮最多 24 个结构候选，只让一个进入追加评估

按最大三处主要代价位置，每处生成不超过 8 个修改，总数不超过 24。修改只属于以下三类。

**边界合并或拆分。** A 优先尝试全局拓扑顺序相邻且同核的两个块合并；它减少 Task 边界，但可能增加缓存压力。对尾部最长的大块，在其中部 25%—75% 的构造位置内选取至多 4 个前沿字节最小的切点，拆成两个连续块后重新选择核心。合并相邻全局拓扑区间、拆分连续区间都保持商图无环。非相邻块不直接强行合并。

**子图或小组迁移。** 把尾部瓶颈块迁移到其他核心；或针对某个高字节共享张量，把某核心上使用它的全部消费者子图一起迁移。当这个消费者子图组不超过 4 个时，生成一次成组迁移；超过 4 个时不展开组合枚举，而优先考虑已有连续组和单块尾部负载调整。只有真正消除一个接收单位或减少源端重复写出，才记通信收益。迁移后核心列表按当前全局拓扑顺序重新投影。

**小段重排。** 在全局子图顺序中，将选定块前移或后移至多 8 个位置。前移不能跨过其前驱，后移不能跨过其后继；修改后检查所有受影响的商图边方向，并把全局顺序投影回各核心。B 优先让大驻留张量提前用完；C 优先用真实存在的独立子图错开重复冷读。仅仅修改某一核心的列表却不检查跨核路径，是不允许的。

每次修改均记录旧块序、新块序及受影响的张量集合；合并或重排之后，以新的块序串接仍合法的块内拓扑序，后续“相邻”和“连续”均相对于这个更新后的顺序判断。

便宜排序先把能直接更新的量转成 cycles。记 $D_{\mathrm{part}}$ 为第 5.3 节基础 COPY 的独占参考工作量，$L_{\max}=\max_{k,p\in\{M,V\}}W_{k,p}$ 为最重计算 Pipe 的工作量。对修改 $e:X\to X'$ 定义

$$
\Gamma(e)=D_{\mathrm{part}}(X)-D_{\mathrm{part}}(X')
+L_{\max}(X)-L_{\max}(X')
+G_{\mathrm{sync}}(e)+G_{\mathrm{res}}(e)+\mathbf1\{r=C\}G_{\mathrm{cache}}(e).
$$

$G_{\mathrm{sync}}$ 只计该修改能直接取消的固定同步/切换延迟，且不超过原时间线对应的可见等待；不把已经计入 COPY 的传输时长再算一遍。$G_{\mathrm{res}}$ 取受影响区间理想驻留峰值的正容量超额在修改前后的减少量除以 60；它是快速压力信号，不是已减少的实际 spill。$G_{\mathrm{cache}}$ 仅对原时间线可定位的重复冷读给出参考值：预计移入填充—淘汰窗口的字节数乘 $(1/60-1/250)$，再扣被移动独立工作的参考延后量；未进入该窗口就取 0。相关时间由现有时间线和第 6.4 节的局部参考日历估计。

按 $\Gamma$ 从大到小排序，平局按操作类型、块 id、目标核心破同分。它只是为有限候选排先后，不解释为可相加的真实 Makespan 改善量。排名前 4 个才做完整代理展开与计数扫描。把其中 $J_r$ 最小的一个送入官方追加评估。若这个候选与原方案相同，或没有可解释的代价变化，则不消耗追加评估。

追加评估成功且 Makespan 变小才替换当前解；Makespan 相同则按第 5.2 节的规则选择。失败候选保留明确的错误状态，不写成零时间，不把它混入均值。默认只做一轮；第二轮只使用第 9 节预算中确实剩余的额外配额，而不是自动增加整包搜索深度。

对子图 DAG 合法但官方展开后出现环的候选，使用官方指出的操作级依赖定位是哪次分核/次序修改引入了问题，撤销该修改或使用另一个结构候选。若某组合尚无可执行多核方案，可使用已知整图单 Task 的单核放置并让其他核为空，再经该组合的官方入口评估；它是实际方案，不是用填零伪造成功，也不是主算法的目标。

### 6.7 伪代码

以下是后续拟实现流程，不表示本轮已经执行。

```text
算法：张量计数驱动的拓扑分块与驻留感知调度
输入：原图 G，核心数 K，场景 r，原始 config，剩余整包预算 B
输出：方案 X，以及与 X 对应的成功官方结果 Y

1  读取原图并建立真实张量/操作视图；执行一次必要输入检查
2  计算两类计算工作量、原始 COPY 字节数、反向计算 rank
3  若 r = C：
4      从同一用例同一核心数的最终 B 方案开始
5      在 Cache 入口评估该固定方案，得到 Y；不改配置
6  否则：
7      分别构造关键路径序和驻留收尾序
8      对每个顺序：按目标规模及最多 8 个切点组成连续拓扑块
9      对每个块：在 K 个核心上比较参考完成量和张量增量，分配核心
10     对两份完整方案计算 J_r，按顺序进入首次官方评估
11     取得第一个成功结果 Y，与对应方案 X 成对保存
12 从 Y 定位最多三处主要代价；不足三处不凑数
13 生成最多 24 个合法结构修改；精确更新关联张量通信计数
14 静态筛至最多 4 个，对它们完整计算代理；选出一个 X'
15 若 X' 不同于 X 且剩余预算容纳完整追加评估：
16     运行原始官方入口得到 Y'，包括全部准备和检查
17     若成功且 (Makespan, added_copy_bytes) 更优：X,Y ← X',Y'
18 返回成对的 X,Y；提交 JSON 只写题目允许的两个字段
```

“按顺序进入首次评估”是处理真实不可执行候选，不是把所有初始方案都作为必须评估项；失败尝试同样消耗预算。单核固定基准另由 `evaluate_singlecore` 计算，不由这段构造流程替代。

### 6.8 参数来源、复杂度和停止条件

固定选择为：就绪候选宽度 8、每块上限 512 个核内操作、切点候选至多 8、重排窗口至多 8 个子图、成组迁移上限 4 个子图、每轮结构候选 24、完整代理候选 4、默认追加官方候选 1。它们分别约束分支宽度、修改粒度和评估次数，不是有待大范围搜索的性能参数。目标块周期来自输入两条计算 Pipe 的工作量和核心数。DDR、Cache、容量与延迟全部读取固定配置。

令 $m$ 为真实操作依赖及张量关联规模，$S$ 为子图数，$N'$、$M'$ 为候选临时展开后的操作数和边数，$s$ 为换出扫描产生的预计换出次数，$R_a$ 为同时驻留张量个数。图视图、rank、双 Pipe 与张量计数的工作量为 $O(n+m)$；优先队列拓扑构造为 $O((n+m)\log n)$，前 8 个候选是固定倍数。切点回看可以共享区间计数；直接扫描局部块实现时，上界写成 $O(8\cdot512\cdot(n+m))$，不将未经实现的增量优化冒称常数时间。

一次完整代理需要生成相关 COPY 并处理真实关联，规模为 $O(N'+M')$；采用带下一次使用键的堆进行计数扫描时，开销为 $O((N'+M'+s)\log N')$，并保留插入次序作为破同分条件。32 区间拥挤量用区间端点与前缀累加处理，不逐 cycle 模拟。每轮最多 4 次完整代理，实际次数还受整包预算限制。

官方耗时单独记为 $t_{\mathrm{off}}(G,K,r,X)$。A 的当前 Task 构造会对各 Task 扫描张量；当前 Step2 换出时还会排序驻留候选，其费用包括 $\sum_e O(R_{a,e}\log R_{a,e})$。这些成本不会因为本方候选生成近线性就消失。故不宣称“官方几万节点毫秒级完成”，也不把说明文档中的旧示例耗时当本包实测。

终止条件为一次定点轮完成、没有有意义的合法修改，或剩余总预算不能容纳下一次完整调用。每用例的总生成、准备、评估时间同时记录，观察题面建议的约 5—10 分钟尺度；不把这个尺度乘到每个场景、每个核数、每个候选上。

## 7. 问题 1、2、3 如何逐步展开

### 7.1 问题 1：先把 Task 边界控制好

A 的主矛盾是并行收益与 Task 边界代价。切得太细会同时引入输入重复读取、结果写出/读入及 100/1000 等待；切得太粗则限制分核、增大局部缓存压力。

初始构造按 A 的目标块规模形成适度粒度；分核优先减少末端关键任务的前驱等待，同时平衡两条计算 Pipe。第一次评估后，重点看“合并同核相邻 Task 是否减少实际结束时间”和“拆开一个尾部重 Task 后，是否有足够独立计算覆盖新增 COPY 与同步”。

同核迁移本身不能取消 A 的子图边界 COPY。要消除这些 COPY，需要真正合并子图，而不只是把两个 Task 放在同核。合并之后也重新运行官方 Step1—3，以反映块内顺序改变。

### 7.2 问题 2：保留顺序粒度，把复用和占位放在一起算

B 沿用张量关联、rank、候选生成与接受规则，把执行单位改成核心。不要把 A 的 Task 切换等待带入 B，也不要因为同核没有额外 COPY，就将同核所有子图直接合成一个不可调整的提交子图。

在固定分核下，细子图主要用于表达官方核内顺序的偏好。可以先复用 A 构造出的拓扑块作为一种起点，但正式 B 候选按更细目标规模构造并采用 B 通信计数，不能把 A 的时间和搬运量当作 B 的初始成绩。

优先迁移能减少接收核心个数的大张量消费者组；若同核驻留跨度引发换出，则把相关消费块靠近生产或首次使用位置。判断重排价值时，同时查看 Cube/Vector 并行和被提前块的依赖，避免为了缩短一个张量的生存期而让主计算 Pipe 大段空闲。

### 7.3 问题 3：从同方案硬件对照开始，再优化 FIFO 读取窗口

先固定最终 B 方案 $X_B$，分别取得 $F_B(X_B)$ 与 $F_C(X_B)$。这两项回答“只加 Cache、调度不变”的硬件收益。然后以 $X_B$ 为起点生成 Cache 感知候选 $X_C$，其改动仅涉及合法分核或子图顺序，回答“允许调度适配后还改变多少”。

对一次重复读取，真正有用的窗口是：

$$
F_{\mathrm{first\ fill}}(t)\le S_{\mathrm{repeat}}(t)
< T_{\mathrm{evict}}(t).
$$

左端由首次能完成并插入的 COPY_IN 决定；右端由后续插入及容量决定，命中不会延长 FIFO 排位。若第一次读取仍在途，不能按命中处理；若队列里已经没有此键，不能因为“刚才访问过”而预测命中。

**低成本候选判断采用固定参考时序回放。** 从 $X_B$ 在 C 下的正式时间线提取 COPY_IN 的查询和完成时间，并根据这些事件重新产生插入、淘汰；旧 Cache 插入日志用于核对起点，不能再作为另一份插入重复回放。

候选重建后生成的操作 id 会改变。事件匹配使用“读取/写出类型、逻辑张量 id、所在核心、跨核来源/目标、基础 COPY 或换入换出、同类访问序号”的语义键，而不直接拿两个候选的物理 op_id 相等作为同一事件。对于只重排的候选，将匹配事件的旧正式时刻，加上该事件在新旧临时四 Pipe 展开中的时刻差，作为新的参考时刻；新增或无法匹配的事件采用新候选临时展开时刻。再沿候选参考图按数据、Pipe、同步依赖向后传播必要的时间推迟，保证查询早于对应完成且不违背参考依赖。不受影响、又无需传播推迟的事件保留旧时刻。

按这些参考查询、完成事件重新回放 FIFO，估计命中字节变化。相同时刻使用与官方一致的完成先于发射、核心及 Pipe 遍历规则；仍在 Cache 中的键不刷新，完成后键已被淘汰则按实际代码重新插入。需要映射准确换入事件时，使用第 6.5 节已计入预算的原始扩展图诊断；没有准确映射的换入使用计数扫描位置生成参考事件，并保留为代理。

以参考时序下的新增命中字节估计 DDR 工作量减少及 Cache 读工作量增加，再减去被推迟工作的参考结束时间代价。由同一次重排造成的带宽变化会反过来影响时间，因此这个回放不是最终命中预测器，只用于从最多 24 个候选中选择一个值得正式评估的方案。

具体动作是把一个**真实存在且可提前执行**的独立子图放在重复读取块前面；不是提交“等待 1000 cycles”，更不是提交一条题面没有的预取。若没有可重排的独立工作，就不生成这种候选。也可以把反复在同一核换入的大张量消费者放近一些；一核情况下，Cache 仍可能影响换入读取，不能预先断言一核必定没有命中。

问题 3 输出硬件收益与优化后的整体收益，不能仅选有利口径：

$$
G_{\mathrm{hw}}=\frac{F_B(X_B)}{F_C(X_B)},\qquad
G_{\mathrm{combined}}=\frac{F_B(X_B)}{F_C(X_C)}.
$$

必要的少量交叉对照再计算 $F_B(X_C)$，这样能够看出某个顺序究竟专门利用了 Cache，还是在没有 Cache 时也更好。Cache 带来的读时序变化还可能改变 Pipe 等待，所以不预设每个算例都一定更快。

## 8. 一个说明性手算：切分、计数与读取窗口

本节构造一个小图解释决策，**不是附件算例，也不是官方实测**。设五个核内操作为 $A,B,C,D,E$。$A$ 使用 Cube，$B,C,D,E$ 使用 Vector。外部输入 $x$ 被 $A,E$ 共用，大小为 60000 bytes；$A$ 产生 $z$，大小为 30000 bytes，供 $B,C,D$ 使用。$B,C,D,E$ 各产生一个 6000-byte 最终输出。输入和中间数据都放在 L1，单操作输入输出量远小于 L1 容量；操作间除此以外没有依赖。

取操作周期为 $c_A=4000$、$c_E=4000$、$c_B=c_C=c_D=1000$。原图只需读一次 $x$，写出四份最终结果，因此

$$
Q^{\mathrm{orig}}=60000+4\times6000=84000\ \text{bytes}.
$$

### 8.1 一个明确的三核方案

设置子图 $s_0=\{A,E\}$、$s_1=\{B,C\}$、$s_2=\{D\}$，分别放在核 0、核 1、核 2。子图依赖为 $s_0\to s_1$、$s_0\to s_2$，所以商图无环。若操作 id 分别为 10、11、12、13、14，方案表示为：

```json
{
  "node_to_subgraph": {"10": 0, "11": 1, "12": 1, "13": 2, "14": 0},
  "core_schedules": [[0], [1], [2]]
}
```

把 $A,E$ 放在一起，不只是因为共用输入；它们分别占 Cube、Vector，具备并行条件。参考计算规模为 $\max(4000,4000)=4000$，而不是直接相加得到 8000。能否完整重叠还须经过官方内存申请顺序和 Pipe 排布，这里只说明该组合值得考虑。

### 8.2 同一个跨核扇出，在 A、B 的写出次数不同

对 $z$ 而言，$B,C$ 属于同一个接收单位，只算一次搬入；$D$ 属于另一个接收单位。

A 中源 Task 写出一次，两个目标 Task 各读一次：

$$
Q_{A,z}=(1+2)\times30000=90000.
$$

B 中两个源核到目标核连接分别构造一对 COPY：

$$
Q_{B,z}=2\times2\times30000=120000.
$$

在不发生换出的说明条件下，总 COPY 字节数分别为 174000 和 204000，新增字节分别为 90000 和 120000。这个结果并不说明 B 一定更慢：B 的跨核读取可以在对应源 COPY_OUT 完成加 500 后释放，而 A 需等待源 Task 完成加 1000；时间收益和字节代价不同。

如果再把 $D$ 放到核 1，B 的接收核心由两个变成一个，$z$ 的跨核 COPY 降为 60000 bytes；但核 1 的 Vector 工作量由 2000 增为 3000 cycles。因此这一步应比较“减少 60000 字节及一组跨核传输”与“目标核增加 1000 cycles”，不能只看负载方差。

如果保持 A 中 $s_1,s_2$ 两个 Task 不合并，只把它们放在同一核，$z$ 的 A 搬运仍是 90000 bytes，并增加同核 Task 顺序约束。只有把 $s_1,s_2$ 真正合成一个子图，A 才把这份张量的接收 Task 数降为 1。

### 8.3 驻留跨度为何改变顺序选择

再看一个独立的 UB 局部状态。已有张量 $t$ 大小为 80000 bytes，稍后才会再次使用；当前无关操作需要两个合计 60000-byte 的输入输出区域。申请完成、输入释放之前需要 140000 bytes，超过 UB 的 131072 bytes。若 $t$ 当前不参与计算且未来仍要使用，官方可能将其换出。

若把 $t$ 的最后消费操作提前，并在无关操作申请区域前完成，$t$ 就能够释放。这是重排的具体价值。若 $t$ 原先来自 DDR 且后备有效，一次重新读取代价为 80000 bytes；若是首次需要写回的计算结果，则是 160000 bytes。不能不看后备状态就统一记成两次搬运。

### 8.4 “同时开始”未必最有利于共享 Cache

在另一个读取时序说明中，两核都要读取 $x=60000$ bytes，开始时 Cache 为空。忽略其他搬运，两个 COPY_IN 同时发射，都查询未命中；每份独占参考工作为 $60000/60=1000$ cycles，共享 DDR 后同时完成需 2000 cycles。

若核 0 在 0 时发射，核 1 先执行一段独立、无需 DDR 的已有工作，并在 1000 cycles 时才发射读取，则核 0 的读取可在 1000 完成并插入，核 1 的后续读取可走 Cache，其独占参考时长为 $60000/250=240$ cycles。这个对照只说明“用已有独立工作错开冷读”有明确机制，不代表最终整图一定节省 760 cycles；独立工作的真实依赖及后续计算必须一并评估。

最后，用实际 1 MiB Cache 容量解释 FIFO：先插入 512 KiB 的 $x_1$ 和 384 KiB 的 $x_2$，再命中一次 $x_1$，FIFO 顺序仍为 $[x_1,x_2]$。随后插入 256 KiB 的 $x_3$ 时容量不足，先淘汰的仍是 $x_1$，并不会因为它刚刚命中过而先淘汰 $x_2$。

### 9.3 少量必要基线与机制对照

### 9.4 墙钟预算如何核算

拟将 8 小时按下面方式分配。表中全部是**预算额度，不是已测耗时**。

| 后续实验活动 | 墙钟预算 |
|---|---:|
| 最小合法性验证、少数规模层的计时与并发试运行 | 0.25 h |
| 全包静态特征、两个构造种子、代理筛选与方案输出 | 0.50 h |
| 补齐 1500 项基础官方结果 | 4.25 h |
| 按真实代价选择追加定点候选，最多 1300 项 | 1.75 h |
| 机制对照与少数诊断展开 | 0.50 h |
| 汇总全部逐例结果与自动生成图表 | 0.25 h |
| 错误修正后的重算和尾部大用例余量 | 0.50 h |
| **合计** | **8.00 h** |

批量执行以独立用例/核数组合为进程任务，初始并发取 2，在小规模计时中比较 4；只有实际吞吐提升且总进程内存留有余量时才采用更高并发。48GB 统一内存不等于所有内存都用于评估，拟给评估进程合计约 32GB 的工作额度，其余留给系统和结果处理。该额度是本方运行资源设置，不是修改题目硬件配置，也不表示已测出了评估进程内存需求。

设某批第 $j$ 个任务的生成与代理耗时为 $t_j^{\mathrm{gen}}$，官方完整评估耗时为 $t_j^{\mathrm{off}}$，诊断展开耗时为 $t_j^{\mathrm{diag}}$。按实际并行工作者任务集合 $\mathcal J_w$，估计整批墙钟：

$$
\widehat T_{\mathrm{wall}}
=T_{\mathrm{serial}}+
\max_w\sum_{j\in\mathcal J_w}
(t_j^{\mathrm{gen}}+t_j^{\mathrm{off}}+t_j^{\mathrm{diag}}).
$$

用规模分层试运行的实际统计更新估计，大用例先入队以减少最后只剩单个长任务的情况。对追加候选按“预计可减少的 Makespan / 预计完整评估秒数”排序分配剩余配额，不按用例编号平均分配无限搜索时间。

作为预算反算，1500 次基础调用要落在 4.25 h 中，平均吞吐需达到约 5.88 次/分钟；在理想 4 路充分利用时，相当于平均每次约 40.8 秒。**这是所需吞吐门槛，不是这台 Mac 已经达到的速度。** 实际准备、内存压力、输出写盘和长尾都会影响它。

若计时表明基础组合已逼近总预算，先取消第二轮、降低追加候选配额并复用相同方案的既有结果，不减少 100 例或核数覆盖。若连全部必要官方调用都无法落在 8 小时内，应据实际吞吐说明所需时间，不能用代理时间冒充官方结果，或删去慢用例后声称完成全包。正式评估代码、容量、带宽、同步延迟均不修改。

### 10.1 题目与章节主线

建议论文题目为：**《考虑张量复用与驻留跨度的多核切图与调度方法》**。方法名称保持朴素，正文不堆砌多个英文算法缩写。

先用一张包含“张量消费者—Task 边界—私有驻留—共享带宽”的机制图解释题意，再列真实数据规模。公共模型只定义一次操作、张量、分块、核心、顺序与官方评估映射；问题 1 讲 Task 边界及激活等待，问题 2 讲同核数据复用与驻留占位，问题 3 讲 FIFO 读路径及到达次序。每问都把新增机制与对应结果紧接着写，不先堆十页算法原理再统一堆图。

### 10.2 论文必须回答的机制问题

这些问题的回答应由公式、官方统计和代表性时间段共同支撑。没有真实时间线支持时，不把一个性能变化归因为某种具体等待；没有全局最优证书时，不写“求得全局最优调度”。

### 10.3 必须出现的图表

### 10.4 一段可借鉴的模型介绍

> 本文首先将计算图中的每个张量与其生产、消费操作对应起来，按任务或核心统计实际需要的数据读写。针对场景 A，将连续拓扑区间组成子图，在保留并行计算空间的同时减少任务边界及其等待；针对场景 B，将同核数据的驻留过程纳入调度，根据张量的最后使用位置调整子图次序，减少容量不足带来的换入换出。随后，结合 Cube、Vector 两条计算流水线的工作量生成分核方案，并根据官方时间线对拖慢任务结束的局部位置进行有限修改。引入只读 Cache 后，进一步区分读取发射、首次填充完成和 FIFO 淘汰时刻，通过合法的子图重排调整重复读取的到达次序。最终，各方案均由题目给定的多核评估程序计算 Makespan 与辅助指标。

|---|---|---|

| `construct.py` | `build_topological_order(...)`；`make_blocks(...)`；`assign_cores(...)` | 构造两个拓扑种子、有限切点和双 Pipe 分核，输出完整合法结构候选 |

### 11.2 官方真实接口与使用边界

固定单核接口在 `code/singlecore_evaluate.py`：`build_singlecore_plan` 和 `evaluate_singlecore`。三问最终入口分别为 `evaluate_scene_a`、`evaluate_scene_b`、`evaluate_problem_3`；命令行参数读取集中在 `contest_io.py` 的 `run_problem_cli`，配置读取在 `evaluation_validation.py`。

官方准备链为：`schedule_step1.py::step1_schedule` → `schedule_step2.py::step2_spill_insertion` → `_build_extended_graph` → `schedule_step3.py::prepare_step3_execution`。B/C 的 `_prioritize_task_seq` 会按核心上的子图顺序稳定重排并检查拓扑；不能仅向 Step1 传一个自定义优先级就声称实现了本方法的顺序控制。

`stub_multicore_cut_and_schedule.py` 内的 `derive_multicore_plan` 和 `validate_multicore_plan` 是真实可用的结构解析与检查接口，但随机生成函数不是性能基线。完整可执行性还依赖问题入口调用的 `validate_task_order` 或 `validate_execution`。

正式评估优先使用原始 CLI，避免因为只 import 某个函数而漏传固定等待值。拟建 runner 为每个“场景/用例/核数/候选”建立独立输出位置，并显式给第二位置参数方案路径和 `--config`。例如，下面是**后续运行的命令格式**，不是本轮已经执行的命令：

```bash
python OFFICIAL/code/multicore_cut_evaluate_problem_2.py \
  OFFICIAL/data/case_001.json \
  OUTPUT/problem_2/case_001/k4/plan.json \
  --config OFFICIAL/data/config.txt \
  -o OUTPUT/problem_2/case_001/k4/result.json \
  --trace-output OUTPUT/problem_2/case_001/k4/trace.json \
  --log-output OUTPUT/problem_2/case_001/k4/log.txt
```

`OFFICIAL`、`OUTPUT` 是拟建 runner 根据真实目录解析的路径参数，不是假定用户目录里已经有这些字面文件夹。显式指定输出位置可以防止默认评估输出写回原始 `data/`，也避免多进程相互覆盖。

### 11.3 数据依赖与实现顺序

先实现图视图与通信计数，使用说明性小图核对“一源多目标”及“多消费者同核去重”；再实现拓扑顺序、分块与双 Pipe 分核，确保能写出两个字段的完整方案；随后接通原始单核与 A/B/C CLI，让实际配置和结果字段贯通。之后实现计数式驻留代理，再用首次成功的正式时间线定位定点修改；最后接入 Cache 的参考时序回放、整包配额分配与结果汇总。

有限修改不要求实现所有通用图划分算子。首版必须具有连续区间合并/拆分、单块/至多四块成组迁移、至多八块范围的合法重排。候选出现时才做需要的图检查，不运行与求解无关的扫描系统。

复用的内容是原图视图、张量倒排、既有成功方案和完全相同组合的结果。局部修改后，通信计数可以增量更新；官方展开或 Makespan 不通过修改旧结果 JSON “增量算出来”。重要的内存诊断另调用原始构造函数，明确计算成本，也不改动官方文件。

### 11.4 必要验证集中在一处

实现时将检查集中到 runner 与官方入口：输入覆盖和唯一性正确；子图及执行顺序可行；固定配置正确；官方返回成功且全部操作完成；用于汇总的方案与结果成对；平均加速比采用指定口径。容量及展开依赖优先采用官方检查。

出现失败时保存错误说明并修正相关候选，不吞掉异常、不补零。单个结果文件是否存在不是成功判据，尤其不能误读同名旧结果。正常的任务状态、字典去重和结果对应关系已经足够，不新增哈希审计平台、插件框架或容灾工程。
