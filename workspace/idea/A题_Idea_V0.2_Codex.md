# A题 Idea V0.2：张量驻留域感知的多核调度

**题目：通用神经网络处理器下的多核调度问题**  
**文档类型：独立研究 Idea · 逐问模型建立与求解 · 论文执行大纲**  
**版本日期：2026-09-23**

> 核心研究问题：在算子、核内调度器和硬件参数固定时，怎样通过子图划分、分核和同核顺序，控制张量跨越的驻留边界与读入时机，从而缩短官方 Makespan？

本文按“问题一的模型建立与求解 → 问题二的模型建立与求解 → 问题三的模型建立与求解”逐问展开。十二节覆盖题意、文献、数学推导、算法、手算、实验和实现任务。文中静态统计来自当前官方附件；性能、耗时与实验表格均为后续执行设计，未填入未测结果。

## 1. 一页核心卡：这篇论文究竟解决什么

把一张神经网络计算图平均分给多个核，并不能直接得到好的调度。同一个张量被多个算子使用时，真正需要付出的搬运代价取决于这些算子落在哪些 Task、哪些核，以及读入时共享 Cache 是否已经保存了该张量。分得过细会增加问题一的 Task 切换与 DDR 往返；过度集中又会压缩并行度，并在问题二中延长张量存活时间、触发换入换出；问题三还存在“两个核几乎同时读取同一张量，却都未命中”的时序现象。本方案以张量驻留域为统一建模对象，先沿拓扑序构造有限数量的连续子图，再按关键路径、Pipe 负载和张量级搬运代价进行分核，用存活区间筛掉高换出风险的安排，最后依据官方事件轨迹对少量可调整顺序做定向修正。

方法暂称 **TRS：Tensor-Residency Scheduling，张量驻留调度**。名称只指向一个机制：改变数据的驻留范围及使用顺序，进而改变通信、容量和关键路径。

| 核心卡项目 | 本文的具体内容 |
|---|---|
| 输入 | 官方 100 个图、固定 `config.txt`、指定核数 |
| 可改变的决策 | 非 COPY 算子的子图归属、子图所在核、同核子图顺序 |
| 最终目标 | 对每个用例、问题和核数，最小化官方评估返回的 `makespan` |
| 结构洞察 | 普通切边数没有表达“同一张量被几个不同驻留域消费”；静态字节数也没有表达数据何时可用 |
| 统一方法 | 拓扑连续划分 + 张量关联代价 + 有限局部调整 + 官方评估验收 |
| 问题一 | Task 是驻留域；处理跨 Task 搬运与 100/1000 cycles 激活约束 |
| 问题二 | 核是驻留域；处理跨核成对搬运、500 cycles 同步和核内 Spill |
| 问题三 | 在问题二上追踪 FIFO 驻留阶段；利用合法顺序改变 COPY_IN 命中时机 |
| 论文要证明的事情 | 代价模型是否更准确地选择方案，存活区间机制是否降低 Spill，Cache 调序是否在真实 Makespan 上获益 |
| 结果字段 | 官方 Makespan、平均加速比、额外搬运字节、Spill 字节、Cache 字节命中率、算法墙钟时间 |

研究定位侧重系统与编译优化：把真实执行语义转化为能求解、能解释、能验证的模型。借鉴 AAAI 级执行大纲的贡献与证据组织方式，相关工作优先选择与神经网络执行、图划分和资源调度直接相关的原文。

这些事实直接决定三项设计：不在数万操作上建立全局整数规划；按张量的消费域计数，避免高扇出导致切边代价失真；分别跟踪 M/V 工作量，避免用操作个数代表计算负载。它们尚未证明通信或容量是每个用例的主瓶颈，后续需用官方轨迹分类。

### 2.3 三问的区别

| 项目 | 问题一：场景 A | 问题二：场景 B | 问题三：B + 只读 Cache |
|---|---|---|---|
| Task 单位 | 每个子图一个 Task | 每核一个 Task | 每核一个 Task |
| 同核跨子图数据 | 经 DDR 中转 | 可片上驻留，计入容量 | 同问题二 |
| 同核顺序影响 | Task 激活先后 | 稳定分桶后改变核内序列、Spill 和 Pipe FIFO | 同问题二，并改变 Cache 事件次序 |
| 跨核同步 | 前驱 Task 结束后 1000 cycles | 源 COPY_OUT 结束后 500 cycles | 同问题二，即使命中也保留同步条件 |
| 同核切换 | 前 Task 结束后 100 cycles | 无逐子图 Task 切换项 | 同问题二 |
| 共享读 Cache | 无 | 无 | 1,048,576 bytes，FIFO，250 bytes/cycle |
| DDR | 三问均为共享 60 bytes/cycle | 同左 | 与 Cache 独立共享，不能相加成 310 |

每核 L1 容量为 524,288 bytes，UB 为 131,072 bytes。每条 `PIPE_M`、`PIPE_V`、`PIPE_MTE2`、`PIPE_MTE3` 同时只有一个在飞操作。不同 Pipe 可以重叠，不同核的 DDR 搬运竞争同一带宽池。

### 2.4 提交字段怎样变成官方时间

合法提交的顶层字段必须且只能是 `node_to_subgraph` 与 `core_schedules`。开始时刻、单个 COPY 的发射时刻、预取、Cache 替换、内存地址和 Pipe 内任意重排均不是提交自由度。

官方调用链可概括为：

```text
原图 + 两字段计划 + 固定配置
  -> derive_multicore_plan：覆盖、子图、核与基本依赖
  -> 场景构图：形成 Task，重建输入/输出及跨域 COPY
  -> Step1：确定性 reverse DFS 产生局部序列
  -> B/C 按 core_schedules 中的子图顺序稳定分桶并检查拓扑
  -> Step2：容量约束下插入 Spill / Reload
  -> Step3：固定每条 Pipe 的 FIFO 顺序，生成内存复用依赖
  -> A 的 Task 顺序校验或 B/C 的扩展执行图校验
  -> 多核事件模拟、共享带宽竞争、C 的 FIFO Cache
  -> Makespan、搬运计数、时间线及 Cache 事件
```

因此，算法设计的全局拓扑序用于构造分区和可表达的同核顺序，不能宣称其就是官方实际操作发射顺序。本文把完整官方评估通过作为执行合法性的验收证据。

### 3.3 三条路线与最终选择

| 路线 | 划分、分核与顺序 | 成本与局限 | 决策 |
|---|---|---|---|
| 全图精确优化 | 在操作层联合求子图、核、排序和时间 | 上万操作且含离散事件、Spill 和 FIFO 状态；准确线性化本身就是大项目 | 不作为四天主线 |
| 普通图划分 + 负载均衡 | 按边权分区，按总计算量分核，再拓扑排序 | 忽略同张量多消费者去重，也忽略 Task 与核的驻留差别 | 用作简化对照 |
| TRS | 拓扑连续区域、张量级域计数、Pipe/关键路径代理、有限驻留和事件修正 | 放弃部分任意划分空间，换取可执行性和可核算成本；最终用官方时间选择 | 主方法 |

## 4. 共享符号、约束与候选骨架

### 4.1 对象与变量

记 $V$ 为所有非 COPY 计算操作，$n=|V|$；$T$ 为与计算操作相关的张量集合；$E$ 为保留 COPY 收缩依赖后的计算操作边集；$I$ 为操作与张量的关联数。对张量 $t$，$s_t$ 是大小，$p(t)$ 是计算生产者，$C(t)$ 是计算消费者集合；没有计算生产者的张量属于图输入。当前材料中每个张量最多有一个计算生产者。

操作 $v$ 的计算时长为 $w_v=\max(1,\mathrm{cycles}_v)$，Pipe 类型为 $q_v$。张量片上位置为 $m_t\in\{L1,UB\}$；官方构图把需要进入片上的原 `DDR` tensor 转为 UB 时，代理采用相同映射。

决策写为 $\Pi=(g,c,\sigma)$：$g(v)$ 给出操作所属子图，$c(j)\in\{0,\ldots,K-1\}$ 给出子图 $j$ 的核，$\sigma_c$ 为该核的子图顺序。$K$ 是指定核数，允许部分核的顺序为空。$S$ 是非空子图数。

输出映射满足：每个 $v\in V$ 恰好属于一个非空子图；每个子图恰好出现在一个核序列中一次；依赖、扩展执行关系和容量满足该场景官方检查。仅有原始 DAG 无环不够，核之间双向传数据也不等同于操作级死锁。

### 4.2 真实目标与候选代理

对场景 $X\in\{A,B,C\}$，真实目标统一为

$$
\min_{\Pi\in\mathcal F_X(G,K)}F_X(\Pi),\qquad
F_X(\Pi)=\operatorname{OfficialMakespan}_X(G,\Pi;\mathrm{config}).
$$

$\mathcal F_X$ 是通过该场景完整官方检查的计划集合。后文的代理 $J_X$ 只用于产生和排序候选，不能替代 $F_X$，也不据此宣称全局最优。

### 4.3 拓扑连续分区命题

先生成计算图的一条拓扑序 $\pi=(v_1,\ldots,v_n)$，再把它划成不重叠的连续区间。按区间在 $\pi$ 中的位置编号，并令每核顺序为这些编号的投影。

**命题 1。** 该表示的子图商图无环，且在商图上加入每核相邻子图顺序边后仍无环。

**证明。** 原始依赖从较小拓扑位置指向较大位置。跨区间依赖必从较小区间编号指向较大编号；新增核内顺序边也严格增加编号，因此不存在有向环。这个命题覆盖分区及 Task 层顺序，B/C 的 Pipe、内存与 COPY 扩展边仍交给官方执行图检查。

主方法不需要一般图分区后的复杂修复。后续移动子图到另一核时保持全局区间顺序；Q3 的顺序调整则重新检查子图 DAG 与新全局顺序相容，再投影到各核。

### 4.4 共享候选生成器

反向拓扑计算关键路径秩

$$
r(v)=w_v+\max_{u\in\operatorname{succ}(v)}r(u),
$$

空后继的最大值取 0。Kahn 算法维护就绪堆，每次取 $r(v)$ 最大的至多 $h=8$ 个操作作为窗口。窗口内按

$$
P(v)=r(v)+\frac{b_{\rm release}(v)-b_{\rm open}(v)}{60}
$$

选择操作，再按较小操作 id 打破平局。排序开始时代理存活集合为空；图输入在首次消费时打开，内部张量在生产者被选中时打开，在最后一个未安排消费者被选中后关闭。首次读入且本步立即用完的图输入不进入跨操作存活集合。$b_{\rm release}$ 统计本步关闭的既有存活张量字节，$b_{\rm open}$ 统计本步新打开且仍有未来消费者的张量字节；同一张量在同一操作中只计一次。这是结构排序分数，不能解释为已节省的实际 DDR 时间。

为避免就绪窗口反复扫描高扇出张量，两个字节量按操作维护增量计数。输入首次打开时，更新其剩余消费者的打开成本；张量仅剩一个未安排消费者时，更新该消费者的释放收益。每个张量的这些状态事件各发生至多一次，消费者集合随操作选择删除，所有状态更新累计扫描 $O(I)$ 个关联。就绪堆按固定 $r(v)$ 取窗口，窗口内读取已维护的 $P(v)$。

设 $W=\sum_vw_v$。仅生成 $\rho\in\{4,8,16\}$ 三档粗细，目标子图数 $S_0=\min(n,\rho K)$。在累计计算量的第 $jW/S_0$ 附近，考察落在 $[(j-0.2)W/S_0,(j+0.2)W/S_0]$ 的切点，以

$$
J_{\rm cut}(i)=\left|W_{1:i}-\frac{jW}{S_0}\right|+\frac{B(i)}{60}
$$

选择切点。$B(i)$ 为关联位置跨过切点的张量大小之和，同一张量只计一次；输入张量按其消费者位置区间计入。窗口没有切点时取距目标最近的位置，重复切点去重，禁止空子图。最后得到至多 $\rho K$ 个区间。孤立大操作不拆分。

$B(i)$ 用张量首末关联位置的差分数组求出，计算所有切点不需要逐切点扫描全部张量。三档只是固定候选集合；后续计时表明成本紧张时统一降为 $\rho=8$，不能按结果为每个案例手填参数。

这一骨架三问共用，接下来的驻留域、通信公式与评分过程逐问改变。

## 5. 问题一的模型建立与求解：Task 边界与并行度的权衡

### 5.1 本问要回答的科学问题

**在每个子图独立构成 Task 的情况下，怎样避免因追求负载均衡而制造过多 DDR 往返与启动等待？**

本问采用张量与 Task 的关联模型。先确定切分带来的确切边界搬运量，再分析这些 Task 的执行与激活链。分区决定数据要跨过多少 Task；分核决定这些 Task 能否重叠以及使用哪种同步延迟。

### 5.2 Task 级张量搬运模型

记 $D_A(t)=\{g(v):v\in C(t)\}$ 为消费 $t$ 的不同 Task 集合。若存在生产者，记 $a_t=g(p(t))$，$r_A(t)=|D_A(t)\setminus\{a_t\}|$。令 $o_t=1$ 表示官方构图需要最终输出写回，即原张量有 COPY_OUT 消费者或没有计算消费者；其他情况为 0。

未计 Spill 的张量搬运量为

$$
V_A^0(t)=
\begin{cases}
s_t|D_A(t)|, & t\text{ 为图输入},\\
s_t\left[r_A(t)+\mathbf1\{r_A(t)>0\ \lor\ o_t=1\}\right],
& t\text{ 有计算生产者}.
\end{cases}
$$

**命题 2。** 在当前单计算生产者图上，该式精确描述官方 A 构图的张量边界 COPY 字节数，且同核跨 Task 也按此式计费。

**推导。** 每个非生产 Task 对该张量只建立一次输入 COPY，无论该 Task 内有多少消费者。生产 Task 只要存在外部消费者或最终输出，就建立一次输出 COPY；这两个条件通过逻辑“或”合并。因此一个张量被 $r$ 个外部 Task 消费时，合计 $(1+r)s_t$，而不是按 $r$ 条边各计一次写出与读入。

总调度搬运量与额外搬运量分别为

$$
V_A^{\rm sched}=\sum_tV_A^0(t)+V_A^{\rm spill},\qquad
V_A^{\rm added}=V_A^{\rm sched}-V^{\rm original}.
$$

$V^{\rm original}$ 为原始 COPY 的官方字节计数，保持其定义。若张量本来已有最终输出，则跨 Task 后的新增量不能再次计入原有的那一次写回。官方 `cross_task_traffic` 对此类传播只计 $r_As_t$，与读写总量不同。

### 5.3 激活约束与准确目标

设 Task $j$ 的激活、结束时间分别为 $a_j,f_j$，$\operatorname{prev}_c(j)$ 是同核前一个 Task。约束为

$$
\begin{aligned}
a_j&\ge f_i, && i\in\operatorname{pred}(j),\\
a_j&\ge f_i+1000, && i\in\operatorname{pred}(j),\ c(i)\ne c(j),\\
a_j&\ge f_{\operatorname{prev}_c(j)}+100,
&& \operatorname{prev}_c(j)\text{ 存在}.
\end{aligned}
$$

取所有适用约束的最大值，首个无前驱 Task 可在 0 开始。$f_j-a_j$ 由 Task 内数据依赖、Pipe FIFO、容量复用和全局 DDR 竞争共同决定，不能预先视为与其他 Task 无关的固定常数。真实目标是 $\min\max_jf_j=\min F_A(\Pi)$。

在保持分区不变时，单纯把 Task 换到另一核不会改变 $V_A^0$；它主要改变并行性和激活约束。只有划分边界发生变化，才改变本问的张量消费 Task 数。这一区别用于解释消融结果。

### 5.4 可计算代理与参数来源

对每个 Task 计算 M/V 工作量 $W_{j,M},W_{j,V}$、计算子图最长路径 $L_j$、分配到该 Task 的输入与输出 COPY 字节 $V_j^0$。构造

$$
\widehat d_j=\max\{W_{j,M},W_{j,V},L_j,V_j^0/60\}.
$$

按 §5.3 的激活规则递推 $\widehat f_j=\widehat a_j+\widehat d_j$。用局部序列的首次产生/首次输入到最后一次使用的张量区间估计 $\widehat L_{j,m}^{\rm peak}$；同一操作的输入和输出先同时计入，再释放结束使用的张量，避免漏算分配峰值。此顺序取候选拓扑序在 Task 内的投影，属于筛选代理，实际峰值由 Step2/3 决定。

定义超容风险字节

$$
P_A=\sum_{j,m}\max(0,\widehat L_{j,m}^{\rm peak}-C_m),
$$

其中 $C_m$ 为官方 L1/UB 容量。最终代理为

$$
J_A(\Pi)=\max\left\{\max_j\widehat f_j,\frac{\sum_tV_A^0(t)}{60}\right\}
+\frac{2P_A}{60}.
$$

各项均为 cycles。系数 2 对应“写出再读回”的粗略风险尺度，不代表精确 Spill 下界；有 DDR backing 的换入可能只需一次读。它在全部用例固定，后续只做一次去除该项的对照，不按案例调参。

### 5.5 求解算法 TRS-A

1. 生成 §4 的拓扑序和三档连续分区，建立 Task DAG、张量消费 Task 计数及每个 Task 的 M/V 工作量。
2. 按全局子图顺序依次放置 Task。枚举 $K$ 个核，计算该 Task 的 $\widehat f_j$；选择最小者，平局时依次选择较小的核上最大 Pipe 负载、较小核编号。核序列保持全局顺序投影。
3. 对每档方案做至多两轮局部改进。每轮选代理关键链上优先、随后按 $\widehat d_j$ 降序的至多 8 个 Task，枚举迁移到其他核；另选边界字节最大的至多 8 个切点，分别尝试向左、向右移动一个操作，要求两侧仍非空。
4. 对局部候选计算完整 $J_A$，仅接受严格降低代理的最佳一个；没有改善立即结束该档。每轮最多 $8(K-1)+16$ 个局部候选。更新受影响张量的域计数、Task DAG 和核序列。
5. 三档最终候选去重，按 $J_A$ 排序。先官方评估第一名；通过后得到当前有效解。备用候选仅在评估失败或分配到额外预算时评估，以真实 $F_A$ 选择更好者。失败保存具体官方错误，不能用零时间填充。

```text
TRS_A(graph, K, evaluation_budget):
    view <- parse_compute_graph_and_tensor_incidence(graph)
    topo <- critical_reuse_topological_order(view, ready_window=8)
    candidates <- []
    for granularity in permitted_subset([4, 8, 16]):
        regions <- cut_contiguous_regions(topo, K, granularity)
        plan <- place_regions_by_scene_A_finish(regions)
        repeat at most 2 sweeps:
            moves <- top_8_region_moves + top_8_boundary_shifts
            trial <- best_strict_proxy_improvement(moves, J_A)
            if no trial: break
            plan <- trial
        candidates.append(plan)
    candidates <- deduplicate_and_sort(candidates, J_A)
    return official_select_with_budget(candidates, scene=A)
```

终止条件由候选数、两轮上限和官方评估预算共同确定。正式输出只能来自通过官方评估的计划。单核基准计划可嵌入含空序列的 $K$ 核计划作为备用方向，但实际写出的文件仍按对应入口核验。

### 5.6 说明性手算：什么时候不该切

考虑局部依赖链 $a\to t\to b$，$w_a=1000$、$w_b=800$，$s_t=12000$ bytes，两操作在同一计算 Pipe，容量足够。这里只比较从 $a$ 开始到 $b$ 完成的局部链，省略共同的外部输入和最终输出，无其他 DDR 竞争。

放在一个 Task 时，局部完成时间为 $1800$。分成同核两个 Task 后，$a$ 计算 1000、写出 200、等待 100、读入 200、$b$ 计算 800，合计 **2300 cycles**。分到两核时该链没有可利用的并行分支，1000 cycles 跨核等待使总时间为 **3200 cycles**。此例说明切分必须换来实际并行收益，核数增加本身并不产生收益。

再考虑一个 12000 bytes 张量被两个其他 Task 消费：源端写出一次 12000，两个目标各读 12000，总计 **36000 bytes**。两个消费者若合成同一个目标 Task，则降为 **24000 bytes**。按消费者边数计价无法表达该差别。

以上为手算，不是官方用例结果。后续微型图核对采用同样公式，并由官方程序确认边界计数。

### 5.7 本问论文段落、图表与验收

正文依次写：Task 级通信代价推导 → 激活约束 → 拓扑连续分区命题 → TRS-A 算法 → 全用例结果 → 粒度与关键链分析。主结果包含全部 100 用例的 1–5 核加速比曲线；1 核点使用统一官方单核基准，故为 1。

必须回答三个机制问题：更细分区是否增加边界搬运和激活等待；张量域计数是否比边切割更准确地筛选方案；代理改善是否确实带来官方 Makespan 改善。报告最佳、典型及退化案例，不能只展示最有利的一个 Gantt 图。

## 6. 问题二的模型建立与求解：核内复用与存活区间

### 6.1 从问题一改变了什么

同核所有子图合为一个 Task，跨子图张量可留在片上。因此，本问的驻留域从 Task 变成核；子图仍然有用，因为它通过稳定分桶控制局部顺序，并影响 Spill 和 Pipe FIFO。这里的“合并”没有融合算子或减少算子 cycles。

本问的中心问题是：**怎样在减少跨核复制时，避免因核内张量长时间存活而增加 Spill 和关键路径等待？**

### 6.2 核级张量搬运模型

记 $D_B(t)=\{c(g(v)):v\in C(t)\}$ 为消费核集合，$b_t=c(g(p(t)))$ 为生产核，$r_B(t)=|D_B(t)\setminus\{b_t\}|$。未计 Spill 的搬运量为

$$
V_B^0(t)=
\begin{cases}
s_t|D_B(t)|, & t\text{ 为图输入},\\
s_t\left[2r_B(t)+o_t\right], & t\text{ 有计算生产者}.
\end{cases}
$$

**命题 3。** 对内部张量，官方 B 的每个源核到目标核的连接各插入一对 COPY，因此跨 $r$ 个目标核需要 $2rs_t$，最终输出另加 $o_ts_t$。

这与问题一的 $(1+r)s_t$ 不同：问题二没有把所有目标核共享为一次源端写回。将多个消费者集中到同一目标核只生成一对跨核 COPY；将它们留在生产核则没有这对 COPY。图输入依然是每个消费核各读一次。

定义

$$
V_B^{\rm sched}=\sum_tV_B^0(t)+V_B^{\rm spill},\qquad
V_B^{\rm added}=V_B^{\rm sched}-V^{\rm original}.
$$

官方 Spill 记录中，一次记录的搬运为 $s_t(1+\mathbf1\{\text{本次创建新的 DDR backing}\})$。已经有原始输入 backing 或先前 Spill backing 时，后续 Reload 不重复写出。故不能机械地把每条 Spill 记录都乘以 $2s_t$。

### 6.3 操作级执行与容量约束

对跨核 COPY 对，目标读取开始时间满足

$$
S_{\rm in}\ge F_{\rm out}+500,
$$

同时还需其核内前驱、Pipe 队首和内存依赖全部就绪。同核不同子图不再增加问题一的 100 cycles 切换项。

令 $H_B(\Pi)$ 为官方构图与 Step1/2/3 产生的扩展执行图，包含局部数据依赖、内存复用边、各 Pipe FIFO 边和跨核 COPY 边。真实可行性要求 $H_B(\Pi)$ 可执行，且对每核、每类片上存储、每个时刻 $\tau$：

$$
\sum_{t\ \text{在核 }c\text{ 的 }m\text{ 中驻留于 }\tau}s_t\le C_m.
$$

Spill 是官方用于满足容量的机制，不是算法可以自由指定的变量。当前操作同时需要的输入、输出不能被当作任意可换出的受害者。Step3 采用可分字节额度生成复用依赖，本文无需额外优化真实物理地址碎片。

### 6.4 存活区间为何必须进入模型

对一个候选计划，将候选全局子图顺序中各区间的内部拓扑序依次拼接，再投影到各核。插入只用于代理的边界事件：输入在该核第一次使用前读入；远程输出在生产后按每个目标核各记一个 COPY_OUT 使用事件；最终输出另记一次。此处多个输出事件都紧邻生产者，是固定的时序近似；通信字节仍逐目标核计数。

设 $\mathcal T_c$ 为在核 $c$ 上存在生产或消费需求的逻辑张量集合。每个核本地副本用 $(t,c)$ 标识，定义其首次分配到最后一次本核使用的闭区间 $[\ell_{t,c},u_{t,c}]$，以及该副本的片上类别 $m_{t,c}$。同一事件先分配再释放。同一逻辑张量在不同核分别占用容量，本核多个消费者共享一个逻辑驻留区间。

由区间扫线得到

$$
\widehat L_{c,m}(i)=\sum_{t\in\mathcal T_c}s_t\mathbf1\{m_{t,c}=m,\ \ell_{t,c}\le i\le u_{t,c}\},\qquad
P_B=\sum_{c,m}\left[\max_i\widehat L_{c,m}(i)-C_m\right]_+.
$$

输入跨多次本核使用时保持同一逻辑驻留区间。该估计表达顺序对压力的影响；真实 reverse DFS、稳定分桶、Spill 和 Pipe 重叠产生的峰值及代价由官方给出。$P_B$ 不是 Spill 字节数，不能放进主结果表冒充官方字段。

### 6.5 分核代理与 TRS-B 算法

构造计算操作代理图：将候选全局子图顺序中各区间的内部拓扑序依次拼接，保留计算依赖，并按该顺序给同核同计算 Pipe 的操作加串行边。跨核张量依赖的代理延迟按 $500+2s_t/60$ 计；同一操作对之间有多个待传张量时，先把其字节求和，再加一次 500。使用该图最长路径记为 $\widehat L_B$。它没有复现真实 COPY 重叠、FIFO 或带宽事件，因此仅为路径排序代理。

各核 M/V 总负载记为 $W_{c,M},W_{c,V}$。定义

$$
J_B(\Pi)=\max\left\{
\max_{c,q\in\{M,V\}}W_{c,q},\ \widehat L_B,\ \frac{\sum_tV_B^0(t)}{60}
\right\}+\frac{2P_B}{60}.
$$

不同张量被切到同一目标核时，应先更新消费核计数再计价，不能对每条算子边单独累加传输。代理中的同步和存活项用于候选选择；最终目标仍为 $F_B$。

TRS-B 的具体步骤如下：

1. 复用全局拓扑序和三档连续区域，重新以核驻留域建立代价，不直接照搬 A 的最优分核。
2. 按区域顺序放置。维护每核 M/V 已分配工作量、张量消费核计数和已放置操作的代理结束时间。试放当前区域时按其内部拓扑序扫描，操作的代理开始时间取数据前驱完成加 §6.5 传输延迟、该核同 Pipe 上一操作完成两者的最大值，再加 $w_v$ 得到完成时间；扫描后回滚试放状态。对每个核比较“已放置部分的最长路径、最大 Pipe 负载、已确定的边界搬运/60”三者的最大值；平局时依次选择较小的最大 Pipe 负载、较小核编号。未放置消费者不提前算到任何目标核，未放置操作也不提前占用 Pipe。
3. 完成全图初始分配后，计算完整 $P_B$ 与 $J_B$。这一步使未来消费者及存活区间全部进入评分。
4. 至多两轮局部改进。候选区域按“是否在一条最长代理链上、是否参与估计峰值超容区间、关联跨核张量字节数、区域编号”排序，前三项降序、编号升序，取前 8 个尝试迁核；关键链并列时按前驱操作 id 固定选择。另按 $B(i)$ 降序、切点位置升序取至多 8 个边界，左右各移动一个操作。每个候选保持区间连续和全局顺序，重算受影响张量域与完整代理，接受严格最好的一个，候选同分时按其枚举顺序选择。
5. 三档候选按 $J_B$ 去重排序，用官方 B 评估取得有效解。记录官方 Spill 字节和 `memory_peak_by_core`，用它们检验容量代理，而不是再实现另一套 Spill 决策器。

当需要核对局部顺序如何产生时，直接调用或追踪官方 `_build_scene_b_tasks` 内的 Step1 → `_prioritize_task_seq` → Step2 → Step3。求解代码不复制这些私有实现，也不以修改官方代码来迁就代理。

### 6.6 增量统计与复杂度

共享数据包括 `tensor_producer[t]`、`tensor_consumers[t]`、`region_ops[j]`、`region_tensors[j]`、`consumer_count[t][domain]`、`core_of_region[j]` 以及每核 M/V 工作量。计数表保存关联次数，只有域计数从 0 变 1 或从 1 变 0 时，才改变该张量的消费域数。

一次区域迁核只需扫描该区域关联的张量，就能精确更新边界字节；记其关联数为 $I_j$，该部分为 $O(I_j)$。但最长路径、局部顺序和存活压力会传播，首版直接对候选重扫全图，不能把整次改进标为 $O(I_j)$。

设 $M$ 为实际生成的局部候选总数；三档、两轮、每轮 $8(K-1)+16$ 个候选时，$K\le5$ 给出 $M\le288$。解析、关键路径和扫线为 $O(n+I+|E|)$；拓扑窗口排序为 $O(h(n\log n+I))$，其中 $h=8$ 固定。使用每核顺序列表、张量事件差分和 DAG 动态规划时，一次完整代理重算为 $O(n+I+|E|+S^2)$，总代理成本上界写为

$$
O\!\left(h(n\log n+I)+(3+M)(n+I+|E|+S^2)\right).
$$

内存以 $O(n+I+|E|+S^2)$ 级结构为主，逐案例处理。对 35,705 个计算操作的最大案例也不保存数百份完整图，只保留当前状态、可回滚的局部修改和至多三份最终计划。

官方评估成本另计。A 构图会对每个子图扫描张量表，具有 $O(S|T|)$ 项；官方排序、列表查找、Spill 和事件模拟也有额外开销。上述代理复杂度不能被写成官方评估的复杂度或实测运行时间。

### 6.7 说明性手算：少通信不等于少耗时

沿用问题一的 $a\to t\to b$，问题二把两个子图放在同核时可直接复用，局部链仍为 **1800 cycles**；跨核时为 $1000+200+500+200+800=\mathbf{2700}$。这说明同核跨子图在两问中具有不同代价。

再构造一个 UB 例子，容量为 131072 bytes。操作 $a$ 产生大小 81920 的 $x$，$b_1,b_2$ 都读取 $x$；独立链 $d\to e$ 使用另一个 81920 bytes 张量 $y$。所有其他同时存活数据在例子中忽略，且 $x$ 是没有 DDR backing 的内部张量。

顺序 $a,b_1,d,e,b_2$ 在 $d$ 分配 $y$ 时需要同时保留 $x,y$，总计 163840，大于容量。$y$ 属于当前操作，不能作为受害者；$x$ 之后仍被 $b_2$ 使用，因此需要一次写出和一次读回，合计 **163840 bytes**。仅其连续带宽服务需求就为 $163840/60\approx2730.67$ cycles；两个独立孤立 COPY 分别取整时合计 2732 cycles，实际重叠与竞争由官方决定。

合法地改为 $a,b_1,b_2,d,e$ 后，$x$ 在 $y$ 分配前释放，该例中的 Spill 消失。两种顺序的计算量、分核和原始切边完全相同。这个例子为存活区间模块提供直接动机，后续实验必须检查真实用例是否出现同类机制。

## 7. 问题三的模型建立与求解：FIFO 驻留阶段与读取时机

### 7.1 本问的新增状态

问题三继承 B 的 Task、跨核 COPY、500 cycles 同步和 Spill。Cache 只改变符合条件 COPY_IN 的读取路径和对应带宽池。输入、跨核中间量和 Spill Reload 均可参与查找；键取非 DDR 输出 tensor 的 `logical_tid`，没有该字段才使用其 `id`。

查询发生在 COPY_IN **发射时**。多个核在首次读取完成之前同时查询同一键，可能全部 miss；官方没有把这些在飞 miss 合并为一份请求。命中不刷新 FIFO 顺序，COPY_OUT 不填充只读 Cache。

所有 COPY_IN 完成时都会执行插入逻辑，包括此前命中的操作。如果其键仍在 Cache，插入直接返回；如果该键在传输期间被淘汰，完成时可重新插入。大于容量的张量不进入 Cache。该完成事件规则必须保留，不能把实现简化成“只有 miss 完成才插入”。

### 7.2 FIFO 驻留阶段的数学描述

把一个键 $t$ 成功进入 FIFO 到被淘汰的这段时间称为一次驻留阶段。设其插入事件为 $a$，容量为 $C_{\rm cache}$。令 $B_{\rm after}(a,\tau)$ 为在该次插入之后、查询事件 $\tau$ 之前，所有**实际成功追加到 FIFO 队尾**的事件字节之和；已在队内而返回的重复插入、hit 查询和超过容量的对象均不计入。若同一键被淘汰后再次成功插入，应计作新的事件。

**命题 4。** 在同一驻留阶段内，$s_t\le C_{\rm cache}$ 且没有其他删除机制时，$t$ 在查询时仍驻留的条件是

$$
s_t+B_{\rm after}(a,\tau)\le C_{\rm cache}.
$$

**证明。** FIFO 中在 $t$ 之后追加的项不可能先于 $t$ 被淘汰。只要这些较新项与 $t$ 的大小和不超过容量，淘汰较老项即可容纳它们；一旦超过容量，较老项全部移除后仍不够，$t$ 必被淘汰。该条件以实际成功插入序列为对象，不能把所有读取请求或所有不同键访问量代入。

真实查询还必须晚于该驻留阶段的插入事件。若 $t$ 已经结束一个驻留阶段，需要用最新阶段重新判断；同一时刻的退休、插入和发射按官方事件顺序解释。

这个命题把算法目标变得具体：让后续使用落在首次完成之后、FIFO 淘汰之前，并同时控制为此造成的计算延迟。

### 7.3 命中率、额外搬运与 DDR 字节的区分

固定同一个计划 $\Pi$，A/B/C 的构图及 Spill 口径中，问题三的静态调度 COPY 总量记为 $V^{\rm sched}$。令 $H$ 为实际命中的 COPY_IN 总字节。则 Cache 提供的读取字节为 $H$，物理 DDR 搬运字节可由

$$
V^{\rm DDR}=V^{\rm sched}-H
$$

得到，并用时间线的 `memory_path` 与 COPY 字节核对。零字节操作仍可能有最小 1 cycle，其时延由官方保留，不影响字节等式。

官方字段 `data_movement_bytes.added_copy_bytes` 在模拟前就由边界和 Spill 静态构图算出，**不会减去 Cache 命中**。报告时原样保存它，并把推导的物理 DDR 字节作为另一列。官方 Cache 命中率为

$$
h_{\rm byte}=\frac{H}{H+M},
$$

$M$ 是 miss 的 COPY_IN 字节。按次数的命中率可以附报，不能替换官方字节口径。

两个独立带宽池给出资源服务下界

$$
F_C(\Pi)\ge\max\left\{\frac{V^{\rm sched}-H}{60},\frac{H}{250}\right\}.
$$

计算、依赖、同步与队首等待可使实际时间更大。因而最大化 hit rate 不是本问的目标；算法只接受降低 $F_C$ 的方案。

### 7.4 TRS-C：利用事件诊断做有限合法调序

先把 TRS-B 的有效计划 $\Pi_B$ 在 Cache 硬件上评估一次，得到同计划硬件对照和初始 $F_C(\Pi_B)$。分析官方 `cache_events` 与 `per_core_timeline`，将有重复使用的键按以下机制分类：首次完成前的重复 miss、插入后被容量淘汰再 miss、正常 hit。该分类只在实际事件中计算，不用静态扇出推算命中率。

候选只改子图顺序，不提交等待时间或预取：

1. 在每核顺序中枚举相邻子图对。尝试交换它们在全局子图顺序中的位置，要求交换后的全局顺序仍满足所有子图依赖；随后投影回各核。核序列完全相同的计划按内容去重。
2. 只统计大小不超过 Cache 容量的键。按基准 `cache_events` 的原有顺序识别两类机会：该键尚无成功插入、已有另一笔更早发射且未完成的 miss 时发生的重复 miss；该键曾插入、最近一次驻留因淘汰结束后发生的 miss。前者对应读者后移，后者对应读者前移。事件同刻时保留官方列表顺序。
3. 以 `(core_id, op_id)` 将每次查询关联到官方操作时间线中的 `subgraph_id`。令 $E_{\rm pot}$ 为候选交换中满足上述移动方向的受影响 miss 事件，每个事件最多计一次；定义 $\widehat H_{\rm potential}=\sum_{e\in E_{\rm pot}}\operatorname{bytes}(e)$。一次读入即使被多个子图使用，也只按官方赋予该 COPY_IN 的子图统计一次。该量是潜在改善机会的启发统计，不预测真实命中，也不是节省字节的理论界。
4. 按候选新顺序重建 §6.5 的代理图，计算 $\widehat D_{\rm chain}=[\widehat L_B(\Pi')-\widehat L_B(\Pi)]_+$。定义 $J_{\rm swap}=\widehat H_{\rm potential}(1/60-1/250)-\widehat D_{\rm chain}$，按分数降序、潜在字节降序、交换子图编号升序排序，最多保留 8 个候选。不在预筛时预测新查询时间；新的 hit/miss、Spill 和时间传播全部重新由官方计算。
5. 全部 500 个案例与核数组合均生成初始有效 Cache 结果并诊断。额外评估只分配给有候选且分数为正的组合；基础实验包最多验证 12 个候选，具体全局选择按上述分数排序，时间许可再扩展。每个组合首轮最多验证一个候选，避免把预算集中到单例。
6. 候选通过完整 Q3 官方评估且严格降低 Makespan 时才接受；否则保留原计划。对接受的变化计划补跑 B，得到该计划自身的无 Cache 对照。实验预算为全部尝试都预留这次 B 评估的上界。

```text
TRS_C(base_result_B, official_trace_C, allocated_extra_budget):
    base_plan_B <- base_result_B.plan
    episodes <- FIFO_residency_episodes(official_trace_C.cache_events)
    failures <- classify_repeated_misses(episodes, official_trace_C)
    swaps <- legal_adjacent_core_order_swaps(base_plan_B, failures)
    swaps <- top_8_positive_screened_swaps(swaps)
    best <- evaluated_base_plan_B_on_cache
    matched_no_cache_result <- base_result_B
    for trial in allocated_subset(swaps):
        result <- official_evaluate_C(trial)
        if valid(result) and result.makespan < best.makespan:
            best <- result
    if best.plan differs from base_plan_B:
        matched_no_cache_result <- official_evaluate_B(best.plan)
    return best, matched_no_cache_result
```

Cache 方案的改进属于受预算限制的 anytime 搜索。只采用原始 B 计划的组合仍有完整有效结果；报告调序实际覆盖的组合数、全部尝试和预算，不能把少量选择性调序描述成 500 个组合均执行了同等搜索。

### 7.5 两种对照必须分开

**硬件对照：** 固定 $\Pi_B$，比较 $F_B(\Pi_B)$ 与 $F_C(\Pi_B)$，回答“只增加只读 Cache 有何影响”。覆盖全部 100 用例、1–5 核。

**调度对照：** 比较 $F_C(\Pi_B)$ 与 $F_C(\Pi_C)$，回答“Cache 事件引导的合法调序有何影响”。同时给出 $F_B(\Pi_C)$，判断该收益是否来自一般顺序变化。对预算未分配调序的组合，$\Pi_C=\Pi_B$，如实保留。

若用分别优化后的无 Cache 与 Cache 方案作最终性能对比，将其命名为“硬件与调度联合效果”，不把二者差值全部归因于 Cache。

### 7.6 说明性手算：FIFO 与同时 miss

取官方 Cache 容量 1048576 bytes。张量 $x,y,z$ 分别为 524288、393216、262144 bytes。按先后完成的独立读取，先插入 $x$、再插入 $y$，使用 917504 bytes；接着读取 $x$ 命中并完成，FIFO 次序仍为 $[x,y]$。随后插入 $z$，总需求 1179648，必须先淘汰 $x$，队列成为 $[y,z]$，占用 655360。此后再查 $x$ 将 miss。这个顺序中的 hit 在插入 $z$ 前已经完成，故不存在命中传输完成后重插的歧义。

若两个核在空 Cache 中同时发射对 $x$ 的读取，两次查询都发生在任何填充完成之前，因此都 miss。共享输入相同没有使第二次读取自动命中。只有通过合法顺序让后一个查询落到第一个完成之后，并且期间没有淘汰，才获得复用机会。

例子使用大于当前数据最大张量的说明性对象来清楚展示容量关系，不作为官方数据分布或真实性能证据。正式机制图用实际用例的事件绘制。

正文顺序为：B 模型继承关系 → 发射查询与完成插入 → FIFO 驻留命题 → 事件诊断与合法交换 → 同计划硬件结果 → 调序效果及代价。

至少输出逐用例 Makespan、官方额外搬运、Cache 字节命中率和 1–5 核无 Cache/Cache 对比。机制图同时展示首次填充前 miss 字节、容量淘汰 miss 字节、关键链延迟和真实 Makespan。只有 hit rate 上升而 Makespan 未下降时，不能把它列为成功调度。

### 8.2 假设、实验和结论调整规则

**H1：边代价失真主要出现在同一张量多消费者落入重复驻留域时。** 模型核验使用冻结候选池：对每个诊断设置，将完整方法、无域计数消融及已有基线已经评估的最终计划合并去重，两个代价模型在同一池上重评分，比较边界字节误差和方案排序，复用已有官方结果。端到端消融则保持相同初始区域、邻域规则和候选次数上限，允许实际接受路径及后续候选不同，比较整个决策过程的最终 Makespan。静态机制量使用

$$
R_{\rm dup}=\frac{\sum_t s_t\bigl(|C(t)|-|D(t)|\bigr)}{\sum_t s_t|C(t)|},
$$

分母为 0 时单独标为无消费者情形。$D(t)$ 按 A/B 分别取消费 Task/核集合；该指标衡量边展开重复，不代表可实际节省的总字节。若域模型纠正字节数却没有改善方案选择，C1 的有效性结论只保留代价建模与解释能力，不写调度收益。

**H2：延长的核内张量存活会抵消跨核通信收益。** 在 B 上固定划分候选范围与官方评估次数，比较完整模型和去存活项版本，同时观察 $P_B$、官方 Spill 和 Makespan。若代理压力与官方 Spill 无稳定对应，先检查输入/输出同时占用及官方分桶顺序；修正后仍无效则删除该评分项，保留实际观察到的容量分析，不为维持叙事增加新启发式。

**H3：可挽回的重复 miss 是时序问题，而非仅由共享输入数量决定。** 用相同 `cache_events` 定义比较原顺序与新顺序，确认被目标化的 miss 是否转为 hit，以及提前/推迟是否延长计算关键链。如果没有可表达的合法交换，记录为该机制无可用自由度；不写成算法搜索失败。

### 8.3 最小但有区分力的基线

1. **官方单核基准。** 调用 `singlecore_evaluate.py` 的统一口径，为 Q1/Q2 所有核数提供共同分母。官方示例 stub 只用于理解接口，不当作高性能基线。
2. **负载均衡基线。** 使用与 TRS 相同的固定拓扑序和当批允许的粒度集合，仅按每核 M/V 最大工作量贪心放置；同核顺序为全局投影。多档候选按该负载分数选一个进入官方评估，不追加完整方法没有的评估次数。
3. **HEFT-style 适配基线。** 同一批区域，按向上秩的就绪顺序放置，枚举核的代理最早结束；通信使用各问真实边界规则，不额外加入存活与 Cache 调序。并列秩以 id 确定，始终保存一个全局拓扑放置顺序并投影到各核；多档候选按该完成时间代理选一个进入官方评估。所有方法的生成墙钟另行计入，不能只比较评估次数。
4. **无驻留域计数消融。** 保持完整方法的初始区域、邻域规则与次数上限，只把外部消费域数换成外部消费者操作数，写回及最终输出规则保持原样。其缺陷是被测试的干预，不改官方评价。
5. **无存活项消融。** 保持其他步骤及候选预算，令 $P_A=P_B=0$。若候选顺序因此改变，重新生成整个求解轨迹，不能只在最终选中计划上删除日志中的一项。

前两个启发式基线属于明确可实现的比较方法，不能被称为完整 Alpa、DNNFusion 或 TASO 复现。那些系统拥有本题不允许的优化自由度，无法作为相同接口下的直接可运行对照。

为使去域计数干预唯一，定义 $d_A(v)=g(v)$、$d_B(v)=c(g(v))$，以及 $k_X(t)=|\{v\in C(t):d_X(v)\ne d_X(p(t))\}|$。有计算生产者时，消融模型为

$$
V_{A,\rm edge}^0(t)=s_t\left[k_A(t)+\mathbf1\{k_A(t)>0\lor o_t=1\}\right],\qquad
V_{B,\rm edge}^0(t)=s_t\left[2k_B(t)+o_t\right].
$$

图输入在两种消融中均计 $s_t|C(t)|$。这样只移除同一消费域内的读入合并，不同时改变 A 的源端一次写回规则。冻结池只用实际已有官方结果，增加重评分不增加官方评估次数。

### 8.4 指标与统计口径

用例 $i$、核数 $K$ 的加速比为

$$
S_{i,K}^{A/B}=\frac{T_i^{\rm official\,1core}}{T_{i,K}^{A/B}},\qquad
\overline S_K^{A/B}=\frac1{100}\sum_{i=1}^{100}S_{i,K}^{A/B}.
$$

不把平均单核时间除以平均多核时间作为题目要求的平均加速比。Q1/Q2 的 1 核曲线点按统一基准定义为 1。Q3 的 1 核无 Cache 使用 B 入口与同计划比较，不将它自动等同于 official singlecore 的场景 A 时间。

并行效率可附报 $\overline S_K/K$，但固定启发式基准下加速比可能超过核数，不能直接认定为错误。额外报告中位数、10% 分位、最差加速比和合法结果覆盖数，以展示异质性。

算法为确定性方法；一次正式结果不需要伪造多 seed。墙钟性能按相同案例组合重复计时估计系统波动，官方模拟 cycles 与宿主墙钟秒数分列。对 100 个用例进行配对 bootstrap 时，区间反映这组用例的结构差异，不解释为模拟器随机误差或所有未来模型的总体保证。

### 8.5 逐问取舍与停止规则

本地冠军研究强调“比较应改变后续决定”。本方案采用下列明确规则，普通参数在六例计时后固定，不用看到结果后再挑有利口径。

| 观察到的情况 | 采取的决定 | 保留的证据 |
|---|---|---|
| Q1 更细划分只有更多 Task、搬运和激活，真实时间不降 | 不继续细化该实例；保留当前已评估的更粗方案 | 三档中实际评估的计划、边界字节、时间 |
| Q1 字节模型更准确但代理排序未改善 | 保留精确计数，调整对其性能贡献的表述；不盲目换全局优化器 | 冻结候选池中的字节误差与排序 |
| Q2 去掉存活项效果相当，且容量诊断未显示相应收益 | 删除无收益评分项，按同一修改后的方法重生成受影响结果 | 完整/去项的同规则对照与实际耗时 |
| Q2 代理下降而官方时间上升 | 拒绝该官方候选，检查变化来自 Spill、Pipe 还是同步 | 旧新计划、真实时间与官方分解 |
| Q3 hit 上升但时间不降，或合法交换无机会 | 保留原 B 计划在 Cache 上的结果，停止该组合的额外搜索 | 事件分类、时间变化及已用评估次数 |
| 任一题仍缺有效用例，或必要矩阵的剩余时间不足 | 先补齐输出及错误修复，暂停新增算法和扩展对照 | 未完成组合和更新后的墙钟预测 |

相同官方 Makespan 时保留先前有效方案，避免只为变动而变动。任何方法定义的删除或修改，都同步更新方法名称/配置、正文、图表与结果选择，不能把旧方法的最佳数值混入新方法。

固定图、计划和配置下的模拟 cycles 是确定性输出；宿主墙钟的波动需要重复计时，不能用墙钟噪声解释模拟 cycles 的退化。

### 9.3 核心对照与总次数上界

结构诊断集使用上述六例、核数 2/5、A/B 两场景，构成 $6\times2\times2=24$ 个设置。负载均衡、HEFT-style、无驻留域计数、无存活项各运行一次，共 **96 次**。完整方法对应结果从主结果复用。

Q3 基础优化包最多验证 **12 个** Cache 调序候选，并为它们分别准备 B 的同计划对照上界 **12 次**，合计 **24 次**；重复候选直接复用已有结果，实际次数可少于上界。未通过或未改善的候选也计入搜索开销。

另预留 **24 次**用于失效候选的备用计划、必要复核及关键微型图的官方核对；微型图调用同样计时计次。于是完整基础实验包规划为

$$
1500+6+96+24+24=\boxed{1650\text{ 次官方评估上界（按当前备用额度）}}.
$$

备用额度是时间规划，不是允许丢弃失败用例的门槛。出现更多未解决用例时，先完成所需有效输出并更新耗时预测，报告实际超出次数。

六例对照支持机制诊断，不足以声称在 100 例上全面战胜其他算法。若计时允许，优先把负载均衡和 HEFT-style 扩展到全部 100 例、2–5 核、A/B：完整基线需要 $2\times100\times4\times2=1600$ 次，其中已有 48 次可复用，故新增 **1552 次**。扩展是否执行由剩余墙钟和吞吐判断，表中如实区分六例诊断集与全体主结果。

### 9.4 墙钟预算怎样核算

| 环节 | 分配上限 | 包含内容 |
|---|---:|---|
| 首批计时和并发校准 | 0.4 h | 54 次可复用计时、6 次并发复测及配置决定 |
| 全图解析与方案生成 | 0.6 h | A/B 候选、增量统计、顺序与计划输出 |
| 剩余完整主评估 | 4.3 h | 扣除已完成首批后的必要 1500 次覆盖 |
| 核心基线与消融 | 0.9 h | 96 次结构诊断对照 |
| Cache 定向优化与匹配对照 | 0.6 h | 最多 24 次基础包评估及事件分析 |
| 汇总与论文所需图表数据 | 0.6 h | 算术平均、同计划配对、机制指标和绘图 |
| 备用修复与复核 | 0.6 h | 备用计划、异常定位、完整输出核验 |
| **总计** | **8.0 h** | 所有问题共享此窗口 |

用实测任务吞吐预测，而非直接用进程数除耗时。若串行同批时间为 $T_1$、双进程墙钟为 $T_2$，有效并行度为 $p_{\rm eff}=T_1/T_2$。按小图、常规图、大图/深图分层，设每层剩余任务数为 $N_b$、单任务实测秒数为 $\widehat t_b$，则

$$
\widehat T_{\rm remain}=T_{\rm generation}+\sum_b\frac{N_b\widehat t_b}{p_{{\rm eff},b}}+T_{\rm analysis}+T_{\rm reserve}.
$$

每个案例已完成的评估实时从 $N_b$ 中扣除。预测偏紧时依次：取消全体扩展基线；取消额外候选重评；把三档降为固定 $\rho=8$、两轮局部搜索降为一轮；减少 Cache 可选修正。始终先保留全部题目要求的 1500 个基础组合。

举例说明可核算性：若剩余 1446 个主任务平均 10 秒、有效并行度 1.6，则仅该项约 2.51 小时；若平均 30 秒，则约 7.53 小时，尚未含其他工作，原八小时安排就不成立。这是条件演算，不是机器性能估计。若必要组合本身超过窗口，应报告实际预算冲突并优先完整覆盖，不删除大图或改用代理填结果。

题面所说单例约 5–10 分钟是可接受的求解尺度提示，不代表 100 例、多场景、多核数都能各占满这个额度。方案生成、重评次数和并发必须按总墙钟统一控制。

### 10.5 可以直接借鉴的方法介绍

> 我们以张量驻留域组织多核划分与调度。对于子图独立执行的场景，以消费 Task 数计算张量的边界搬运，并将同核切换和跨核激活纳入任务依赖模型；对于同核子图合并的场景，将驻留域扩展到核，按源核与目标核对建立通信代价，同时利用张量存活区间刻画片上容量压力。在此基础上，沿拓扑序生成有限数量的连续区域，通过关键路径、Pipe 负载和搬运需求选择分核方案。共享只读 Cache 场景进一步使用官方事件轨迹识别首次填充前的重复读取与 FIFO 淘汰，对可交换的子图顺序进行定向调整。局部候选先按代理筛选，进入最终比较的计划由原始官方评估器检验，并以真实完工时间选择；正式输出只采用通过完整官方评估的计划。
