## 本题事实底座：据题面与当前附件核对，不随版本改写

原始材料为《通用神经网络处理器下的多核调度问题.docx》和同名附件 ZIP。附件实际含 `README.md`、`code/`、`data/`、`docs/`；当前上传版本有 `data/case_001.json` 至 `data/case_100.json` 共 100 个用例。本地存在更新材料时先识别对应版本，不能把旧包清点结果冒充新包结果。

**决策和输出。**联合决定非 COPY_IN/COPY_OUT 操作的子图归属、子图分核和同核子图顺序。提交 JSON 顶层必须且只能包含 `node_to_subgraph` 与 `core_schedules`；覆盖与唯一性、子图依赖无环及执行顺序满足题意。操作发射时刻、内部缓存替换策略不是提交接口可直接控制的自由变量。

**问题 1。**场景 A，一个子图就是一个 Task。所有跨子图数据都经 DDR 中转，包括同核不同 Task；同核前一 Task 完成后至少等待 100 cycles，跨核前驱 Task 完成后至少等待 1000 cycles，激活时刻取相关约束的最大值。

**问题 2。**场景 B，同核全部子图合并为一个 Task；同核数据可驻留复用，但占用 L1/UB，必要时产生换入换出。跨核边通过 COPY_OUT/COPY_IN 传递，目标 COPY_IN 在源 COPY_OUT 完成并经过 500 cycles 同步延迟后才具备相应就绪条件。

**问题 3。**在场景 B 上增加共享只读 FIFO Cache。COPY_IN 发射时查询逻辑 tensor id；命中不刷新 FIFO 顺序，未命中从 DDR 读取并在完成后按规则插入，容量不足时先进先出淘汰。Cache 与 DDR 分别共享各自带宽，不是 LRU，不是固定的“DDR 带宽 + Cache 带宽”。具体可缓存对象和并发访问按原始代码核对，不自行设计写回策略或未提交的预取操作。

**固定资源。**L1 = 524288 bytes；UB = 131072 bytes；共享 DDR = 60 bytes/cycle；只读 Cache = 1048576 bytes、250 bytes/cycle。正式结果使用原始 `data/config.txt`，不为改善成绩修改配置。

**评估机制。**官方程序重建边界搬运、生成核内确定顺序与换入换出、形成 Pipe 和内存复用依赖，再进行多核事件模拟。最终 Makespan 考虑动态共享带宽；核内参考时间、静态通信量估算和代理分数不等于最终结果。子图 DAG 只是合法性的一部分，加入核内顺序、Pipe 顺序、跨核 COPY 与内存复用依赖后仍需可执行。也不能仅凭核心之间互相传数据就判定操作级死锁。

**统计与计算预算。**问题 1、2 需要题目要求的全部用例和核数，1～5 核曲线采用统一官方单核基准，2～5 核生成多核方案；平均加速比是逐用例加速比的算术平均。问题 3 需要 1～5 核下无 L2 与只读 Cache 的对比，并报告逐用例 Makespan、额外搬运量、Cache 命中率。硬件对照与分别优化后的方案对照要区分。固定启发式单核基准可能使多核加速比超过核数，不能自动视为错误。题面建议避免暴力迭代搜索，以单个用例约 5～10 分钟给出结果为佳。

关键原文位置：题面 §1.3～1.5、问题 1～3、附录 B.4～B.6、附录 C～D。关键代码：`singlecore_evaluate.py`、`multicore_cut_evaluate_problem_1.py`、`multicore_cut_evaluate_problem_2.py`、`multicore_cut_evaluate_problem_3.py`、`schedule_step1.py`、`schedule_step2.py`、`schedule_step3.py`、`evaluation_validation.py`、`contest_io.py`。这些文件均在附件 `code/` 下；示例 `stub_multicore_cut_and_schedule.py` 只演示接口，不是性能基线。

## 完整 Idea 的统一正文结构

按以下顺序写实质内容，标题可换成自然中文，不把它变成一堆待填表格。

1. **用一段人话讲清楚 Idea。**这题难在哪里，我们具体怎样切、怎样分核、怎样排，核心改进为什么与官方计时有关。
2. **题意与瓶颈。**输入、真实决策、三问差别，以及有材料支持的主要计算或通信矛盾。
3. **参考方法及本题的改动。**用少量真实原文说明借鉴什么、为什么适用、哪里不能照搬；把来源集中列清楚。
4. **核心主线与贡献。**选择一个主方法，讲清机制间的关系，而不是罗列独立模块。
5. **数学模型。**符号、变量、目标、约束、必要假设；真实评估目标与求解代理分开，量纲和计数口径一致。
6. **可执行的求解过程。**初始化、候选生成、打分或接受、状态更新、结束条件、参数来源、关键数据结构和伪代码。复杂度说明按实际图规模和候选范围计算。
7. **问题 1、2、3 如何递进。**明确哪些结构共享、哪些代价或策略改变，不能用一个通信公式覆盖三种机制。
8. **小图解释。**用一个明确标为“说明性手算”的小例子走过关键决策；不把该例子或代理分数冒充官方实测结果。
9. **后续实验与 8 小时预算。**必要基线、全部正式组合、少量核心对照、耗时核算、最小验证顺序；当前阶段只设计，不执行。
10. **论文怎样讲。**模型名称、章节主线、必须回答的几个机制问题、题目要求的图表，以及一段可直接借鉴表达方式的方法介绍。不编造结果段。
11. **交给 Codex 的实现蓝图。**建议模块、输入输出、关键函数职责、数据依赖和实现顺序。拟建接口明确标为拟建；官方接口引用真实文件，不假装代码已经存在。
12. **必要的文末说明。**实际来源与页码、真正未取得的材料或未实测事项，以及本版本的几项重要变化。没有的问题不凑数。
