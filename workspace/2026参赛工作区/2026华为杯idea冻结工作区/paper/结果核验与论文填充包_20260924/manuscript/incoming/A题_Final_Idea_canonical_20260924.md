# A题 Final Idea：张量驻留与查询时序驱动的多核调度

题目：2026 年“华为杯”中国研究生数学建模竞赛 A 题《通用神经网络处理器下的多核调度问题》  
定稿日期：2026-09-24  
使用方式：第 1至7 节给出完整模型和算法，第 8至10 节安排实验与初稿，第 11 节对接现有代码，第 12 节集中列出来源和实施进度。

## 1. 先用人话说明：我们到底怎么做

这道题要安排一张计算图在多个核心上运行。把计算拆开，可以让几个核心同时干活，但数据也要在核心之间来回搬；把有关联的计算放在一起，可以复用数据，但同一时刻留在片上存储中的数据太多，又会被迫搬出去、再搬回来。我们围绕这个取舍做三件事：**先算清一份数据要送到哪些地方，再决定计算怎么切、放在哪个核心，最后调整先后顺序，让数据尽早用完、空间尽早释放。**问题三加入共享 Cache 后，还要关注各核心什么时候读同一份数据：前一次读入完成后，后一次读取才有机会命中 Cache。

具体做法是从四种有明确含义的划分出发，用迁移计算块、拆分或合并计算块、调整同核顺序来改善方案。计算过程中先快速估时，再调用官方核内调度得到实际换入换出，最后用官方多核模拟比较方案的总完成时间。容量压力明显下降、共享数据查询时间发生变化的方案，也会进入比较。这样，算法既寻找更多并行机会，也处理数据搬运、片上容量和 Cache 访问时序带来的代价。

三问各有一个清楚的研究问题：

| 题目 | 需要回答的问题 | 主要调整 |
|---|---|---|
| 问题一 | 多切一块带来的并行，能否抵消新增搬运和 Task 等待？ | 子图大小、分核、Task 顺序 |
| 问题二 | 同核数据可以复用后，怎样兼顾负载和片上容量？ | 接收核心数、张量存活时间、同核子图顺序 |
| 问题三 | 有了共享 Cache，怎样安排共享输入的消费者和读取顺序？ | 消费者聚合或分散、查询先后、两类带宽的使用 |

本文把一份张量能够共享片上副本的计算范围称为**驻留域**。问题一的驻留域是一个子图 Task；问题二、三的驻留域是一个核心上的合并 Task。这个概念把三问连起来，也让“为什么这样切、为什么这样分核”能够用字节数和执行时间解释。

## 2. 题目给了什么，我们决定什么

### 2.1 输入、输出与共同目标

输入是 100 张计算图 `case_001`至`case_100`。图中有操作和张量：操作给出计算周期 `cycles` 和所属流水线 `pipe`，张量给出存储位置 `pos` 和大小 `size`。下文把张量理解为一份需要保存和传递的数据，把 Pipe 理解为核心内部负责某类操作的执行通道。

我们决定三个量：

- $g(v)$：计算操作 $v$ 属于哪个子图。
- $a(s)$：子图 $s$ 放在哪个核心。
- $\sigma_k$：核心 $k$ 上各子图的先后顺序。

记整个方案为 $X=(g,a,\sigma)$。实现时提交如下两个字段：

```json
{
  "node_to_subgraph": {"计算操作id": 0},
  "core_schedules": [[0], []]
}
```

`node_to_subgraph` 覆盖全部非 COPY 操作；每个非空子图在一个核心的列表中出现一次，空核对应空列表。操作的具体发射时刻、换出对象和 Cache 替换由官方评估器计算。

官方程序依次重建搬运操作、安排核内顺序、插入换入换出、建立 Pipe 和内存复用依赖，再模拟多核共享带宽。记它给出的总完成时间为 $F_r(X)$，即 Makespan，$r\in\{A,B,C\}$ 分别对应三问。我们的选择目标是

$$
\min_X\bigl(F_r(X),Q^{\mathrm{add}}(X)\bigr).
\tag{1}
$$

两个量按顺序比较：先选择总完成时间更短的方案，时间相同时选择额外搬运字节更少的方案。候选再同分时按规范化计划的固定顺序选择。

方案满足操作完整覆盖、子图唯一分核、子图依赖无环和同核顺序要求。A 进一步检查子图依赖与同核 Task 顺序共同组成的图；B/C 由官方 `validate_execution` 检查展开后的数据、Pipe、内存复用和跨核 COPY 依赖。算法复用这些检查，保留官方返回的具体错误。

### 2.2 三问的实际差别

| 项目 | A：问题一 | B：问题二 | C：问题三 |
|---|---|---|---|
| Task | 每个子图一个 Task | 每个核心一个合并 Task | 同 B |
| 同核不同子图之间的数据 | 经 DDR 中转 | 可以留在 L1/UB 中复用 | 同 B |
| 同步 | 同核前一 Task 完成后等待 100 cycles；跨核前驱 Task 完成后等待 1000 cycles | 跨核 COPY_IN 等源 COPY_OUT 完成，再等 500 cycles | 同 B |
| DDR 带宽 | 60 bytes/cycle，所有读写共享 | 同 A | 同 A |
| 共享 Cache | 无 | 无 | 1048576 bytes；读带宽 250 bytes/cycle；FIFO |

每核 L1 为 524288 bytes，UB 为 131072 bytes。正式实验从原始 `data/config.txt` 读取参数。C 的 DDR 和 Cache 各有自己的服务队列，分别分配带宽。

B/C 的子图列表参与核内顺序构造，各 Pipe 随依赖推进，相邻子图的操作能够重叠。A 的下一个 Task 则需要等待相关整个 Task 完成。

### 2.3 数据结构告诉我们什么

100 张图的非 COPY 操作数最少为 552，中位数为 3720.5，最多为 35705。计算依赖的弱连通分量数中位数为 39.5；对 2至5 核，各有 16 张图的分量数少于核数。`case_016` 有 17995 个计算操作，却只有一个计算依赖分量。因此，算法同时使用“把天然独立分量分给不同核”和“在大分量内部继续切块”两种构造。

这些图中，每个张量至多有一个计算生产者，操作依赖经张量连接，每个原始 COPY 对应一个输入和一个输出张量。后面的搬运公式利用这一结构。原 COPY 的 `cycles=0` 是占位值，搬运时间按字节数和带宽重新计算。

记两类计算 Pipe 的总工作量为 $W_M,W_V$，原图 COPY 总字节为 $Q^{\mathrm{orig}}$。用

$$
r_G=\frac{Q^{\mathrm{orig}}}{60\max(W_M,W_V)}
\tag{2}
$$

描述原始搬运与计算工作量的比例。这个比例用于选取结构不同的代表图。实际完成时间还包括调度产生的搬运、等待与换入换出。

## 3. 问题一：怎样切图，才能让并行收益超过新增开销

### 3.1 先把每份数据的搬运算清楚

设张量 $t$ 的大小为 $b_t$，计算消费者集合为 $C(t)$。$T_{\mathrm{in}}$ 表示图输入，$T_{\mathrm{prod}}$ 表示计算产生的张量，$u(t)$ 是其生产者。图输入用原 COPY_IN 之后的片上张量标识；一个逻辑张量及其 DDR 副本统一计量。若计算结果需要原 COPY_OUT 写回，或没有后续计算消费者，记 $o_t=1$，否则为 0。

问题一中，数据送入几个不同 Task，就需要分别读入几次。对图输入定义 $I_A$，对计算产生的张量定义 $R_A$：

$$
I_A(t)=\{g(v):v\in C(t)\},\qquad
R_A(t)=\{g(v):v\in C(t),\ g(v)\ne g(u(t))\}.
$$

$I_A(t)$ 是图输入的接收 Task 集合，$R_A(t)$ 是计算结果需要送往的外部 Task 集合。集合自动合并同一 Task 内的多个消费者。按官方构图规则，结构搬运量为

$$
Q_A^0=
\sum_{t\in T_{\mathrm{in}}}b_t|I_A(t)|+
\sum_{t\in T_{\mathrm{prod}}}b_t
\left[|R_A(t)|+\mathbf1\{|R_A(t)|>0\ \text{或}\ o_t=1\}\right].
\tag{3}
$$

第一项是输入读取。第二项中，每个外部 Task 读一次，源 Task 写一次；源端这次写出也可以承担最终输出。这个式子直接解释了合并的作用：把两个消费 Task 合成一个，能够减少重复读取；将它们分配到同核但仍保留两个 Task，搬运仍然存在。

### 3.2 Task 激活时间

设 Task $s$ 的激活时间为 $B_s$、完成时间为 $E_s$，$p(s)$ 为同核前一个 Task。它的激活时间满足

$$
B_s\ge\max\left\{
0,\max_{t\in\mathrm{Pred}(s)}E_t,
\max_{t\in\mathrm{Pred}(s):a(t)\ne a(s)}(E_t+1000),
E_{p(s)}+100
\right\}.
\tag{4}
$$

不存在的前驱项省略。某核心列表中的第一个 Task 若没有数据前驱，激活时间为 0；其余按式（4）取最大值。各等待条件取最大值，体现“数据到齐且本核能够开始工作”。

### 3.3 用四个起点寻找合适的切分粒度

| 起点 | 划分 | 作用 |
|---|---|---|
| A0 | 整图一个子图，放核心 0 | 保留完整图作为比较起点 |
| A1 | 将完整计算分量装入 $K$ 个箱，同箱合成一个子图，每核一箱 | 利用天然独立计算，减少 Task 数 |
| A2 | 沿连续支路拓扑序 D 切成最多 $2K$ 块 | 在较大块之间寻找并行 |
| A3 | 沿关键路径优先拓扑序 H 切成最多 $4K$ 块 | 为长依赖链附近的分支提供更细安排 |

起点生成后，先快速估时，再做官方核内展开，选择展开评分最好的起点 $X_A^0$ 做第一次完整评估。接着围绕它尝试迁块、拆并、边界操作迁移和同核调序，分别保留普通改善方案与容量压力下降方案，再与其他起点共同竞争第二次完整评估。最终按式（1）选取结果。第 6 节给出每一步的确定规则。

问题一的切分同时改变并行度、式（3）的搬运、式（4）的等待和每个 Task 内的存储压力。比较这些变化后，才能判断一个新切点是否划算。

### 3.4 这一问要得到什么结果

对 100 张图计算 2、3、4、5 核方案，使用同一官方单核基准形成 1至5 核平均加速比曲线。逐例保存 Makespan、额外搬运量、Task 数和分核方案。结果分析回答：哪些图主要受依赖链限制，哪些图通过切分获得并行，哪些图因为 Task 搬运和等待而偏向较粗的划分。

## 4. 问题二：让数据在同核复用，并尽早释放片上空间

### 4.1 同核复用改变了搬运公式

问题二把同核子图合成一个 Task，驻留域从“子图”变成“核心”。对图输入定义 $I_B$，对计算产生的张量定义 $R_B$：

$$
I_B(t)=\{a(g(v)):v\in C(t)\},\qquad
R_B(t)=\{a(g(v)):v\in C(t),\ a(g(v))\ne a(g(u(t)))\}.
$$

当前官方构图器为每个远端接收核生成一对 COPY_OUT/COPY_IN，最终输出另外写回。因此

$$
Q_B^0=Q_C^0=
\sum_{t\in T_{\mathrm{in}}}b_t|I_B(t)|+
\sum_{t\in T_{\mathrm{prod}}}b_t\bigl[2|R_B(t)|+o_t\bigr].
\tag{5}
$$

把共享同一输入的消费者集中到同一核，可以减少输入接收域；把中间结果的消费者迁到生产者所在核，可以减少跨核写读。操作分核保持不变时，调整子图边界与同核顺序会保持式（5）不变，但可能改变张量占用空间的时间以及实际换入换出。

跨核传输满足

$$
S_{\mathrm{COPY\_IN}}\ge D_{\mathrm{COPY\_OUT}}+500,
\tag{6}
$$

其中 $S$、$D$ 分别表示操作开始和完成时间。

### 4.2 容量为什么必须和顺序一起考虑

一份张量从申请空间开始，到最后一个读者完成才释放；读者包括计算操作和 COPY_OUT。设物理张量版本 $\tilde t$ 的申请、释放时间为 $A_{\tilde t},L_{\tilde t}$。对每个核心 $k$ 和存储区 $m\in\{L1,UB\}$，有

$$
\sum_{\tilde t:A_{\tilde t}\le\tau<L_{\tilde t}}
b_{\tilde t}\mathbf1\{\mathrm{core}(\tilde t)=k,\mathrm{pos}(\tilde t)=m\}
\le C_m.
\tag{7}
$$

扫描核内访问序时，先为当前操作申请输出空间、统计输入和输出同时驻留的峰值，再释放末次使用的输入。官方 Step2 在空间不足时插入换出和恢复，Step3 将空间复用关系写入执行依赖。

容量改善的直接做法是：把一个大张量的末次消费者提前，或将另一个大张量的生产推迟，让它们少占用同一段时间的空间。依赖关系决定可移动的位置，展开后的恢复操作说明省下了多少搬运。

对每次恢复 $e$，记恢复大小为 $b_e$；如果此前需要新写一份 DDR 副本，$z_e=1$，已有可用副本则 $z_e=0$。搬运分解为

$$
Q^{\mathrm{spill}}=\sum_e b_e(1+z_e),\qquad
Q^{\mathrm{sched}}=Q^0+Q^{\mathrm{spill}},\qquad
Q^{\mathrm{add}}=Q^{\mathrm{sched}}-Q^{\mathrm{orig}}.
\tag{8}
$$

三项依次对应额外换入换出、调度 COPY 总量和题目要求的额外搬运量。容量超出多少字节与最终换出多少字节不同：换出以整份张量为单位。

### 4.3 四个起点与容量改善

B0、B1 分别沿用整图和分量装箱。B2 沿 H 序切成最多 $4K$ 块，B3 沿优先释放存储的 R 序切成最多 $8K$ 块。多个子图的顺序参与官方稳定分桶，使同一分核方案可以产生不同的核内访问安排。

普通改进沿着快速估时更好的方案继续搜索。同时，在已经生成的候选中保存一个容量压力下降最多的方案。即使这个方案的快速估时暂时增加，也将它展开一次，观察真实 Spill 和内存依赖是否改善。两个候选共同使用原有的两个局部展开位置。

求解流程与问题一共用：四起点、第一次完整比较、局部改进、第二次完整比较。B 的评分使用式（5）、式（6），容量扫描贯穿同核合并后的访问序。

### 4.4 这一问要得到什么结果

对 100 张图保存 1至5 核 B 方案；其中 1 核结果用于问题三的硬件比较。问题二的加速比曲线采用题目统一单核基准。逐例同时分析结构搬运、Spill 搬运和完成时间，选取“结构字节相同、顺序不同”的方案对，解释调序如何通过缩短张量存活时间改变执行结果。

## 5. 问题三：让共享 Cache 配合分核和查询顺序

### 5.1 Cache 的规则决定了应当调整什么

C 继续使用 B 的 Task 结构和跨核同步。每个符合条件的 COPY_IN 在发射时，按逻辑张量 id 查询 Cache；这包括图输入、跨核读入和 Spill 恢复。存在 `logical_tid` 时使用它，否则使用 tensor id。查询所需字节为正且逻辑键有效时参与统计。

- 命中：使用 Cache 读带宽，保持当前 FIFO 插入顺序。
- 未命中：从 DDR 读取。
- 每个 COPY_IN 完成：尝试插入 Cache；键仍在时保持原位置，键已被淘汰时重新插到队尾，容量不足则淘汰最早进入的条目。
- 单份张量超过 Cache 容量时保持未缓存。COPY_OUT 写回 DDR。

同一张量第一次搬入尚未完成时，其他核心也可能发出读取，这些读会分别 miss。一个命中读在执行期间，如果对应条目被淘汰，它完成后又可以将该条目插回队尾。这两种事件直接影响后续命中。

因此，C 同时尝试三种安排：将共享输入的消费者聚合，减少重复读取；将计算分散到更多核心，利用并行和 Cache 读带宽；调整同核顺序，让后续查询更有机会发生在前次搬入完成之后。

### 5.2 快速估时：分别计算 DDR 和 Cache 的工作

先按 DDR 独占时长计算参考查询顺序。对图输入 $t$，令 $r_t=|I_B(t)|$，按查询时刻、核心号和稳定次序确定第一次读。快速估时将能放入 Cache 的输入按“一次 DDR、其余接收核走 Cache”计算，得到两个服务池的工作量：

$$
(d_t,l_t)=
\begin{cases}
(0,0),&r_t=0,\\
\left(\lceil b_t/60\rceil,(r_t-1)\lceil b_t/250\rceil\right),
 &r_t\ge1,\ 0<b_t\le1048576,\\
\left(r_t\max(1,\lceil b_t/60\rceil),0\right),&\text{其他情况}.
\end{cases}
\tag{9}
$$

其余边界搬运按 DDR 计算，记独占工作量为 $O_D$，于是

$$
W_D^{\mathrm{light}}=\sum_t d_t+O_D,\qquad
W_L^{\mathrm{light}}=\sum_t l_t.
$$

把对应 COPY 时长放回参考依赖图，得到参考完成时间 $H_{\mathrm{light},C}$。C 的轻量评分为

$$
\ell_C(X)=\left(
\max\{H_{\mathrm{light},C},W_D^{\mathrm{light}},W_L^{\mathrm{light}}\},
W_D^{\mathrm{light}}+W_L^{\mathrm{light}},\Pi(X)
\right).
\tag{10}
$$

$\Pi$ 是第 6 节定义的容量压力。主评分取路径和两个池工作量的最大值。式（9）是一种乐观输入复用估计，用于快速挑选候选；下面的 FIFO 回放进一步考虑查询、完成和淘汰的次序。

### 5.3 用真实核内展开做一次 FIFO 回放

先取得官方核内展开的 COPY、Pipe 顺序和依赖。将 COPY 按 DDR 独占时长递推，得到参考发射和完成时刻。固定这份事件流，按同刻先完成、后查询的次序处理事件；同类事件按官方核心号、Pipe 次序和稳定序号处理。回放第 5.1 节的全部插入规则，得到预计命中集合 $\hat h$。

随后将预计命中的 COPY_IN 改为 Cache 独占时长，重算一次参考最长路 $H_C^{(1)}$。两个池的独占工作量为 $W_D(\hat h),W_L(\hat h)$，预计 DDR 字节为 $\hat Q_D$，预计命中字节为 $\hat Q_H$。展开评分为

$$
p_C(X)=\left(
\max\{H_C^{(1)},W_D(\hat h),W_L(\hat h)\},
\hat Q_D/60,-\hat Q_H,Q^{\mathrm{spill}}
\right).
\tag{11}
$$

FIFO 回放和时长重算各做一次，评分按元组顺序比较。共享带宽造成的后续事件变化，由最后的官方完整模拟计算。

### 5.4 从同一 B 方案出发，生成三类方案

对同一图、同一核数，保存 B 第一次成功完整评估的初始化方案 $X_B^0$。C 首先评估这个方案，得到相同调度下增加 Cache 的结果；后续 C 改进都从它出发。

**聚合方案。**共享图输入按“字节数 × 不同消费块数”降序排列，同分按张量 id。其消费块按最大 Pipe 工作量降序、最小操作 id 升序排列。目标核取该输入计算消费者总周期最多的核心，同分取较小核心号。跳过已经位于目标核的块，逐次将一个消费块移向该核，试依赖允许的最早、最晚位置，接受第一个轻量评分改善的方案，再按新状态继续。

**分散方案。**从含至少两个共享图输入消费操作的块中，按最大 Pipe 工作量降序、块内最小操作 id 升序选块。把 H 序限制到该块，按第 6.2 节的切点规则二分。先试前半块、再试后半块；其他核心按当前最大 Pipe 负载升序、核心号升序排列，仍试最早、最晚位置。移动后，至少一个共享输入增加接收核心，原核心也保留消费者。接受第一个轻量评分改善的方案，再继续。

聚合与分散各从 $X_B^0$ 独立开始，每条路径最多实例化 8 次候选，无效尝试也计数。相同方案复用回放结果；所有受影响的输入、输出域和容量重新计算。最后接受的方案作为该路径代表，未发生改善时该代表为空。

**局部顺序方案。**按第 6 节生成普通、容量和时序代表。时序锚点来自 C 基准的官方 `cache_events`：取发生至少两次 miss 的逻辑张量，按第一次 miss 之后的累计 miss 字节降序选至多 8 个，同分按逻辑 id。围绕它们调整相关块的前后位置，查看参考查询时刻、MTE2 次序或跨核释放关系是否改变。方案相对固定基准改变上述任一关系，就参与时序代表比较；轻量评分暂时增大的方案也保留。按受影响锚点的基准重复 miss 字节总和降序，再按轻量评分和计划键选代表；基准记录中的字节用于确定编辑重点。基准完整评估失败或没有有效事件时，时序锚点为空，容量和普通代表继续参与比较。

局部方案优先取时序代表，其次容量代表，再次普通代表。它与聚合、分散各占一个展开位置，按“局部、聚合、分散”的顺序登记，同一计划展开一次并保存各来源。加上 B 基准，C 共使用最多四次独立展开。对展开评分严格优于基准的代表，选择最好者做第二次完整评估，按式（1）保留结果。失败处理集中在第 11.3 节。

### 5.5 用三种比较解释 Cache 的效果

记 B 最终方案为 $X_B^*$，C 最终方案为 $X_C^*$，计算

$$
S^{\mathrm{hw}}=\frac{F_B(X_B^0)}{F_C(X_B^0)},\qquad
S^{\mathrm{adapt}}=\frac{F_C(X_B^0)}{F_C(X_C^*)},\qquad
S^{\mathrm{opt}}=\frac{F_B(X_B^*)}{F_C(X_C^*)}.
\tag{12}
$$

三项均从主矩阵的已保存结果计算，分别回答：相同调度增加 Cache 有多少收益；增加 Cache 后继续调整调度有多少收益；两种硬件配置各自优化后相差多少。前两项相乘的分子为 $F_B(X_B^0)$，第三项使用 $F_B(X_B^*)$，因此分别统计。

C 的官方额外搬运字段在 Cache 模拟前生成，表示计划安排的 COPY。实际由两个池承担的字节另算为

$$
Q_L=\mathrm{hit\_bytes},\qquad
Q_D=Q^{\mathrm{sched}}-Q_L.
\tag{13}
$$

问题三逐例报告 B/C 完成时间、双方额外搬运量、Cache 字节命中率，以及 $Q_D,Q_L$。结果分析把命中变化与总时间联系起来：DDR 等待减少了多少，新增并行有没有抵消等待，Cache 读池是否成为新的限制。

## 6. 公共求解器：每一步怎样计算

### 6.1 三种拓扑顺序

每张图解析一次，保存操作邻接、张量生产者与消费者、原 COPY 端点、弱连通分量和 Pipe 工作量。张量的域计数用字典维护：键为“逻辑张量、驻留域”，值为消费者数量；数量从 0 变 1 或从 1 变 0 时，接收域数才改变。

计算操作 $v$ 的反向关键路径长度为

$$
h(v)=c_v+\max_{v\to u}h(u),
\tag{14}
$$

$c_v$ 是计算周期，无后继时最大项为 0。三种顺序定义如下。

**H 序：先安排后面还有较长计算链的操作。**每次在已就绪操作中按 $h(v)$ 降序、操作 id 升序取一个。

**R 序：在关键路径优先的基础上，优先释放空间。**先取 H 优先级最高的至多 8 个就绪操作，再按“本步释放的输入字节减去新增活跃输出字节”降序、$h(v)$ 降序、id 升序选择。这里依据计算消费者构造顺序，完整容量扫描还计入 COPY_OUT 等读者。

**D 序：尽量连续安排一条支路。**分量按最大 Pipe 工作量降序、最小操作 id 升序排列；分量内根和后继按 id 升序访问，用迭代 DFS 的逆后序得到拓扑序，再连接各分量。

### 6.2 装箱、切块和分核

**分量装箱。**按最大 Pipe 工作量降序、最小操作 id 升序处理分量。每个分量试放到所有核心，先比较放置后的 $\max_{k,q}W_{k,q}$，再比较新增图输入接收域字节，最后按核心号选取。同箱的分量合并成一个子图。整图起点和分量装箱起点统一使用 H 作为轻量参考序。

**连续切块。**块数为 A2 的 $2K$、A3/B2 的 $4K$、B3 的 $8K$，并取与操作数 $n$ 的较小值。假设还需要形成 $b$ 块，剩余 M/V 工作量为 $M_r,V_r$，当前块的目标为 $\max(M_r,V_r)/b$。候选前缀的计算量取 $\max(M_{\mathrm{prefix}},V_{\mathrm{prefix}})$。在目标上下 10% 的窗口中，依次比较切点穿过的去重张量字节、与目标的偏差和切点位置；窗口为空时取计算量最接近目标的合法位置，同距取靠前切点。每个切点给剩余块保留至少一个操作，最后一块接收余项。

切点穿越字节由张量在序列上的最左、最右计算关联位置形成区间，再用差分累计求出。它负责挑切点，完整计划的搬运使用式（3）、式（5）。连续拓扑块的跨块依赖沿块序向后，初始商图因此无环。

**逐块分核。**按块拓扑序处理细分块，依次试放到每个核心列表末尾。每次回放已经放入的前缀，比较轻量评分，再按核心号选取。前缀中，尚未放置的消费者暂时没有消费域；已产生且还要交给未来消费者的张量作为前缀出口，令其前缀 $o_t=1$。图输入按已放消费者计接收域。每放入一块，重新计算整个已放前缀的搬运和参考时间，最后对完整起点再回放一次。

### 6.3 计划规范化与轻量执行骨架

规范化按各子图内最小操作 id 重新编号，并同步替换核心列表中的子图 id。**核心编号和每核子图的相对顺序保持原样。**这样，不同编号的相同方案能够合并，而调序产生的新方案会被保留下来。

每个图、核数、场景内按起点 0、1、2、3 的顺序登记计划。首次登记同时保存参考构造序；后续遇到同一规范化计划时复用它。局部编辑继承对应起点的参考序，新块沿该序排列。C 先登记 $X_B^0$，再按局部、聚合、分散登记。计划与图、场景、核数、配置、官方代码版本共同确定一次可复用计算。

轻量执行骨架保留计算操作及其数据依赖，按式（3）或式（5）加入虚拟边界 COPY。输入 COPY 放在首次消费者之前，输出 COPY 放在生产者之后。A 在各 Task 内使用参考序；B/C 按核心子图列表稳定分桶。各 Pipe 连接相邻操作，再加入 A 的 Task 起止与等待边，或 B/C 的跨核 COPY 释放边。

同一位置有多个 COPY 时，先按逻辑张量 id；输入中原图输入在前，跨核输入按源核和源 Task；输出中最终写回在前，跨域写出按目标核和目标 Task；最后按构图登记序号排列。A 的源写出兼任最终输出与外域传递时登记一次。每个虚拟操作据此取得稳定序号。输入 COPY 归属首次消费块，输出 COPY 归属生产块。

COPY 经过带宽为 $B_p$ 的服务池时，独占参考时长取 $\max(1,\lceil b_e/B_p\rceil)$。在参考依赖图上递推

$$
\widehat D_o=d_o+
\max_{p\in\mathrm{Pred}_{\mathrm{ref}}(o)}(\widehat D_p+\delta_{p,o}),
\tag{15}
$$

$d_o$ 是计算或 COPY 独占周期，$\delta_{p,o}$ 为对应的 100、1000、500 cycles，普通依赖取 0；根的前驱项为 0。A 使用零时长 Task 起止节点表达式（4）。记最大参考完成时间为 $H_{\mathrm{light}}$，全部 DDR COPY 独占周期之和为 $W_D^{\mathrm{light}}$。

沿核内访问序统计张量理想活跃字节，每个张量首次进入骨架时申请空间、全部读者访问完成后释放，同一步先计申请后的峰值、后释放。A 的不同 Task 分别扫描，B/C 沿同核合并序扫描。容量压力定义为

$$
\Pi(X)=\sum_{k,m}\left[\max_j\mathrm{Live}_{k,m}(j)-C_m\right]_+.
\tag{16}
$$

其中 $[x]_+=\max(x,0)$。它度量不做换出时，各核各存储区的峰值超出容量多少字节。A/B 的轻量评分为

$$
\ell_{A/B}(X)=\left(\max\{H_{\mathrm{light}},W_D^{\mathrm{light}}\},Q^0,\Pi(X)\right).
\tag{17}
$$

所有评分元组按字段顺序比较，时间与字节保留各自单位。轻量骨架有环时结束该候选的筛选。容量超额由 $\Pi$ 描述，后面的官方展开负责生成实际换入换出。

### 6.4 官方核内展开补充实际代价

一次完整计划的官方核内展开简称 profile。A 调用 `_build_scene_a_tasks`，B/C 调用各自的 `_build_scene_b_tasks`，取得展开操作、`seq`、`pipe_ops`、内存依赖和搬运汇总。`prepare_step3_execution` 内部还调用 `step3_simulation`，计时包含这部分工作。

在展开图上连接官方数据、内存、Pipe 依赖以及对应场景的释放边，按式（15）计算参考最长路 $H^0$；真实展开 COPY 的 DDR 独占工作量记作 $W_D^0$。A/B 的展开评分为

$$
p_{A/B}(X)=\left(\max\{H^0,W_D^0\},Q^{\mathrm{sched}},Q^{\mathrm{spill}}\right).
\tag{18}
$$

大额恢复操作从展开操作中的 `spill_logical_tid`、`transfer_bytes`、物理张量和消费者定位。官方内部临时变量 `spill_records` 的信息由这些返回字段与汇总量承接。C 使用同一展开结构，再计算式（11）。

完整模拟将各服务池的带宽平均分给同时在途的搬运。例如某池当前有 $m_p(\tau)$ 个搬运，每个剩余工作量 $R_e$ 按 $dR_e/d\tau=-1/m_p(\tau)$ 推进，完成时刻沿用官方取整规则。三层计算各有职责：轻量层选编辑，展开层比较实际核内代价，完整模拟给出最终结果。

### 6.5 局部候选怎样生成

计算操作数决定搜索规模：

| 图规模 | 轮数 | 每轮 A 候选 | 每轮 B 候选 | 每轮 C 候选 |
|---|---:|---:|---:|---:|
| $n\le2000$，41 图 | 3 | 64 | 48 | 64 |
| $2000<n\le10000$，40 图 | 2 | 48 | 36 | 48 |
| $n>10000$，19 图 | 1 | 32 | 24 | 32 |

每轮按“整块迁核、拆并、边界操作迁移、同核调序”的固定次序，各取一个候选轮流处理；某类耗尽就跳过。候选总数使用表中上限。子图数上限为 $\min(n,8K+16)$。

| 编辑 | 确定的生成规则 |
|---|---|
| 整块迁核 | 先列生产者、消费者所在的其他核心，按核心号排列，再补一个计算负载最低的其他核心；负载同分取小核心号。目标列表试满足同核依赖的最早、最晚位置，重合则试一次 |
| 拆分或合并 | 合并同核列表中相邻两块；拆分采用锚点前后最近的非空拓扑切点，拆出的块先相邻留在原核 |
| 边界操作迁移 | 隔离一个操作；B/C 还尝试它与本块参考序中前邻、后邻组成的两操作块，依次枚举。剩余操作保持前后连续段，再按整块迁核规则放置 |
| 同核调序 | 试相关生产块之后、消费块之前，以及容量峰值关联块的两侧；C 在本类名额中优先处理时序锚点 |

A 每轮由单操作形成的新 Task 候选最多 8 个，其锚点来自跨域搬运、关键路径或容量压力。

跨域锚点按关联跨域字节降序取至多 32 个操作；路径锚点在边界操作中按 $h(v)$ 降序、关联字节降序、id 升序取至多 32 个。容量锚点优先取当前计划 profile 中恢复字节最大的至多 8 个操作，字节同分按操作 id。没有对应 profile 时，取当前轻量扫描最早出现的最大超额峰值，按张量大小降序、id 升序取至多 8 份活跃张量，以其生产者和消费者定位编辑位置。各类描述按关联字节降序、路径值降序、操作 id、目标核、插入位置排序，再轮流实例化。

每个候选按“应用编辑、规范化、检查、更新张量域、重放时间与容量”处理。迁移操作时，重算它的全部输入、输出以及共享消费者涉及的域。所有重复计划合并计算，候选来源保留。

### 6.6 普通改善与容量、时序探索

保存初始化 $X_0$，搜索当前状态从它开始。

**普通链。**每轮选择轻量评分严格小于当前状态的最佳候选，更新当前状态及其域、列表、参考时间和容量；候选与当前状态同分时不更新；多个改善候选同分时按计划键选择。记录最好的已接受方案 $X_{\mathrm{ord}}$。新计划使用自身容量状态，已有 Spill 锚点在对应计划相同时复用。

**容量代表。**在各轮已经生成的合法候选中，保存满足 $\Pi(X)<\Pi(X_0)$ 的方案，按容量下降量降序、轻量评分升序、计划键升序选择 $X_{\mathrm{cap}}$。比较基准始终为初始化。容量代表单独保留，普通链仍按当前状态继续。

**C 时序代表。**采用第 5.4 节定义的重复 miss 锚点与查询变化条件，保存 $X_{\mathrm{time}}$。普通链、容量代表和时序代表来自同一批实例化候选，共用表中的候选数和轮数。

一轮没有普通改善、候选耗尽或达到轮数时结束搜索，再处理已经保存的代表。A/B 按容量代表、普通代表依次展开，各最多一次；两者重合时展开一次，某类为空时省去相应工作。C 则按第 5.4 节选择一个局部代表。失败展开计入对应次数，保存实际错误。

### 6.7 两次完整比较怎样衔接

A/B 先对去重后的四起点做 profile，按展开评分、计划键选择 $X_0$，进行第一次完整评估。第二次比较的候选池由两部分组成：其他尚未完整评估的成功起点，以及展开评分严格改善 $X_0$ 的容量、普通代表。按相同展开评分选出最好者完整评估，最终取两次成功结果中式（1）较小者。第一次失败时，第二次优先评估尚未试过且 profile 成功的整图起点，再考虑其他成功起点。

C 的第一次完整比较使用 $X_B^0$，第二次使用评分改善的最好代表；B 后续得到的 $X_B^*$ 单独保留，用于式（12）的分别优化对照。每个图、核数和场景最多两次完整调用，失败调用也计入其中。

```text
对每张图 G：
    构建静态视图，计算统一单核基准 T1
    对 A 的 K=2..5、B 的 K=1..5：
        构造四起点，去重，计算轻量信息与官方展开评分
        选择初始化 X0，做第一次完整评估并保存
    对 C 的 K=1..5：
        取同图同核数 B 的成功初始化 XB0
        展开并回放 FIFO，对 XB0 做带 Cache 的第一次完整评估

    对 A/B 各组合：
        从保存的 X0 做局部搜索，取得普通与容量代表
        展开这两个代表，将评分严格优于 X0 的代表与其他未完整评估的成功起点组成候选池
        若候选池非空且还有第二次完整比较位置，评估其中评分最好者
        按 Makespan、额外搬运量保存最终方案
    对 C 各组合：
        从 XB0 构造局部、聚合、分散三个代表
        展开、回放 FIFO，选择评分改善的最好代表做第二次完整比较
        保存 C 最终方案，以及同方案和分别优化的配对结果

使用保存的结果生成逐例表、平均加速比、机制对照和论文图表
```

初始化和改进是同一算法的两段执行过程，分别保存结果便于测量新增计算带来的收益。异常分支按第 11.3 节执行。

### 6.8 复杂度与解释结果的下界

设张量数为 $t$，操作与张量关联数为 $I$，子图数为 $S$。静态视图需要 $O(n+t+I)$ 空间和线性遍历，H/R 的堆式选择为 $O((n+I)\log n)$，D 为线性遍历。切点扫描逐块执行，细分起点最多有 $SK$ 次前缀试放。一项完整轻量回放的上界为 $O(n+t+I+S^2)$；每个组合局部回放次数由“轮数 × 每轮候选数”确定，C 再加聚合、分散共 16 次试放。

一次官方展开用实测成本 $P_r(G,X)$ 计量。展开后有 $N_X$ 个操作、$E_X$ 条依赖，参考最长路和容量反馈扫描为 $O(N_X+E_X)$；C 有 $N_{\mathrm{in}}$ 次读入时，FIFO 排序增加 $O(N_{\mathrm{in}}\log N_{\mathrm{in}})$，随后重算一次最长路。

设原计算图最长路径为 $L_G$，最少必需输入与最终输出字节为

$$
Q_{\min}=\sum_{t\in T_{\mathrm{in}}}b_t+\sum_{t\in T_{\mathrm{prod}}}o_tb_t.
$$

初始 Cache 为空，每个输入至少先从 DDR 读取一次，得到共同必要下界

$$
LB_K=\max\left\{L_G,W_M/K,W_V/K,Q_{\min}/60\right\}.
\tag{19}
$$

结果中报告 $F_r/LB_K$ 描述与必要下界的距离，并比较下界各分量，说明计算链、总计算量和搬运施加的约束。C 还可将实测 $Q_D/60,Q_L/250$ 与计算下界取最大值，核对两个池承担的工作。加速比使用题目规定的 $T_1$，下界用于解释其大小。

## 7. 用一张小图看懂三问

### 7.1 数据与计算

以下为公式手算示例。输入 $x$ 大小 60000 bytes；操作 $p$ 用 $x$ 计算 1000 cycles，产生 30000 bytes 的 $z$；操作 $a,b$ 都用 $x,z$，各计算 800 cycles，各产生 6000 bytes 的最终结果。三个操作都使用 V Pipe。

```text
x → p → z → a → ya → DDR
│       └→ b → yb → DDR
├────────→ a
└────────→ b
```

例如 $a$ 的输入加输出为 $60000+30000+6000=96000$ bytes，小于 UB 容量。原始搬运为 $60000+6000+6000=72000$ bytes。

### 7.2 同核与合并在两问中作用不同

| 方案 | A 结构搬运 bytes | B 结构搬运 bytes |
|---|---:|---:|
| 全图一个子图，放核心 0 | 72000 | 72000 |
| $p,a,b$ 各一子图，都在核心 0 | 282000 | 72000 |
| 三个子图分别在三个核心 | 282000 | 312000 |
| $p$ 一核，$a,b$ 同在另一核，仍是两个子图 | 282000 | 192000 |
| 进一步将 $a,b$ 合成一个子图 | 192000 | 192000 |

三个子图分到三核时，A 为 $3\times60000+30000+2\times30000+2\times6000=282000$；B 为 $3\times60000+2\times(30000+30000)+2\times6000=312000$。把 $b$ 移到 $a$ 的核心后，B 降至 $2\times60000+60000+12000=192000$，减少 120000 bytes。

这次迁移同时减少了计算并行：分支分核时纯计算依赖路径为 $1000+800=1800$ cycles，同核时三项 V 计算合计 2600 cycles；两种 B 方案的 DDR 独占工作量则由 5200 降为 3200 cycles。算法比较的正是这两种方向相反的变化。

### 7.3 等待与容量带来的变化

沿 $p\to a$ 看计算和同步，同一 Task 中为 1800 cycles；A 切成同核两个 Task 后为 $1000+100+800=1900$；放到不同核后为 $1000+1000+800=2800$。再加入对应 COPY 及共享带宽，即构成实际时间计算。

容量用另一个局部状态说明：两个 81920 bytes 的 UB 张量同时驻留，占用 163840 bytes，比容量多 32768 bytes。如果换出其中一份并新写 DDR，写回加恢复为 163840 bytes；已有持久副本时，恢复新增 81920 bytes。将第一份张量的末次消费者提前，可以消除这段重叠。这说明容量峰值适合寻找编辑位置，完整张量的换入换出决定真实搬运成本。

### 7.4 同样读三次，查询时间会改变结果

单独观察三核读取 60000 bytes 的 $x$。一次 DDR 独占读需要 1000 cycles，一次 Cache 独占读需要 240 cycles。

若三次查询在初始时刻同时发射，空 Cache 下三次都 miss，公平共享 DDR 后均在 3000 cycles 完成。若第一读在 0 时刻发射，1000 时刻完成并插入，另两次恰在 1000 时刻查询且条目仍在，它们同时命中，共享 Cache 带宽需要 480 cycles，于 1480 时刻完成。这组数值描述给定查询时刻的读入子系统。整图通过分核、子图顺序和依赖关系改变查询时刻，同时承担其他计算和搬运。

再看完成时插入：三份各 400000 bytes 的数据 $x',y',z'$，当前 FIFO 为 $[x',y']$。$x'$ 命中读发射后，$z'$ 先完成并插入，队列变为 $[y',z']$；在途 $x'$ 随后完成，发现自身键已被淘汰，重新插入后队列为 $[z',x']$。因此，FIFO 回放需要处理命中读的完成事件。

### 7.5 资源变化怎样改变聚合与分散的选择

取一个 60000 bytes 输入和五个独立 V 操作，每个计算 100 cycles、使用 5 核。先按第 5.2 节的输入复用估计分析读入和计算。聚合到一核，参考时间为 $1000+5\times100=1500$。分散到五核且容量能够容纳输入时，令 $d_L=\lceil60000/B_L\rceil$，评分为

$$
J_{\mathrm{disp}}^{\mathrm{light}}
=\max\{1100,d_L+100,1000,4d_L\}=\max\{1100,4d_L\}.
\tag{20}
$$

| Cache 带宽 bytes/cycle | 每次 Cache 周期 | 聚合评分 | 分散评分 | 评分选择 |
|---|---:|---:|---:|---|
| 125 | 480 | 1500 | 1920 | 聚合 |
| 250 | 240 | 1500 | 1100 | 分散 |
| 500 | 120 | 1500 | 1100 | 分散 |

容量低于 60000 bytes 时，分散方案五次都走 DDR，评分为 5000，聚合仍为 1500。这组计算揭示两项作用：足够的 Cache 带宽支持更多接收核，足够的容量让共享输入能够留下来。正式实验再通过实际查询事件和两池服务量观察这两项作用。

### 9.3 用吞吐测量预测墙钟

总目标为 8 小时，即 28800 s，其中准备、汇总和必要返工安排 3600 s，主要计算安排 25200 s。初始化、改进、机制对照的初始安排分别为 10800、9000、5400 s，再根据上述计时调整。

记阶段 $s$ 的串行等价工作量为

$$
W_s=\sum_j(t_{\mathrm{seed},j}+t_{\mathrm{light},j}+t_{\mathrm{profile},j}
+t_{\mathrm{official},j}+t_{\mathrm{FIFO},j}+t_{\mathrm{IO},j}).
\tag{23}
$$

这里每项工作计一次。串行准备、汇总另计，官方完整入口包括它内部的展开，独立 profile 则计额外展开。每图静态解析计入准备或首次 worker 工作中的一个位置。

设系统及主进程占用 $M_0$，单 worker 最大增量内存为 $m_s$，逻辑 CPU 数为 $p_{\mathrm{hw}}$，预留 8 GiB，内存允许的 worker 数为

$$
p_{\mathrm{mem},s}=\min\left\{p_{\mathrm{hw}},
\max\left(0,\left\lfloor\frac{48\,\mathrm{GiB}-M_0-8\,\mathrm{GiB}}{m_s}\right\rfloor\right)\right\}.
$$

实用数量记作 $p_s\le p_{\mathrm{mem},s}$。由相同任务的串行耗时之和 $T_{\mathrm{sum}}$ 和并发墙钟 $T_{\mathrm{batch}}$ 计算

$$
\eta_s=\min\left(1,\frac{T_{\mathrm{sum}}}{p_sT_{\mathrm{batch}}}\right),
\qquad p_{\mathrm{eff},s}=\eta_sp_s.
\tag{24}
$$

$p_s$ 回答开几个进程，$p_{\mathrm{eff},s}$ 回答它们提供了多少串行等价吞吐。六次复测先给初始效率，再按图规模与工作步骤的观测修正预测。内存只能容纳更少进程时减少同时保留的展开图和并发数。

未计入 $W_s$ 的阶段内串行时间记作 $T_{\mathrm{serial},s}$，最长依赖链时间为 $T_{\mathrm{chain},s}$，包括 B 初始化完成后才能开展 C 的依赖。墙钟预测为

$$
\widehat T_{\mathrm{wall}}=T_{\mathrm{prepare}}+T_{\mathrm{summary}}+
\sum_s\left[T_{\mathrm{serial},s}+\max\left\{W_s/p_{\mathrm{eff},s},T_{\mathrm{chain},s}\right\}\right].
\tag{25}
$$

预测和实测同时保存，出现超时就能定位是候选工作量、并发争用还是少数长任务造成的。单独运行 C 时，将同图同核数的 B 初始化计入本次用时；已有完全相同 B 结果时直接复用。

### 10.3 可以直接写入初稿的方法介绍

> 多核调度需要同时安排计算和数据流动。增加核心数量能够分担计算，但跨 Task 和跨核传输会增加搬运与同步，同核复用又会改变片上存储的占用。本文以张量的生产者和消费者为基础，将能够共享片上副本的计算范围定义为驻留域。问题一按子图 Task 统计接收域，问题二按核心统计接收域，由此建立对应的结构搬运模型。求解时，利用独立计算分量和不同拓扑顺序构造初始划分，通过迁块、拆并和同核调序共同调整负载与张量存活时间。候选先经过参考时间计算，再由官方核内展开补充实际换入换出和内存依赖，最后通过共享带宽模拟选择完成时间最短的方案。问题三进一步回放 FIFO Cache 的查询和完成事件，围绕共享输入的聚合、分散和重复 miss 调整调度，并分别测量相同方案的硬件收益与调度适配收益。

问题一可以这样开始：

> 问题一的每个子图独立形成一个 Task。切分既增加可并行执行的任务，也增加跨 Task 的数据读写与激活等待。为计算一次切分的净收益，本文先按张量的外部消费 Task 数统计搬运，再将 Task 完成依赖与同核顺序共同写入时间递推。随后从分量装箱、连续支路和关键路径三个角度生成划分，并通过局部调整选择 Task 粒度与分核方式。

问题二可以这样开始：

> 问题二允许同核子图共享片上副本，数据传输由子图边界转为核心边界。减少接收核心能够减少重复搬运，但更多计算集中到同核后，张量存活区间容易重叠。本文在核心接收域计数的基础上引入活跃容量扫描，通过提前末次消费者和推迟新张量生产来释放空间，再用官方换入换出结果比较各调度方案。

问题三可以这样开始：

> 共享 Cache 将重复读取的一部分工作从 DDR 转移到独立的 Cache 读通道。FIFO 替换下，一次查询能否命中取决于此前哪些读已经完成，以及期间插入了哪些数据。本文据此将查询和完成事件加入候选评分，从共享输入的消费者分布与读入次序出发生成方案，并通过固定 B 方案、Cache 适配方案和分别优化方案的三组比较分析加速来源。

结果段按“具体变化、对应数值、执行机制”组织。例如比较两个同分核方案时，同时写完成时间、Spill 字节和哪一段张量存活重叠被缩短；分析 Cache 时，同时写 DDR 服务字节、重复 miss 次数和查询次序。较慢方案与较快方案使用相同指标呈现，它们共同解释算法的取舍。
