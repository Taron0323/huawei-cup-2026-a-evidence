### 1.3 模型层面

- 全文“模型”主要是三类东西：①把提交格式写成集合与指示函数（式 1～2）；②按接收域统计搬运字节的记账公式（式 8、16、17、21、22）；③复述评估器的时间推进与 FIFO 规则（式 4、10、18、25、27，算法 4）。这些都正确，但**没有一个以决策变量、目标函数和约束组成的完整优化模型**。研究生赛评委通常期待先有一个规范的数学规划（哪怕不可直接求解），再说明为什么用启发式。
- 已经有很好的素材可以组装成优化模型：决策变量 g、a、σ；目标 min F_r(X)，次目标 min D_r(X)；约束式 (1)(2)(3)(10)/(18)；再把 Partition 归约写成一个命题（“即使只考虑两核、无依赖、无搬运的特例，判定工期 ≤ W/2 也是 NP 完全的”），以此过渡到启发式。现在 Partition 只有一句话埋在 5.1.2 末尾。
- 下界 LB（式 6～7）做得好，但只用于事后诊断。表 30 显示 F/LB 的 90 分位数超过 4.4，说明有大量图离下界很远，这本来应该驱动算法改进（比如对 F/LB 大的图追加评价预算）。

### 1.4 算法层面（除数据错误外最大的短板）

1. **评价预算只有 2 次**。每图、每核数、每场景最多 2 次完整评价，而表 30 显示单次评价中位数只要 0.75～1.5 s。题目允许每个用例 5～10 分钟，典型图完全可以做几十到上百次评价。2 次预算让排序代理的好坏直接决定结果，而代理从未被验证过（没有报告代理分数与真实工期的相关性）。
2. **局部编辑是固定位置的一次性操作**：迁块只移“负载最大核的第一个子图”，合并只合“第一个有两块的核的前两块”，调序只换“前两块”。这不是局部搜索，只是 3 个确定性扰动。结果也印证了这一点：6.4.2 写明 B 五核 100 个最终方案中 **99 个直接来自种子，只有 1 个来自局部编辑**。摘要里的“贪心分核”“局部最优方法”“确定迁块、合并与调序调整方案”属于过度表述。
3. **没有把少核方案继承到多核**。5.3.3 与 6.3.3 都写了“上一核数的已选计划没有自动补入本核数的必评队列”，而附录 A.2 的 `pad_plan_cores` 的注释恰恰说明了少核方案补空核后仍合法。题目 B.5 明确允许内层数组为空。这是 19 张图五核慢于单核、33 张图 4→5 核反升的直接原因。
4. **整图基准不是必评候选**。A0/B0 只是“普通候选”，排序靠后就不会被评价。结果：B 单核有 51 张图慢于 A0（单核下所有子图本来就合并成一个 Task，唯一差别是 Step1 的顺序提示），case_058 的 B 单核比 A0 慢 42%。Q3 已经把 X_B 设为必评，Q1/Q2 应同样处理。
5. **Q2 没有用 Q1 的解热启动**。A 方案在 B 场景下同样是合法计划。经重算，五核下 B 比 A 慢 30% 以上的有 6 张图：case_035、039、043（2.5 倍）、053（3.0 倍）、063（2.3 倍）、083。case_053 的 B 甚至选了整图方案，工期 = 单核基准。反过来 A 也可以借 B 的方案（case_055、067 的 B 好得多）。
6. **B/C 的合法性检查不完整，浪费预算**。代码 `validate_plan` 只在 `scene == "A"` 时检查同核顺序与依赖一致，4.4 节也说 B、C“外层只检查覆盖和格式”。但题目 1.3 与 B.5 要求所有场景同核顺序都不得违反依赖。表 27 中 B 有 110 次、C 有 77 次完整评价失败，每次失败都占掉 2 次预算中的 1 次；7.6 的 12 条“依赖环失败”也是同一原因。把 A 的检查逻辑对 B/C 同样打开，这些预算就能省下来。
7. **切块按操作数而不是周期**。A2/A3、B2/B3 都按操作数近似均分，文中自己也承认会造成负载偏斜。改成按累计周期（或按 M/V 两条流水线分别累计）均分，改动很小。
8. **单分量大图是短板**。表 28 显示单一弱连通分量的 16 张图五核均值只有 1.11～1.26，A 场景 9/16 慢于单核。这正是题目最想考察的“切图”能力，建议集中精力做：按拓扑层/关键路径分段、同一分段内按 M/V 负载配对、相邻分段尽量同核（A 场景同核等待 100 vs 跨核 1000）。
9. **Q3 算法很弱**。共享输入候选只取“按大小排序的前 8 个张量”，聚合到“编号最小的消费核”，调序只是“把相关子图挪到末尾”。五核仅 7 张图适配改善，平均适配比 1.0011。你们在 7.2.1 和 7.3.1 的解析例里已经推出了关键规律（同时查询全部未命中，错峰才能命中），但算法没有利用它：比如对每个跨核共享输入指定一个“领读核”，让其他核把消费该输入的子图往后排。

## 附录 A：复核脚本（重算三问逐核均值与慢例）

下面的脚本读取你们的 `main_results.csv`。我不确定具体列名，请把 `COLS` 里的名称改成实际列名后运行。

```python
import pandas as pd

COLS = dict(graph="graph", scene="scene", cores="cores",
            base="baseline_makespan", final="final_makespan")

df = pd.read_csv("main_results.csv")
df = df.rename(columns={v: k for k, v in COLS.items()})
df["sp"] = df["base"] / df["final"]

# 题面口径：A、B 单核记为 1
df.loc[(df.cores == 1) & df.scene.isin(["A", "B"]), "sp"] = 1.0

print(df.groupby(["scene", "cores"])["sp"].agg(["mean", "median"]).round(4))
print(df[df.sp < 1].groupby(["scene", "cores"]).size())

# 继承机制：K 核取 1..K 核及整图基准中的最短 Makespan
best = []
for (g, s), sub in df.groupby(["graph", "scene"]):
    sub = sub.sort_values("cores")
    run = sub["base"].iloc[0]
    for _, r in sub.iterrows():
        run = min(run, r["final"])
        best.append((s, r["cores"], r["base"] / run))
b = pd.DataFrame(best, columns=["scene", "cores", "sp_inherit"])
print(b.groupby(["scene", "cores"])["sp_inherit"].mean().round(4))
```
