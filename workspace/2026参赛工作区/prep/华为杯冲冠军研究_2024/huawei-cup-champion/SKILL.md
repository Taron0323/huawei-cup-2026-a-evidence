# 华为杯冲冠军

把赛题要求转成一套有解释、有比较、有检验、能交付并能答辩的解答。历史获奖论文提供设计经验；本 Skill 不提供官方评分权重或获奖概率。

## 接入当前任务

1. 识别用户要做的是选题、建模、验证、写作、审查还是答辩。只完成请求范围；一段建议不启动全流程，不创建一套空文档。
2. 进入已有项目先读项目入口、当前状态、题面和相关结果。沿用项目的路径和记录方式；已有模型时从当前瓶颈继续。没有正式赛题时做准备或演练，有赛题时依据实际状态工作。
3. 涉及参赛规则时核对当年官方原件、更新时间和适用阶段。论文评阅、进入数模之星和现场答辩是不同阶段；历史答辩投票比例不作为现年论文权重。
4. 对正式比赛，先确认当前规则允许的 AI 辅助范围。AI 支持分析、编码和表达，队员负责核心判断、核验和按规则披露；不代填身份、不虚构签名、人工审阅或提交结果。

## 建模决策主线

对当前需要解决的一问，先明确：**交付对象 → 可用信息 → 数学对象 → 基线 → 关键不足 → 有针对性的改进 → 验证 → 最终答案**。

- **交付对象**：预测表、参数估计、机制解释、调度配置、风险地图等必须具体。优先补齐漏问和未落地的输出。
- **可用信息**：每个变量写清单位、对象标识、时间点及预测/决策时是否可得。按独立实验、对象、区域或时间确定拆分单位；多行属于同次实验时不得仅凭随机行拆分声称跨实验泛化。
- **数学对象**：先确定状态、变量、目标和约束，再选算法。解释物理关系如何进入特征、方程、边界或损失，而不只写领域背景。
- **基线**：建立能回答题目的简单方案。先比较物理公式、统计模型、规则或常规优化器中最合适的一个，再决定复杂模型的必要性。
- **改进**：用一句话说明它修复了哪种观察到的不足。针对分布、约束、目标或数据结构改进；算法数量和名称新颖不构成贡献。
- **比较**：同数据、同划分、同单位、同目标变换与反变换、同指标定义、可比计算预算。先修口径再排优劣。新增模块用有无模块对照；随机算法报告重复波动，优化报告可行性和预算。
- **检验**：按结论选择留出、扰动、极端边界、误差切片或独立计算。噪声测试不替代新工况测试；拟合指标不替代预测性能；情景仿真不替代真实实施效益。
- **答案**：回代原始约束和单位，明确适用域、精度或偏好。多目标给可行折中方案及选择理由；未给权重时不把权重交给优化器任意选择并宣称唯一最优。

只有当当前方案的有效性已经能被检查，且剩余预算容纳实现和验证时，才增加新模型。效果相近时优先可解释、可复算、成本较低的方案；记录没有收益的改进及其停止理由。

## 按需读取

- 解释历史共性、借鉴某类题或论证为什么这样做：读 [2024-patterns.md](references/2024-patterns.md)。历史数值均为作者报告，不能直接作为当前结果。
- 组织建模与实验、修复验证、安排剩余工作：读 [execution.md](references/execution.md)。按问题类型选择检查，不机械执行所有条目。
- 改摘要、正文、图表或准备答辩：读 [paper-and-defense.md](references/paper-and-defense.md)。只迁移论证结构，保留来源归属。

已有 `mathmodel-astra` 时，可由它管理项目状态与阶段，本 Skill 负责上述模型取舍和证据要求；未安装它时也能独立使用，不把安装其他 Skill 当作前置条件。

## 交付尺度

实际产物优先。一次模型改进通常交付改动、可追溯结果、取舍结论和仍缺的关键证据；一次审查给出按影响排序的问题及修复位置；一次写作直接给修订稿。结论分别标明来自原文、当前实测、当前仿真或待验证推断。程序运行成功、科学结论成立、队员审阅和平台提交状态分别报告。

需要完整推进时，先列不超过三个近期目标并持续更新。资料足够就推进普通可逆工作；只有影响目标或结论的缺失信息才提问。任何评分仅在用户要求时作为自定义诊断，公开定义，不能冒充官方标准。
