# 数学建模项目协作规则

本项目采用根目录《数学建模-AI全流程工作法-GPT6-Astra-Max-Ultra版.md》。旧版保留为历史来源，修订依据见 `prep/astra/revision-review.md`。2026 年正式题面已到达 `赛题：CUMCM2026Problems/`，用户已授权开展 C 题研究、本地计算和第一版论文交付，当前为 `COMPETITION / DRAFT_COMPUTE`。C 题原始输入已归档，54 项需求已建立；最新结果以 `paper/results/CURRENT.json` 为入口。报名组别、生效赛区、H1--H5 和人工终审仍按真实反馈登记。

## 开始与续接

先读 `README.md`、`config/competition.json`、`paper/STATUS.md`、`paper/CONTEXT.md`、`paper/IDEA.md`、`paper/REQ.md`。然后只加载当前阶段提示词、相关题型卡片和已有代码。上下文压缩后读 `paper/HANDOFF.md` 并核对实际文件。

在用户授权范围内直接执行可逆工作，完成计算、核验和文件落地。能从题面、文件和工具查到的事实自己查。普通实现选择自行决定并记录；遇到影响目标函数、核心假设或正式结论的未决问题，给出有依据的建议，并继续不依赖该答案的工作。用户的新指令优先于本项目工作法和技能中的建议。

## 事实与文件

- 用户要求：每一次大编辑都必须完整留档到根目录 `Each Stage Review Work/`，规则与索引见该目录 `README.md`。大编辑包括题面理解、模型假设、求解/验证代码、关键参数、结果、图表、论文、配置和协作规则的实质修改。
- 每次大编辑先新建 `YYYYMMDD-NN-主题/` 并保存修改前完整文件，完成后保存修改后完整文件、差异、改动说明、验证命令与实际结果、来源路径和 SHA-256、待人工审阅项。不能只放摘要、路径或聊天记录。新增/删除文件须明确登记；同一阶段的相关小修可合并。
- 已交付的审阅快照不得覆盖；后续修订另开序号，并关联前一包。原始题面和原始数据只记来源与哈希，不重复复制进审阅包。首次补录的历史基线必须注明重建来源和局限，不冒充事前快照或 Git 历史。
- 人工审阅初始状态为 `PENDING`，只有真实用户反馈才可更新，记录审阅人、时间和意见。AI/程序核验不代填人工通过；每次大编辑结束时将审阅包路径同步到 `paper/STATUS.md` 和 `paper/HANDOFF.md`。

- `paper/data/` 存原始数据，`paper/inputs/` 存题面，均只读使用；接收时记录 SHA-256。清洗输出写 `paper/clean/`。
- `paper/CONTEXT.md` 是事实与口径入口；参数表、运行清单和结果 CSV 是对应数值的权威依据。预估值、演练值、正式计算值明确区分。
- `paper/REQ.md` 保留题面逐字原句和稳定 ID；`paper/requirements.csv` 是逐项状态和路径的结构化记录，更新时同步展示表。
- `paper/IDEA.md` 记录建模理由、各问依赖、最多三项经验证的增量，以及触发兜底的条件。冻结结论若被新证据推翻，记录冲突、旧证据和新证据，再提议修订；不得默改。
- 所有演练仅在 `practice/`，不得写进正式结果目录或冒充获奖论文结论。
- 代码输出 CSV、运行元数据和验证记录；求解与绘图分离。数值结论通过 `paper/evidence/claims.csv` 关联代码、结果、图表和论文位置。

## 建模与验证

先做数量级预估及数据体检。比较数学结构，再比较算法；保留可解释基线和退出条件。按每一问选择 `references/problem_types/` 中相关卡片。

对关键结果执行量纲量级、边界退化、小规模对拍、独立互验、守恒与题面对账、现实合理性检查。记录适用范围，不适用项要写理由，不能填假 PASS。随机算法使用预先登记的种子列表，报告重复结果的波动；固定单个种子不等于稳健性。预测按时间划分，预处理仅拟合训练数据。启发式不能无依据宣称全局最优。

先定义验收条件，再运行。检查通过后进入下一阶段；只有代码、数据、环境改变或新证据出现时重跑相关检查。每条研究路线有时间盒与降级方案。

## 写作与交付

先定章节和图表的论证任务，写作与求解可并行。论文主源为 `paper/latex/main.tex` 及 `sections/`；`paper/draft.md` 只作论证提纲，避免双份正文漂移。正常写作不改导言区；确有编译修复需要时做最小修改并立即编译。

结论先有证据再措辞。参考文献核对原始来源和所支撑的具体句子。不得把模型评审分数当真实获奖概率，不得编造引用或核验结果。写作规则只管表达，不替代推导和证据。

2026 年 CUMCM 的 AI 使用要求见 `references/official/`。记录实际工具、型号、用途、典型提示、采纳修改与人工核验情况。AI 检查不能填成人工检查；正式核心建模和分析由参赛队主导。不要在正式评审期间向队外人员发送赛题讨论或请求指导。

湖南、江苏、河北的赛区资料分别在 `references/regions/hunan/`、`references/regions/jiangsu/`、`references/regions/hebei/`。实际任务选择一个生效赛区，再叠加全国规则；学校通知不当作全省规则。用户要求跳过需要密码或登录的网站，不索取或尝试密码，公开缺项如实记录。

打包必须明确区分演练包与正式提交包。账号操作、签名、人工审查和实际上传不能由准备脚本虚报完成。提交文件按当年官方规则和赛区通知生成。

## 模型与进度

目标模型 `gpt-6-astra`，一般阶段用 `max`，关键设计和审查建议 `ultra`。推理档位由客户端或 CLI 参数选择，提示词不能切换档位；核验实际设置，不因写了 Ultra 就声称已使用 Ultra。不要求展示隐式思维链，交付可核对的公式推导、决策依据、试验记录与结论即可。

每次完成阶段后更新 `paper/STATUS.md` 和 `paper/HANDOFF.md`，写清输出、未决事项、下一条命令及运行中的进程标识。不要把“准备就绪”写成“比赛任务已完成”。
