## 5 提示词和模型设置怎样配合

以下命令均在工作台根目录执行：

```sh
cd "/path/to/数学建模"  # 将路径替换为本机实际项目根目录
.venv/bin/python tools/start_astra.py --stage 5 --effort ultra --dry-run
```

## 6 收到赛题后如何放文件

先保留下载的原始题面和附件。让阶段 01 接收，或对每个文件运行：

```sh
.venv/bin/python tools/ingest.py '/实际下载路径/题目.pdf' --kind inputs --origin '实际官方发布地址或来源说明'
.venv/bin/python tools/ingest.py '/实际下载路径/附件.xlsx' --kind data --origin '实际官方发布地址或来源说明'
```

上面的路径与来源要换成真实值。接收工具拒绝覆盖同名文件和符号链接，核对 SHA-256，并把工作副本设为只读。后续所有清洗、字段重命名和衍生数据写到 `paper/clean/`，不改 `paper/data/`。

| 目录或文件 | 该放什么 |
| --- | --- |
| `paper/inputs/` | 正式题面、题面补充说明 |
| `paper/data/` | 收到的原始附件，只读 |
| `paper/clean/` | 清洗数据、体检报告与处理说明 |
| `paper/code/` | 求解、验证、绘图源代码和运行帮助 |
| `paper/results/<run_id>/` | 某次运行的 CSV、验证文件及清单 |
| `paper/figures/` | 正式图表及可编辑图源 |
| `paper/latex/` | 唯一论文正文主源 |
| `paper/evidence/` | 需求、结论、参数、图表、人工检查及 AI 记录 |
| `paper/submission/` | 检查通过后生成的交付文件 |

输入 PDF、扫描图片或其他非表格附件不应混入表格体检目录。`tools/data_audit.py` 支持 CSV、TSV、Excel 各工作表和可解析的 JSON 表；其他格式须按题面增加对应读取器。

先运行不改数据的事实检查：

```sh
.venv/bin/python tools/data_audit.py paper/data --output paper/clean/data-audit.json
```

再根据题面建立 `paper/schema.json`，定义真实列名、单位、主键、范围、时间频率及关联关系后复查：

```sh
.venv/bin/python tools/data_audit.py paper/data --schema paper/schema.json --output paper/clean/data-audit-domain.json
```

表标识为 `附件.xlsx::工作表名`，CSV 则为实际文件名。结构示例可从 `tests/test_data_tools.py` 查看，但字段和范围必须按本题改写。`read_complete` 只表示读取完成，领域检查要看 `domain_checks_pass`；缺少 schema 时不能宣称题面约束已经通过。出现 error 时命令退出码为 2，源数据保持原样。

## 7 五类状态文件各自记录什么

`paper/CONTEXT.md` 记录题面事实、术语口径、单位、假设、符号、数量级预估和已定结论。数值依据仍是参数表、结果 CSV 和运行清单；这里保存对它们的解释与入口。

`paper/REQ.md` 保留题面逐字原句及每个要求的交付位置，结构化版本是 `paper/requirements.csv`。二者同步更新。题目有几问就建几问，复合要求按可检查的输出拆分。

`paper/IDEA.md` 解释为什么选择这一模型、各问如何依赖、保留什么增量、何时切换基线。队内方案调整需要写明依据及影响，不能默改已定结论。

`paper/STATUS.md` 说明当前完成到哪一步。`paper/HANDOFF.md` 给下一次任务留下实际文件、已通过的检查、未决项、运行进程和下一步动作。聊天中的“完成了”不能替代这些文件与真实结果。

`paper/draft.md` 用来放论证提纲。日常正文直接写在 LaTeX，避免 Markdown 与 LaTeX 各有一份不同的完整正文。

## 8 从计算结果写到论文

先给每个主结果定义验证方法和容差，再运行模型。每次运行使用新的 `run_id`，保存参数、种子、输入、代码和输出哈希。已有结果只有在代码、数据、环境及所需检查未变化时才复用。

求解程序输出 CSV，绘图程序读取 CSV。不要在绘图代码中额外加一个预测项、删除不理想的种子，或把标准差带标成置信区间。需要随机重复时，种子列表事先确定，全部结果保留。

主数值逐条进入 `paper/evidence/claims.csv`，连接结果文件、零起始的数据行号、列名、代码、运行、验证文件与论文标签。具体字段和 `write_manifest` 的路径基准见 [证据记录说明](paper/evidence/README.md)。这一环节很关键：工作台相对路径和 `paper/` 相对路径不能混用。

写作时先说明模型解决的实际困难，再给变量、目标、约束和求解依据。结果段给答案、解释及适用条件；假设和结论都须有来源或检验。自然语言学习用于改善表达，不代替科学证据。

遇到错误按阶段 19 定位。检查不能通过时保留失败证据，给一次有明确时限的修复尝试，必要时切换已经验证的基线。完整时间表与退出条件见 [74 小时安排](prep/schedule.md)。

## 9 LaTeX 模板具体怎么用

先审阅 [6 页演示版](output/latex/template-demo-v3.pdf)，需要填写结构时看 [5 页骨架预览](output/latex/template-main-v3.pdf)。独立源码与这两份预览已放入 [LaTeX 源码包](output/latex/mathmodel-maomao-v3.zip)。v1 和 v2 文件仍保留作历史对照。

| 排版项目 | 当前设置 |
| --- | --- |
| 正文 | 宋体 12 PDF 点，基本行距 15.6 点，段首缩进两字 |
| 摘要 | 正文行距约 17.15 点，题目与关键词同在第一页 |
| 论文题名 | 宋体加粗 16 点，居中 |
| 一级标题 | 黑体 14 点，居中 |
| 二级标题 | 楷体 14 点，左对齐 |
| 三级标题 | 宋体加粗 12 点，左对齐 |
| 图题与表题 | 楷体 12 点，图下表上，三线表 |
| 英文和数字 | Times New Roman |
| 数学公式 | Latin Modern Math（标准 LaTeX 数学字体） |
| 页面 | A4，四边 25 mm，页脚居中连续页码 |

主要字形和字号取自你指定的范文。标题间距略作统一，摘要页码从 1 开始、正文接续为 2，以符合已核对的 2026 全国格式规范。细节见 `templates/latex/STYLE_REVIEW.md`。

正式写作编辑 `paper/latex/sections/`。摘要是 `00_abstract.tex`，建模与求解是 `04_models.tex`，检验是 `05_validation.tex`，参考文献是 `08_references.tex`。按实际问题数增删小节，并填写 `main.tex` 中题名等内容。

编译正式骨架或演示稿：

```sh
.venv/bin/python tools/build_paper.py
.venv/bin/python tools/build_paper.py templates/latex/demo.tex
```

前者输出 `paper/latex/build/main.pdf`，后者输出 `templates/latex/build/demo.pdf`。编译器为 XeLaTeX。同目录的 `.compile.txt` 与 `.check.json` 分别记录日志和程序检查；每次有版面变化仍要打开 PDF 检查。

统一字号和间距在 `mathmodel.sty`，字体来源在 `fonts.tex`。本机读取已安装字体，源码包不附带专有字体。强制使用开源替代字体时把 `\usepackage{mathmodel}` 改成 `\usepackage[portablefonts]{mathmodel}`。替代模式已在本机编译和视觉检查；字形会有差异，Overleaf 未登录实测。

修改样式后应同步模板样式文件和实际论文导言文件，再编译检查，不能用模板骨架覆盖已经写好的正文。`tools/install_template.py` 只在尚未有正文时部署骨架，当前项目已经部署，重复执行会拒绝覆盖。

演示稿中的小算例只是显示公式、图表与代码的样式。正式稿保留的灰色 `\placeholder{...}` 要用实际内容替换；交付检查会拦截残留待填写项。

## 10 Word 备用模板什么时候使用

[Word 骨架](templates/word/model-template.docx)采用同一组主要字体和标题层次，有原生多级编号、自动页码、可编辑公式与三线表。已渲染检查全部 5 页，但尚未通过原生 Microsoft Word 导出进行验证。

平时继续使用 LaTeX。若出现排版故障，先按日志定位并限制修复时间；确需改用 Word 时，把最新已核验正文迁入备用骨架，更新 `STATUS.md` 与 `HANDOFF.md` 的正文主源，然后检查公式、数字、图表和引用。这个模板不提供两种格式的自动双向同步。

Word 输出前更新全部域并导出 PDF，再逐页检查。参考字体缺失会发生替换；换电脑后应提前打开确认，不等到截止前才迁移。

## 14 最后怎样得到交付文件

交付前补齐 `paper/submission.json`：实际论文 PDF、正文起止页、适用的文件名和明确的支撑文件列表。代码、依赖、运行说明、必要结果和核验记录都应列入；路径相对于 `paper/`。

准备阶段只查目录与表头：

```sh
.venv/bin/python tools/check_project.py --mode preparation
```

正式题面、结果、证据和队内审查均完成后：

```sh
.venv/bin/python tools/build_paper.py
.venv/bin/python tools/check_project.py --mode submission --report paper/evidence/final-project-check.json
.venv/bin/python tools/package_submission.py --mode submission
```

**目前运行正式检查应当失败**，因为没有正式题面、需求完成记录和科学结果。这是预期拦截，不能通过填假值绕过。检查器目前适用于有代码、主数值结果且使用 AI 的流程；纯理论、无程序或完全未使用 AI 的情形，需要按当年官方规则调整交付审查。

正式检查会核对主数值与 CSV、运行文件哈希、需求位置、代码清单、A4、正文页数、占位文字、AI 声明位置及当前 PDF 的人工审查记录。它不会判断所有模型是否正确，也不能充分检查图片中的身份信息；这些仍要队内复核。

打包程序只生成本地 PDF、支撑 ZIP 和报告，拒绝覆盖已有包，检查后重新核对源文件是否变化。支撑 ZIP 有逐文件 SHA-256 清单，报告保留 `uploaded: false`。当前采用不超过 20,000,000 字节的保守大小限制。

工作台整体迁移或分享使用清洁准备包，不使用根目录历史 `数学建模.zip`：

```sh
.venv/bin/python tools/package_clean_project.py
```

清洁准备包写入 `output/clean/`，排除 `.git`、`.venv`、`backups`、`tmp`、缓存、LaTeX 构建文件、历史嵌套归档和本机日志；可分享文本中的用户路径替换为 `<LOCAL_PATH>`、系统路径替换为 `<SYSTEM_PATH>`。包内 `clean-archive-manifest.json` 记录纳入、排除、哈希、`LOCAL_MACHINE_LOG` 边界和 `formal_submission_ready=false`。它是准备源代码包，不是正式提交包。

电子论文从一页摘要开始，不放身份页或目录；正文不超过 30 页，参考文献前有真实 AI 使用声明。纸质材料、文件名及赛区补充要求以实际当年通知为准。最后在规定客户端提交对应文件的 MD5，再按上传窗口上传同一版本并保留真实回执。科研脚本的 SHA-256 记录不能替代比赛要求的 MD5 操作。
